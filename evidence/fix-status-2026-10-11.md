## 原生故障修复与实际结果

首轮实际故障记录见 [native-faults-20261011-first.json](native-faults-20261011-first.json)。Docker 引擎重启后，已有 `nexent-runtime-sandbox` 容器停止但占用名称；原生 SDK 创建同名沙箱失败，回退至不允许 JSON 导入的本地解释器。代理启动原容器后，第二轮身份与权限项通过，但 Windows 主机 SQLite 锁未阻塞 Linux 容器，连接中断也只输出平台普通错误文字。第二轮真实失败记录见 [native-faults-20261011-second.json](native-faults-20261011-second.json)。

修复原有沙箱恢复、容器内持锁和 SDK 连接错误映射后，第三轮 [native-faults-20261011-third.json](native-faults-20261011-third.json) 5/5 通过：伪造 Metadata 400/010105 且无审计调用；未映射账号 BLOCKED/ROLE_NOT_CONFIGURED；群众调用工作人员工具 BLOCKED/FORBIDDEN；真实存储锁 ERROR/TOOL_TIMEOUT、两次尝试且无子 Agent；MCP 停止 ERROR/CONNECTION_TIMEOUT、一次尝试且无工具/子 Agent。故障结束后容器已恢复，业务三表仍为 0。

SDK 覆盖仅处理本项目 MCP 地址的连接异常组/链，保留现有成功、其他失败和清理逻辑。固定原模块 SHA-256 校验阻止未知源码应用，部署时生成私有覆盖并只读挂载，现有容器经校验、复制与重启后已核对覆盖哈希。具体证据见 [runtime-error-overlay.json](runtime-error-overlay.json)。本次因此存在明确的 SDK 运行时变更；上游源码、SQL 和镜像版本保持固定。不能继续使用“SDK 未修改”描述当前运行环境。

已新增恢复所有权、嵌套异常分类、其他地址/混合异常/认证失败不误判、未知源码拒绝和锁异常释放测试。修复后的 [完整核心回归](native-20261011T115445853107Z/summary.json) 已通过 40/40：4B 20/20、中位 7375.39 ms；8B 20/20、中位 8367.51 ms。按规则继续选择 4B，三个 Agent 均发布至版本 14。汇总记录本轮实际 SDK 覆盖哈希，确认成功链路没有回归。最新 [native-faults.json](native-faults.json) 绑定该核心目录并再次 5/5 通过；三个账号 UI 验收仍需完成。

| 核查问题 | 当前实现 |
|---|---|
| 首轮预热超时及额外工具调用 | 流空闲读取等待从 30 秒调整为 120 秒；关闭计划和自动任务入口；用户启动的脚本关闭四个测试账号的记忆功能，发布时同步真实返回值动作示例。增加额外工具拒绝规则；后续原生对照已通过。 |

| 会话请求发往配置服务 | 配置与运行客户端分开；会话创建使用 runtime 5014。 |
| 空 Metadata 被平台拒绝 | 普通请求省略该字段；伪造 Metadata 改为独立拒绝测试。 |
| 原生顶层 reasoning_effort 不兼容 | 关闭平台思考，通过三个 Agent 的提供方自定义参数传递 none；已核对固定上游参数处理，后续原生轨迹已验证没有深度思考。 |
| 子 Agent 与最终结果判定不完整 | 核对真实 Agent ID、中文显示名、调用 ID、深度和时序；最终字段及工作人员缺失项必须对应工具审计。 |
| 新会话、预热及参数没有成为选型门槛 | 要求独立会话、预热成功、模型参数正确且实际仅加载当前模型；异常保存失败及部分证据。 |
| SQLite 锁超时未重试 | 将真实 SQLITE_BUSY/LOCKED 转换为技术超时，验证最多两次尝试。 |
| 进度状态写死 | 根据实时环境探测、原生结果、UI 和故障证据生成状态；不接受缺失、旧轮次或变更后的 UI 文件。 |
| 故障及 UI 验收没有闭环入口 | 增加原生负向测试及用户确认 UI 证据脚本，绑定同轮核心结果；未执行不会标为通过。 |
| 首次安装没有自动设置权限 | 启动入口初始化私有目录；Windows DACL 只允许当前用户和 SYSTEM，新文件继承。 |
| Compose 变量默认值被端口改写破坏 | 修复端口解析并恢复已识别的旧错误改写，保持 loopback 绑定。 |
| 账号操作没有用户接手边界 | 从固定官方脚本生成服务部署副本，跳过其自动注册超级管理员；账号初始化和 UI 登录由用户启动。 |
| 旧 MinIO 镜像不可拉取 | 从固定官方服务端与客户端源码构建本地镜像，验证版本和提交，记录实际镜像 ID 后显式配置。 |
| PowerShell 将原生 stderr 进度判成失败 | 使用当前镜像源参数并根据真实退出码判断部署成败。 |
| 新版 FastAPI 自动遥测导致应用启动失败 | Nexent 关闭遥测时，同步关闭 traces/metrics/logs 自动导出器，保留 SDK 使用的原协议设置。 |
| 前端语言重定向被误判为服务未就绪 | 就绪探测跟随语言重定向，实际前端返回 200。 |
