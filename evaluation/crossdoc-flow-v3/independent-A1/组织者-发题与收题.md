# 组织者：发题与收题（A1 → A2 → A3）

读者：陈（组织者）和协助的本机 Agent。对应[最后阶段任务](../../../docs/competition/最后阶段任务-独立评测-截图-漏核心分析.md)的 A1—A3。出题人只读 [给出题人的说明](给出题人的说明.md)，**不读本文**。

## 一、找出题人

- 没接触过本项目的代码、文档、诊断和以前的题目；不是李、程、陈，也不是 Claude 或本机 Agent。
- 能读懂政策文件；不需要会编程，可以用表格填写。
- 预计用时 5—6 小时。提前问清能否在约定时间内交回，并约好交回方式（私下传）。
- 最晚 **11 月 22 日**找到；找不到就放弃 A，材料保持“开发对比”的写法。

## 二、准备发题包

在仓库**外**新建一个空文件夹，只放四样东西：

| 放什么 | 从哪来 |
| --- | --- |
| 七份资料原文（含扫描件两页图片和转录） | 双线分支已备的 `independent-authoring-packet`（ZIP 散列 `2783da39b808dbc661c3d5ca236996767e066b90f8b7a9cd0080ec42b507a210`，回执写明不含代码和诊断）。先核对散列，再**取出其中的资料原文**；包里若带旧的出题说明，换成下面这份 |
| `资料清单.txt` | 自己写：资料1—资料7 的编号、文件名、SHA-256。**记下 Excel 收费目录是第几号**，收题检查时要用 |
| `给出题人的说明.md` | 本目录 |
| `出题表模板.csv` | 本目录 |

不要放：本仓库的任何其他文件、旧题、参考答案、程序输出、评分表、`key.json`、本文。

发出前算一次整包散列，记在私有记录里。

## 三、收题（收到当场做）

1. **立刻算散列。** 三个文件（或表格 + `freeze.json`）各算 SHA-256，连同收到时间记入私有记录。之后原文件不改；出题人的更正另存。
2. **表格方式先转换**（转出的文件给出题人确认一遍）：

   ```powershell
   .\.venv\Scripts\python.exe scripts/check_authored_round.py from-table --table <收到的表>.csv `
     --questions <收题目录>\questions.json --reference <收题目录>\reference.json
   ```

   转换后两个 JSON 文件的散列另记，题目冻结以**确认后的 JSON** 为准。
3. **机械检查**（只输出计数和题号，不输出题面，可以给任何人看）：

   ```powershell
   .\.venv\Scripts\python.exe scripts/check_authored_round.py check `
     --questions <收题目录>\questions.json --reference <收题目录>\reference.json --freeze <收题目录>\freeze.json `
     --corpus .runtime/frozen-qa-v3-titles-20261115/corpus.json --excel-material <Excel 的编号> `
     --prior <旧 30 题 questions.json> <24 道开发题 questions.json> <其他开发、演示题文件> `
     --output .runtime/crossdoc-flow-v3/A1-intake-<日期>.json
   ```

   - `errors` 不为空：**原样退回出题人本人修改**，不替他改；修改后的版本重新算散列、重新检查，旧版本保留。
   - `warnings` 逐条看：`QUOTE_NOT_FOUND_IN_CORPUS` 多半是扫描件转录或空白差异，交 A2 人工核对；`TOPIC_OVERLAP_ABOVE_0_5` 交 A2 判断是否重合；`MATERIALS_IN_FEWER_THAN_TWO_QUESTIONS` 记下即可，不强制退回。
4. 出题人的 `freeze.json` 若写了用过 AI 工具，材料里要照实写“出题时使用了 AI 辅助，参考由出题人本人核对”。

## 四、A2 人工复核

复核人：不出题、不评分的人，陈可以做。逐题写“未发现”或“有误＋原因”两件事：

- 题意是否和旧 30 题、24 道开发题重合（参考第三步的重合筛查）；
- 参考要点是否与原文一致，应停止题的 `stop_basis` 是否成立。

复核结果另存，**不改参考文件**。若某题参考有误，在统计时按“参考有误”单列，不删题、不重写。

## 五、A3 冻结与预检

把题目、参考、语料的散列写进本轮声明（照 `evaluation/crossdoc-flow-v3/round-template.json`），`arms` 写四组：`baseline`、`single_shot`、`flow_v3`、`keyword_bot`；`commit` 写最终冻结点（现为 `459e459`）。六项独立性条件由陈逐项确认：

| 条件 | 本轮如何满足 |
| --- | --- |
| `questions_written_without_access_to_flow_code_or_diagnostics` | 出题人的 `freeze.json` 声明 + 发题包只有四样东西 |
| `questions_written_outside_the_session_that_runs_the_evaluation` | 出题人是另一个人，在自己的电脑上完成 |
| `topic_overlap_reviewed_by_a_person` | A2 完成 |
| `reference_checked_against_sources_by_a_person` | A2 完成 |
| `two_reviewers_who_did_not_write_the_questions` | 李、程 |
| `organizer_does_not_rate` | 陈不评分 |

然后运行 `scripts/flow_v3_preflight.py`（带 `--questions`、`--reference`、`--corpus`）。六项都为真才是 `formal`；有一项不满足就是“开发对比”并列出折扣；`BLOCKED` 时停下。之后进入 A4。

## 六、不能做的事

- 不把题目、参考、出题表、`freeze.json` 放进 Git 或任何公开位置；公开的只有第三步输出的计数文件和散列。
- 不在出题人交回前向其透露系统设计、旧题或旧结果。
- 收题后不改题、不删题、不挑题；运行前不看程序对新题的任何输出。
