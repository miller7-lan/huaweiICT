# Agent 流程核查与优化（2026-10-17）

本轮已修改代码并验证。当前跑通的是**模拟资料的工程闭环**：咨询、分支选择、检索核验、发现变化、暂停冲突、人工复核、分项发布、回退和历史追溯。真实模型推理继续关闭，API 凭据引用全部为空。

## 修掉了什么

| 原来的问题 | 现在的处理与验证 |
| --- | --- |
| 大请求全部读进内存后才检查长度；MCP 没有同样的正文预算 | 接收过程中累计实际字节，超限返回 413，停止读后续正文。浏览器正文上限 64 KiB，MCP 上限 1 MiB；分块请求和伪造小长度均经过检查 |
| 匿名登录能挤占专业人员的登录名额 | 群众/专业会话分别限额 1024/64，复用同角色会话，清理过期会话，群众满额时回收最旧群众会话。1030 次匿名登录后专业入口仍可用；错误口令不能提升权限 |
| 双击或网络重试可能重复创建咨询 | 查询期间锁定按钮，同一会话请求编号绑定输入、串行处理。相同编号复用任务，但重新检查当前暂停状态；换输入重用编号会拒绝 |
| 检索异常后任务一直显示“检索中” | 保存 failed 状态、结束时间和错误类型，历史接口提示重新发起；敏感异常正文不保存。模拟超时检查通过 |
| 连续发布把过期原文和复核记录堆进当前快照，最终碰到数量上限 | 清理当前图中已无引用的原文、证据和旧复核，历史快照和资料版本保留。连续 19 次发布并反复切换正文，当前图保持有界，旧版本与旧原文不变 |
| 同义词建议反复出现时重复插入相同编号 | 同编号替换当前记录，重新绑定本次复核；连续更新无重复编号，完整图校验通过 |
| 回退后本体登记仍显示新版 | 本体登记随本体版本保存，状态页跟随当前知识版本；发布、回退、重启、再切换检查通过 |
| 状态页读取全部历史再截取，记录越多越慢 | SQLite 内限制读取、投影版本元数据，增加状态索引和翻页，显示总数。55 条咨询分页无重叠、无遗漏 |
| 已被替代的包仍可能报逾期 | 已替代包退出逾期判断；当前未解决冲突仍暂停 |

请求缓冲和匿名会话两个问题，在本机、合成数据、仅 loopback 的部署前提下评为低风险可用性问题。独立安全核查覆盖 `src/gov_mcp/decision` 的 9 个文件，并未覆盖全部 vendor 与其他模块。扫描编号为 `49126d8f-5fb8-479e-95d2-96868a548069`，其报告记录**修复前快照**；本文件和新增回归检查记录修复结果。

## 算法和执行效率

1. **复用已验证的版本结构。** 最多缓存 8 个内部版本模板，避免同一版本反复校验和建索引。每次咨询有独立任务和可用性门控，仍从数据库重新读取当前暂停状态；返回值复制后交给调用者，防止污染缓存。
2. **同一条件只算一次。** 条件缓存限定在一次准备过程，换用户事实后重新计算，不跨咨询沿用判断。
3. **原文检索增加倒排表。** 从验证过的原文生成向量和词项索引，只对有共同词项的片段算余弦分数，最多缓存 2 个资料版本。同分按片段编号稳定排序，不信任落盘向量提示。
4. **继续核查底层资料。** 热缓存也验证原文指纹和定位。这部分仍读取资料集合，因此没有声称端到端检索已是亚线性复杂度。
5. **筛选当前任务再读取。** 查询仅读取待复核或部分发布的包，心跳读取待处理包，避免反序列化全部历史包。

检索仍是本地稀疏余弦相似度，没有替换成语义向量。本轮检查了固定样例与穷举算法的片段编号、分数完全一致，优化的是执行效率，没有声称中文准确率提高。补查仍最多三轮，缺少用户条件不会引起无意义的重复检索。

## 实测结果

本机 Python 3.12.14、同一微型虚构资料库、临时运行目录；查询 20 次，分支选择 40 次，检索 100 次，每项先预热一次。计时包含程序调用及相应 SQLite 操作，没有模型推理。

| 操作 | 优化前中位耗时 | 优化后中位耗时 | 本次降幅 |
| --- | ---: | ---: | ---: |
| 完整咨询 | 23.163 ms | 16.446 ms | 约 29% |
| 分支选择 | 4.466 ms | 0.749 ms | 约 83% |
| 资料检索 | 0.414 ms | 0.354 ms | 约 14% |

- **352 项完整回归通过**，新增 17 项优化回归；3 项上游弃用或类型注解警告，无失败。
- **21/21 项模拟闭环检查通过**，覆盖未知条件、三轮上限、分项发布、冲突暂停、历史和回退。
- **16/16 项实际平台接线检查通过**：6 个禁用 Agent 草稿、12 个 MCP 工具、控制 Agent 的子 Agent 与 Skill；从 Nexent 容器实际访问 `host.docker.internal:8780/mcp/` 成功。
- 浏览器验证查询按钮锁定与恢复、冲突项暂停、专业人员分页计数和连接检查。**推理请求 0，Jev 网络请求 0，草稿模型绑定为空，原生已发布版本 0。**

## 还缺什么，下一步顺序

最大的缺口是把模拟闭环换成真实资料处理。

| 顺序 | 缺口与下一步 | 完成标准 |
| --- | --- | --- |
| 1 | 新工作台心跳读取固定模拟资料；先接一个地区、一个事项的已登记公开来源和实际解析结果 | 真实区分正文变化、噪声、失败和不支持格式，来源、时间和定位可追溯；失败不能报成无变化 |
| 2 | 整理、核验、Jev 分类使用确定性回放，候选提交仅接受存储好的回放候选 | 完成模型输出到严格候选结构的转换，校验分支、环节、动作、出处与影响范围，异常不能进入发布链路 |
| 3 | 本体扩展只登记为已确认说明，新增关系不可执行 | 给支持的新关系补结构、依赖、求值与标准对齐验证；其余扩展保持不可执行 |
| 4 | 缺真实业务独立验收 | 专业人员确认案例，测错误确定项、漏项、引文支持、冲突暂停和历史追溯；模拟通过不能替代 |
| 5 | 大库和长期运行未测；原文、审计持续保留，失败咨询仅重新发起 | 补增量索引、容量与保留策略、跨进程恢复和压力测试；浏览器请求去重目前限当前会话，重启需重新登录 |
| 最后 | 启用真实 API 和 Nexent 推理 | 替换离线执行器，绑定模型、凭据，核查真实子 Agent/工具轨迹、超时重试和预算，再跑验收 |

**仅把 `inference_enabled` 改为 true，不会让当前工作台自动使用模型。** `WiredRoles` 目前只准备路由并执行离线函数；真实传输与离线流程是两层。最后接 API 时必须完成真实执行适配和输出验证，不能只填密钥就宣称联调成功。本轮按要求保持开关关闭。
