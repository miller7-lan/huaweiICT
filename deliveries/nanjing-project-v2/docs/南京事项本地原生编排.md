# 南京事项本地原生编排

2026-10-19，用户明确选择“本轮先用本地 Qwen 验证编排”。本活动使用南京真实来源的候选版本及固定虚构办理条件，不涉及居民姓名、证件号或实际政务提交。此前用户选择保留规则候选状态，正式业务发布继续关闭。

## 真实接入与职责

本机 Nexent 仅实际登记 Qwen3 8B/4B，本轮没有可用的 DeepSeek/Jev 配置。新建三个独立、禁用且未发布的草稿：`govmatter_controller` 使用8B，`govmatter_retriever` 和 `govmatter_verifier` 使用4B。只有主控绑定项目 Skill；两个子 Agent 只绑定各自的一个叶子工具。登记前后核对原有 Agent 的模型、工具、Skill、子 Agent 和提示词签名，未修改原有绑定。

五个带专用令牌的本机 MCP 工具位于8785端口：

| 工具 | 实际作用 |
| --- | --- |
| `govmatter_open` | 仅接受固定工程场景，固定当前南京候选版本；每次运行至多一个任务 |
| `govmatter_retrieve` | 从不可变原件包取得关系候选对应的完整段落和日期、定位 |
| `govmatter_verify` | 验证检索内容完整性、原文引用覆盖及带类型的跨文档推导 |
| `govmatter_state` | 从持久存储读取真实阶段，主控不能凭子 Agent 的文字假设成功 |
| `govmatter_finalize` | 再检查当前来源控制和原固定版本，返回与已核验记录一致的候选结果 |

模型只负责工具编排；候选提取仍是已注明的种子模板匹配，关系推导由程序执行。本阶段不据此宣称模型自主学习本体或政策准确率提升。核验没有调用 Jev，也不产生或补造支持分数。

阶段及预算保存在独立私有 SQLite 中，复用事项后端的不可变版本。每阶段都叠加当前来源暂停/新鲜度控制，已完成的历史任务也不能绕过。MCP不提供开启活动、发布、回退、改来源或选择身份的工具。一次活动最多两次原生运行，成功即关闭；第二次必须提供具体修复说明，外部失败关闭活动。平台一次运行内可能有模型重试，需单独查看实际attempt事件，不能将原生请求数当作底层模型调用数。
