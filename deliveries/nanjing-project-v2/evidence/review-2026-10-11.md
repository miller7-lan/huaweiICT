## 应优先修正的三个阻断问题

### 1. P1：创建会话请求发到了错误的服务

位置：[benchmark_native.py:57](https://github.com/miller7-lan/huaweiICT/blob/8ac6418e701dc3b4b3136e8abbb115699bd8bd0e/scripts/benchmark_native.py#L57)、[nexent_api.py:19](https://github.com/miller7-lan/huaweiICT/blob/8ac6418e701dc3b4b3136e8abbb115699bd8bd0e/scripts/nexent_api.py#L19)。

run_case 用 api.call 创建会话，但该方法始终发送至 base=5010。固定上游版本仅在 runtime_app 挂载 conversation_management_router（5014），config_app 没有该路由。第一次预热会在创建会话时失败，尚未进入 Agent 运行及结果保存阶段。

复现：使用 httpx.MockTransport 捕获真实客户端构造的 URL，得到 http://127.0.0.1:5010/conversation/create；同时核对了上游 config_app.py/runtime_app.py 路由挂载。

补齐条件：明确区分配置与运行请求，创建会话经 runtime_base 发送；增加针对服务归属的客户端验证。

### 2. P1：空 Metadata 也会触发平台拒绝

位置：[benchmark_native.py:63](https://github.com/miller7-lan/huaweiICT/blob/8ac6418e701dc3b4b3136e8abbb115699bd8bd0e/scripts/benchmark_native.py#L63)、[nexent_api.py:52](https://github.com/miller7-lan/huaweiICT/blob/8ac6418e701dc3b4b3136e8abbb115699bd8bd0e/scripts/nexent_api.py#L52)。

所有普通用例都发送 metadata={}；导入包和 activate_model 则设置 allow_chat_metadata=false。上游 run.py:1659–1684 以“字段显式存在且值非 None”判断 Metadata 更新，因此空对象也会触发 CHAT_METADATA_NOT_ALLOWED。伪造 Metadata 用例同样会被拒绝，无法按目前的群众 EMPTY 标准通过。

复现：隔离执行固定上游的原生入口校验分支，空对象和伪造角色对象均得到 CHAT_METADATA_NOT_ALLOWED。此为源码分支复现，不是已部署平台实测。

补齐条件：普通用例省略 Metadata 字段；将身份自称的路由用例与“禁止 Metadata 时拒绝请求”的负向用例分开定义。若需验证允许 Metadata 时身份仍不可覆盖，须另用明确配置的测试入口，并保留真实可信身份审计。

### 3. P1：原生运行接口不接受当前配置下的 reasoning_effort=none

位置：[benchmark_native.py:62](https://github.com/miller7-lan/huaweiICT/blob/8ac6418e701dc3b4b3136e8abbb115699bd8bd0e/scripts/benchmark_native.py#L62)。

Ollama 直连接受 none，不能据此推断 Nexent 原生入口也接受。固定上游 create_agent_info.py:2815–2833 要求显式 effort 对应启用思考的所选模型，且属于支持级别。当前配置没有启用该开关；请求还传入 generation_config，默认 deep_thinking=false。请求会在创建运行信息时被拒绝，未到达模型。

复现：隔离执行上游校验分支，enable_thinking=false 时 none 被拒绝；对未知能力的通用级别，即使开关为 true，none 也不属于 low/medium/high，仍被拒绝。

补齐条件：按固定上游的思考开关与提供方适配契约配置关闭思考；核对最终送到 Ollama 的请求及三个 Agent 的真实输出。修正 README 中“所有推理请求明确传 none”的原生调用表述。
