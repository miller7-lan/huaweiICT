# 南京事项持久版本与交接后端

2026-10-19。本阶段复用既有 `gov_mcp.knowledge.store.Store` 的不可变对象、版本指纹、事务/CAS发布、回退和审计，实现南京真实来源的独立事项生命周期。没有另造一套替代旧业务主库的批准记录，也没有打开或改写原/M1/M2业务库。

## 已实现并实际执行

- 规则包先校验原件、原文片段、引用偏移和包清单，再保存在内容寻址对象中；候选和版本均保留精确包指纹、本体版本及真实来源范围。
- 种子v1与关系演化v2分别发布为 **工程预览**。v2实际产生跨文档推导，旧会话继续固定v1。该发布不等于真实业务规则获批。
- 重复导入相同语义内容不生成新候选，重复发布不生成新版本；已过期旧原件不能靠重复载入刷新检查时间。
- 发现来源语义/日期/范围变更后，当前控制与旧版本不匹配即停止旧答；显式暂停、撤权及24小时新鲜度叠加所有历史版本。回退不能解除这些当前控制。
- 群众会话归属校验，工作人员取得明确交接码后才能接收；码只存哈希、一次接收，绑定具体工作人员。维护者不因此获得群众会话读取权。
- 交接接收前及工作人员确认前均重查来源状态；源暂停时不消耗交接码。修改数据库/原件也不能绕过不可变版本指纹。
- 正式业务发布入口当前明确拒绝：仍缺真实业务复核及独立评测。工作人员的程序化交接确认另标记为工程确认，不能升级成正式审批。

## 证据

[实际独立运行回执](../evidence/real-matter-closure/stage-03-persisted-lifecycle.json)记录2个候选、2个不可变版本、2个虚构会话及13条审计记录。10项实际程序检查全部通过，覆盖v1/v2差异、旧任务、交接、当前/历史暂停、回退、重启及无业务批准。

此运行使用真实公开原文，但群众、工作人员与维护者均是程序控制的工程身份。暂停为明确标注的故障注入，不声称官网实际撤权；没有HTTP浏览器或Nexent模型调用。没有重新启动Windows心跳。

[43项定向检查](../evidence/real-matter-closure/stage-03-lifecycle-tests.xml)为新生命周期15项加既有图推导28项，全部通过。测试中的变更元数据和复核角色都是标注的夹具，不是新的政策变化或人工批准。没有重复全仓回归。

## 复现

```powershell
# 默认只读已有回执，不会增加会话、重放发布或重置活动
.\.venv\Scripts\python.exe scripts/verify_matter_lifecycle.py

# 首次新环境才执行；存在本轮目录时拒绝重复
.\.venv\Scripts\python.exe scripts/verify_matter_lifecycle.py --run
```

运行目录为 `.runtime/real-matter-closure/lifecycle-stage03`，保留两个版本和历史。源码位于 `matter_lifecycle.py`；身份参数只允许可信宿主注入，后续公开HTTP/MCP工具不能让客户端自行选择角色或声称自己是人工复核人。
