# 一问一答咨询填表入口（2026-10-18）

后续 [Token 节省优化](Token节省优化与验证-2026-10-18.md)将模型输入改为每字段仅发送当前选中值的标准映射，并增加同草稿、同版本、同规范值的精确候选缓存。复用仍需明确同意及重新人工确认；本轮全量 579 项通过，旧文末 562 项是入口首次验收记录。

## 范围与入口

按用户确认，先实现现有模拟事项的**咨询信息表**，不是正式政务申请表。不采集姓名、身份证号、手机号、生日、地址、照片或附件，不连接正式提交接口。

沿用启动命令：

```powershell
scripts/start_agent_workflow.ps1
```

打开 `http://127.0.0.1:8780/guided-form`。原工作台首页也有“新入口”链接，原来的直接选择咨询、专业人员复核、版本与心跳功能保留。

支持办理原因、年龄组、是否本人办理、模拟电子表校验结果四项。问题、预备选项、同义表达及规范值由 `config/decision/intake-form.json` 声明，与当前知识快照字段类型/枚举核对；字段变动不能静默沿用旧表。

## 连贯流程

```text
当前会话登录
  → 创建会话私有草稿，固定字段与知识版本
  → 每次只问一项：预备选项 / 自己填写
     → 本地同义归一、全半角与首尾空白规范
     → 无法可靠匹配：请本人澄清或选择未知，不交给模型猜测
  → 汇总原回答、规范值和选项代码
  → 本人明确同意“仅选项代码外发”
  → DeepSeek 只读格式核查子 Agent
     → 程序校验完整字段、类型、标准显示值及未知项
     → 改写事实、额外指令、工具调用或不合法响应：拒绝
  → 人工逐项检查，可返回修改
     → 修改：旧核查、旧人工确认失效，重新核查
  → 人明确确认，选择已确认适用分支
  → 事务核对知识版本，进入原有咨询流水线
  → 检索 → 规则核验 → 当前冲突暂停门 → 本地回执/带出处清单
```

提问顺序由字段规范驱动，不声称每一句固定问题都来自真实模型。DeepSeek 在末轮统一核查一次，既满足 AI 核查要求，也避免每答一句便重复外发对话。对相同版本重复点击核查复用结果；重复提交同一核查只生成一个本地咨询记录。

## 可自己填写，但不能随意猜测

- 例如“到期了”规范为 `expiry`，“我自己”规范为 `true`，页面同时展示原回答与中文标准值。
- 自填最多 120 个普通字符，本地只接受明确对应的已注册同义表达。不能对应、夹带身份信息、指令或有歧义的文字，不记入草稿，不发给 DeepSeek；请本人澄清。
- “不清楚/未验证”保留 `null`。进入规则引擎时不伪造成 `false`，保留现有追问和未知处理。
- 遗失、代办、关键分支情况未知等没有已确认适用末级分支的情况，不会自动套用成年本人清单。
- 模拟电子表“通过”是工程输入，不是 DeepSeek 检查了真实文件、电子签名或身份。

## 权限边界

| 主体 | 可做 | 不可做 |
|---|---|---|
| 当前会话 | 读取、填写、删除自己的草稿，明确同意核查，人工确认提交本地咨询 | 用草稿 ID 访问别人草稿；伪造最终 facts；跳过核查或确认 |
| 其他会话，包括专业人员 | 使用自己的入口 | 通过新 API 读取/修改其他会话草稿 |
| 格式核查子 Agent | 查看代码、字段选项，输出只读格式核查候选 | 接收原始对话/凭据；更改事实；判断真实资格；调用工具、读取数据库、发布知识或提交表单 |
| 原查询流水线 | 对人确认的规范选项检索、规则核验并检查当前暂停 | 把表单核查当作业务知识发布或正式办理批准 |

复用现有 HttpOnly / SameSite=strict 会话 cookie、同源 POST 校验、实际请求体大小限制、可信主机和无缓存响应。新 API 不接受服务 bearer 作为群众身份，不开放 MCP 填表/提交工具；角色、owner、facts、模型地址或工具权限不能由浏览器额外参数指定。

所有草稿操作按会话锁串行；草稿 ID 与单调 revision 防止旧标签页覆盖，随机 review_id 绑定本轮核查；人工确认必须是精确布尔 `true`。查询开始和写入最终答案时都在事务内核对知识 head，版本改变要求重新核查；已有实时冲突暂停门保持生效。

## 隐私与存储

| 数据 | 去向与保留 |
|---|---|
| 原始自填回答 | 仅本进程当前会话草稿；不写浏览器 localStorage/sessionStorage、不写查询问题、不写模型提示词或应用审计正文 |
| 无法匹配的原回答 | 请求处理后不记入草稿；响应只返回固定错误码，不回显这段文字 |
| DeepSeek 输入 | `synthetic`、固定 schema_id、字段 ID、规范代码、当前选中值的标准显示映射；不含其他未选项、草稿 ID、会话 ID、原回答、用户身份、cookie 或访问口令 |
| 人确认的规范选项 | 提交后进入原有私有查询存储，仅保存现有咨询必要字段；原回答从草稿和核查展示结构清除 |
| 草稿生命周期 | 30 分钟后拒绝读取，并在再次访问时清除；会话退出/淘汰或进程退出后不能通过 API 恢复；删除只清草稿，不删除已确认的历史咨询。不是后台定时物理擦除或进程内存加密保证 |
| 提交回执 | 随本会话可恢复，受现有历史归属校验与当前暂停门保护；不是正式政务受理号 |

“不外发原文”不等于零外发。选项代码也会反映模拟情况，因此核查前仍需要明确同意。本次不支持真实个人信息；以后扩展真实表单必须另行确认字段最小化、授权、保留/删除、真实认证与服务商策略，不是简单修改 `data_class`。

## DeepSeek 路由与启用

- 应用级子 Agent 名称为 `form_format_verifier`，无工具权限；不是声称已经创建/发布 Nexent 原生子 Agent。
- 复用现有 DeepSeek 官方传输与本地凭据绑定，不新增密钥，不把密钥写入配置、页面、模型输入或 Git。
- **独立开关**：`config/decision/connections.json` 的 `form_verifier_enabled`，默认 `false`。原 `inference_enabled` 同样保持 `false`，两个开关互不授权，启用填表核查不会顺带启用原有角色端口。
- 本轮不启用真实推理。由本机维护人员完成官方端点/凭据和授权检查后，才能显式开启新开关并重启本机服务；不能由群众网页、提示词或填入密钥自动开启。
- 填表核查只允许 DeepSeek 官方 profile，不自动改走 Vercel、其他网关、本地模型或模拟回放。响应错格式、拒绝/失败或未启用时保留草稿，不允许绕过 AI 关口继续提交。
- 单次输出上限 1024 tokens；同会话最多 3 次核查尝试（重建草稿不重置），同服务进程最多 20 次，最多 2 个并发。预算耗尽停止，不按用户请求自动重置；这是次数限制，不是金额保证。

## 复现与验收

```powershell
.venv/Scripts/python.exe -m pytest -q tests/test_intake.py
.venv/Scripts/python.exe scripts/verify_guided_intake.py
.venv/Scripts/python.exe scripts/verify_agent_workflow.py --output evidence/guided-intake-20261018/existing-workflow
.venv/Scripts/python.exe -m pytest -q
```

`verify_guided_intake.py` 明确注入 fake verifier，检查新入口、外发同意、未知保留、人工确认、本地提交、重复提交、历史归属和原有冲突暂停等 14 个检查点；**不是 DeepSeek 真实效果或正式申请验收**。证据在 `evidence/guided-intake-20261018/verification.json`。

浏览器检查同样只在独立临时端口、临时数据库和显式假核查器下做纯虚构资料回放，验证自填与选项混合填写、确认前禁用提交、提交回执及刷新恢复；没有用真实个人信息，也没有让 AI 替真实业务用户确认。截图中的 `deepseek-offline-fixture-not-inference` 是明确的回放标记。

正式运行的默认入口只允许先填写；真实模型开关关闭时页面明确提示“未启用”，不能把本地规范化结果冒称为 AI 已核查。

本轮结果：新入口 51 项定向测试通过，HTTP 生命周期 14/14、原工作流 21/21 检查通过，全量 562 项测试通过（3 个既有依赖警告）。所有模型测试均为离线假响应/合同回放，实际远程模型调用 0 次。
