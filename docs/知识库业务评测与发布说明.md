## 当前发布闸门

新运行目录默认使用 business 策略；策略丢失或阈值被降低时拒绝发布。本机真实候选目录也使用该策略。发布事务会同时核对：

1. 候选覆盖当前范围全部核定修订，待复核变化和排除/重分类决定均已处理；原件及片段指纹正确。
2. 业务评测报告绑定本次版本、原件/分类/引用指纹、来源配置和发布策略；变更后旧报告不能复用。
3. 至少30条不同问题，每题都有明确来源的参考答案、被测实际答案、真实执行者的评阅判定和回答/停止结果。新契约须保存AI/人类身份、参考冻结及运行时序、输入/轨迹指纹，并与数据库全部已知开发题登记核对。报告声明独立业务验收集，不能用开发调参样例或仅改写旧题冒充；旧契约仍只接受原真人字段。
4. 每条引用都指向本快照内实际存在的“修订ID+定位”；取回证据最多5条。正向题按题计算相关证据召回率，再求均值，目标≥90%。报告同时保留正向题分母和全部关键断言的支持数/总数。
5. 关键断言支持率100%，范围误用、失效规则作现行回答、关键材料漏项均为0。非空语料必须同时有正向回答题和停止题，不能靠全都拒答通过。
6. 被发布文件的来源启用、未暂停、访问/使用筛查仍有效、最近成功检查未超过配置周期加15分钟，且之后没有未恢复的检查失败。

校验器核对报告结构、版本、指纹、位置和数值。事实、语义独立性及引用支持关系仍须由实际执行者据证核查；填写状态、身份或轨迹哈希不会由软件自动证明政策真实有效。AI评阅不改写为真人，正式评测还须保留对应两端Agent真实轨迹。

工程测试目录显式使用 engineering_fixture 策略，并且只允许文种为 synthetic、来源筛查主体也标为 synthetic 的模拟资料。该模式不会为真实官方文件跳过业务闸门；测试通过不能称为真实业务验收。

## 复核包

运行以下命令会把当前归档的原件位置/指纹、来源访问状态、原始页面标注、带定位片段、分类提案和30条问题导出到私有目录；现为21份归档，其中12份最新修订排除试点、9份待复核。另附AI参考集、真实策略、开发题登记和通用执行者复核字段；真人签字及真人标准答案字段仍留空：

```powershell
.\.venv\Scripts\python.exe scripts\export_knowledge_review_packet.py
```

人工材料标准表至少记录材料名称、适用条件、必交/条件交/替代关系、来源定位和未决问题。先解决[具体复核清单](知识库首批业务复核清单.md)，再通过维护CLI修订元数据及逐份复核。资料不适用时记录排除理由，不删除历史。

```powershell
.\.venv\Scripts\python.exe -m gov_mcp.knowledge_cli --runtime .runtime/knowledge-update exclude <最新修订ID> --reviewer <真实复核人> --reason <实际排除原因> --confirmed
# 需要重新核定已排除资料时，显式重开；重开后仍待复核，生效日不会自动继承。
.\.venv\Scripts\python.exe -m gov_mcp.knowledge_cli --runtime .runtime/knowledge-update reopen <排除修订ID> --reviewer <真实复核人> --confirmed
```

## 报告与发布

资料实际复核完成后生成候选版本，取得当前绑定值：

```powershell
.\.venv\Scripts\python.exe -m gov_mcp.knowledge_cli --runtime .runtime/knowledge-update candidate --region 郑州市二七区 --matter demo-id-renewal
.\.venv\Scripts\python.exe -m gov_mcp.knowledge_cli --runtime .runtime/knowledge-update evaluation-binding <候选版本>
```

当前schema=2报告按[新契约字段表](知识库AI复核契约与留出评测.md)填写。旧schema=1报告根字段为 `version`、`snapshot_binding`、`status=human_reviewed`、`reference_author_kind=human`、实际 `reference_reviewer`、带时区的 `reference_reviewed_at`、`dataset_role=independent_business_acceptance` 和 `cases`。当前草案不能直接改个状态就作为通过报告。

每题填写唯一 `id/question`、实际 `reference_answer/observed_answer`、`expected_outcome/observed_outcome`（answer或stop）、四个零错误计数 `unsupported_claims/wrong_region_claims/expired_rules_as_current/missing_critical_requirements`、`claim_count/supported_claim_count`、标准证据 `relevant_evidence` 与实际取回 `retrieved_top5`。新契约使用 `review_judgment=pass`、具体 `review_notes`、输入和轨迹指纹；旧契约使用 `human_judgment=pass`，不得混用。每条证据格式为 `{"revision":"实际修订ID","locator":"实际条款或页码"}`。停止题不填写业务断言或回答证据。

```powershell
.\.venv\Scripts\python.exe -m gov_mcp.knowledge_cli --runtime .runtime/knowledge-update record-evaluation <候选版本> <实际报告JSON> --reviewer <真实评测人> --confirmed
.\.venv\Scripts\python.exe -m gov_mcp.knowledge_cli --runtime .runtime/knowledge-update publication-check <候选版本>
.\.venv\Scripts\python.exe -m gov_mcp.knowledge_cli --runtime .runtime/knowledge-update publish <候选版本> --maintainer <实际维护人> --confirmed
```

资料复核通过而新版本尚未发布时，当前范围返回 `UPDATE_AWAITING_PUBLICATION`，不会先用旧答案填补间隙。撤出所有文件可形成空的新快照，旧引用仍能按历史版本还原。回滚只恢复发布指针，不能绕过后来已核定变化；存在较新决定时仍会停止现行回答，需重新核定适用版本。

发布后仍持续核对来源新鲜度。来源暂停、停用、最近检查失败未恢复，或超过检查周期加15分钟没有成功检查时，现行问答返回 `SOURCE_CHECK_REQUIRED`；历史版本仍可明确指定并还原，结果带历史标记。这样不会把“曾经发布过”当成“现在已确认仍为最新”。
