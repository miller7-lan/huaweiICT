# 30题给定证据的模型预验证

2026-10-16，北京时间。本项使用项目已配置的本地`gov-qwen3-4b:ctx8192-v1`模型，检查它在获得指定原文片段后如何作答。被测模型不接收参考答案、预期行为、逐题未决答案表或评阅规则。

它与正式咨询和发布验收分别记录。片段仍是待复核资料；只读正式咨询接口继续停止回答，预验证不会更改候选状态、发布指针、business策略或原/M1/M2 Agent。

## 固定输入和评阅标准

- 30个问题沿用现有独立业务草案；上下文取自此前AI参考集绑定的归档定位，逐项核对原件及正文指纹。这是预先指定证据的上下文选择，不测检索召回率。
- 仅将本地实际归档原文、原始页面日期观察、定位、地区和待核查状态传入模型。未归档的网页内容不传入，包括采集器被拒的二七区2026新闻和收费文件；缺少这些补充不能直接算模型知识错误。
- 先保存参考集、[逐题评阅规则](../evaluation/knowledge/pilot-model-prevalidation-rubric.json)、系统提示、输出schema、模型摘要、输入payload及清单指纹，再发起请求。每次验证编号对应固定输入；修改标准或提示需要新编号，不能覆盖原结果。
- 每题最多一次本地请求，不自动纠正答案或重试语义失败。原始响应、耗时和token计数保存在私有目录，公开结果带原始轨迹指纹；超时单独保留并先核对原进程。

## 两层检查

程序检查模型是否正常结束、是否使用冻结模型、返回是否有界、引用ID是否属于该题、短引文是否逐字存在于原片段以及上下文是否保留输出空间。它不判断条文能否支持结论。

随后由Codex AI对照冻结规则和原片段评阅：材料分支、交验/交回环节、后续25日措施、日期层次、范围边界、隐私及禁止无依据保证。结果明确标注AI评阅，不能伪装独立真人金标准或正式业务通过；同一AI作者的草案与评阅也不构成独立人工验收。

已观察到“引用存在但结论不成立”的情形：首题引用了真实材料列表及省级159条，却仍把户口簿和旧证列为当前需要携带的清单，没有解决初领/换领分支差异。该题程序检查通过，语义评阅不通过。短引文仅修改标点也会单列程序错误，不据此自动判定整项政策分析错误。

同一编号再次运行只处理缺失题目，保留已经取得的成功和失败响应。观察超时并不表示后台已停止，须先核对原会话/模型请求状态。模型定义、输入清单或冻结参考内容变化时拒绝继续沿用原编号。

本机通过Ollama原生本地接口返回JSON，依据[聊天接口](https://docs.ollama.com/api/chat)和[结构化输出说明](https://docs.ollama.com/capabilities/structured-outputs)设置schema、关闭思考输出并记录完成原因。此项直接调用本地模型，不能称作Nexent两端完整联调、线上问答准确率或真实政策发布验收。

14项运行器针对性检查通过，覆盖标准答案隔离、逐字引用/OCR不擅改、跨题引用、额外权限字段、长度限制、路径边界及冻结清单变化拒绝，以及AI评阅不能冒充真人、换绑其他回答或使用空/虚构举例。模型实际结果及AI评阅须以完成后的证据文件为准，不能凭运行器检查或单题输出宣称30题通过。
