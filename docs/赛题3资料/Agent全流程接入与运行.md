现在有一套可以操作的本机**全流程模拟工作台**。群众提问、离线三角色协作、条件计算、原文检索、心跳更新、冲突暂停、专业人员复核、分项发布、版本回退和记录追溯，使用同一个持久化工作流。

**模型 API 继续留空。** 这里运行的是实际程序工具和确定性离线角色，不是 Qwen 推理；Jev 使用明确标注的合同回放，不是 Jev 实际分类。资料为虚构的“模拟市通行卡到期换领”，不提供真实办事建议。真实官网、真实模型和新版 Nexent 原生编排仍需单独接入和验收。

## 直接启动

在项目目录执行：

```powershell
.\scripts\start_agent_workflow.ps1
```

打开 [本机工作台](http://127.0.0.1:8780/)。这个入口不依赖 Docker，便于先演示流程；只监听 `127.0.0.1`。

如需其他端口：

```powershell
.\scripts\start_agent_workflow.ps1 -Port 8781
```

Python 依赖沿用项目 `.venv` 和 `requirements.lock`；本轮没有额外下载模型、调用付费服务或更改原有 Nexent Agent。新入口直接使用的 Starlette、Uvicorn 版本已在 `pyproject.toml` 显式声明，与现有锁文件一致。

## 群众怎样使用

1. 点击“进入模拟群众咨询”。
2. 逐层选择“到期换领 → 成年人 → 本人”。未成年人、遗失和代办不会套用成年本人清单。
3. 模拟电子校验结果先保留“不清楚”，生成清单。系统给出已经能确认的申请、领取要求，同时把纸质表与电子表放入待核实区。
4. 选择“补充情况（可选）”，再选择“模拟校验通过”，重新生成。电子表可以进入清单，纸质表不再作为确定要求。
5. 每项展开查看适用条件、关系路径、原文、定位、指纹和版本。检索原文的结果不等于已经确认的业务要求。

选项中的电子校验是**演练输入**，不能声称已经查询真实电子证照系统。补充问题以资料文本处理，当前离线版不根据自由文本生成新的政策结论，也不让问题中的指令调用工具。

查询依次执行主控、检索和核验角色。第一轮一并获取已知的直接原文及分支、条件、适用范围和规范引用，核验发现真实缺口时才补查，最多三轮。没有已确认要求时跳过无意义检索，仍由程序返回未确认要求或继续选分支等状态，不解释为免交材料。用户没填的事实保持未知，不靠增加检索轮数猜测。

每次补充情况创建新任务并关联旧任务，旧答案不覆盖。匿名群众会话在服务重启后需重新进入；专业人员仍可查看持久化的咨询记录。

## 专业人员怎样演示更新

专业人员入口需要本机口令。首次启动自动生成在私有文件 `.runtime/agent-workflow/access.json`，读取 `professional_token` 并在页面填写。它仅用于这个本机模拟服务，不是模型 API 密钥。`mcp_token` 是另外的服务身份口令，不能当作专业人员口令。

```powershell
(Get-Content .runtime/agent-workflow/access.json | ConvertFrom-Json).professional_token
```

不要把口令发给他人、粘进提示词或提交 GitHub。

按以下顺序操作：

1. 进入“知识更新”，点击“登记模拟来源”。初始来源列表为空，不预设真实官网。
2. “立即检查”。初始正文没有变化，不创建知识版本，也不调用模型角色。
3. 将模拟来源切换为“正文发生变化”，再“立即检查”。系统建立变更包，更新原文检索层；旧卡申请动作和领取凭条要求立即暂停。
4. 查看分类回放、整理候选和核验记录。旧卡动作由“交验”改为“出示”，属于新旧冲突；领取凭条增加了“保持条码清晰”的说明。
5. 为变更包指定处理截止时间。没有设置时显示“等待专业人员指定”，不会自动算逾期；逾期不会恢复被暂停内容。
6. 勾选领取凭条项，填写复核说明，点击“确认所选项通过”；这一步只保存复核记录。
7. 点击“发布所选通过项”。领取凭条要求恢复，旧卡冲突继续暂停。发布前会检查当前版本、复核人、依赖和来源状态。
8. 旧卡冲突核对完成后，再复核并发布该项。别名与本体建议也需勾选、复核、发布，不会自动批准。
9. 在“版本与记录”查看咨询、审计和历史版本。回退只改变生效引用，不删除原文，不解除当前冲突控制。

“退回核实”的项继续暂停，后续可补充复核后重新确认；首版不把“拒绝新候选”直接解释为“旧要求已经有效”。

对于“工作人员正在更新相关政策，暂不提供服务”的提示，只停止受影响要求，其他已确认内容继续提供。这句话表示系统内相关政策资料待核对，不作为原发布机关正在修改政策的事实证明。

## 心跳、恢复和版本

- 服务每 30 秒保存存活时间；默认暂停，需要专业人员启动。普通检查周期为一小时，演示启动周期为一分钟，支持手动检查。
- 只读取登记的模拟来源状态；本轮不会扫描互联网或让模型扩展来源。正文噪声不会触发变更，来源失效明确记录失败。
- 延用原有 SQLite 存储的事务、租约、执行者编号和预算控制：同库一轮、租约 120 秒、预算 10 分钟；本轮模拟来源最多两篇变更资料、20 个片段以内。
- 分阶段保存已分类、已整理、已核验等进度。重启恢复尚未完成的阶段，旧执行者不能写入或发布；停机期间不会逐个补跑时间点。
- 同一当前正文不重复处理；正文恢复到以前状态也视为一次新的变化，旧的未完成包转为已替代，不能拿它覆盖新资料。
- 原文、片段和规范依据保持不可变。发布构建完成、校验通过后才切换版本；并发版本发生变化时拒绝覆盖，需刷新后重新检查。
- 查询固定开始时的知识版本，返回前重新读取暂停状态。历史答案保留原样，查看时另外叠加当前可用性；回退旧版本也不能绕过当前暂停。

## 检索与知识怎样分开

资料层自动保存分类后的原文、定位、指纹和本地稀疏向量；新原文可以在候选依据区展示。首版这里使用中文二元字组和词频的余弦检索，**不是已经接通云端稠密嵌入模型**。

业务知识层只发布专业人员确认的要求及依赖。程序使用三值规则计算“满足、不满足、未知”，而不是投票决定资格。候选、地区或时间未确认的内容不进入确定清单。

同义建议发布后保留原名与依据。本体建议发布会形成版本登记，但新的关系类型在执行器支持前只作登记说明，不自动扩展规则权限。

## MCP 与 Skills 的接线位置

独立 MCP 入口是 `http://127.0.0.1:8780/mcp/`，使用 Streamable HTTP 和私有 `mcp_token` 的 Bearer 身份。测试已通过实际 JSON-RPC 列工具和调用查询工具；令牌不要直接写入公开配置。

| 工具 | 本轮用途 |
| --- | --- |
| `govkb_query` | 调用完整离线问答编排 |
| `govkb_check_registered_sources` | 触发登记来源检查，执行者由程序控制 |
| `govkb_get_change_batch` | 读取本轮持久化的变化和候选 |
| `govkb_classify_changes` | 读取已执行的分类回放，避免重复收费调用的误解 |
| `govkb_submit_candidates` | 仅幂等确认完全一致的工程回放候选；不能提交任意业务修改 |
| `govkb_validate_candidates` | 读取程序核验及离线支持信号 |
| `govkb_finish_run` | 记录已完成运行的汇总，不能激活正式知识 |

正式发布、设置截止和回退在专业人员 HTTP 界面内，未暴露为模型 MCP 工具。群众不能调用维护接口；服务令牌不能充当专业人员会话。原文缓存预览要求登录，修改请求要求同源。

`config/skills/govkb-consult-engineering/SKILL.md` 是查询 Skill 模板。`config/decision/providers.template.json` 保留七个空角色接口。当前角色适配器实际串行调度程序，并保存角色、工具、任务、运行、输入输出指纹；远程模型调用数始终为零。

**后续已把这套查询的分阶段工具、Skill 和 6 个禁用草稿接入 Nexent，模型仍未绑定、草稿未发布；见 [先接线后启用 API](先接线后启用API.md)。** 本文记录原先模拟工程范围； 原来的 `gov_mcp.knowledge` 原生心跳和 8B/4B 接口继续保留；新工作流复用了其存储租约、Jev 分类与回放能力，使用独立数据库和页面。迁移真实原生编排时，必须转换候选结构、绑定可信身份，再跑同样的发布与暂停检查；不能混用两套服务的同名 MCP 工具和运行编号。
