# Agent 第一阶段：知识结构与三值判定

2026-10-17。依据 [整体架构草案](Agent整体架构草案-2026-10-17.md)落地第一阶段的程序基础：知识对象、原文和复核绑定、条件判定、模拟分支清单，以及返回前的暂停检查。

本阶段为独立离线演练。所有政策文字、地区、事项和“已确认”样本均为模拟，复核人类型固定为 `simulated_professional`。没有调用 Nexent Agent、Jev、模型或官网，也没有改动原 Agent 的运行配置。API 模板所有服务、模型、地址及凭据引用均为空。

## 已实现的内容

| 能力 | 实现行为 |
| --- | --- |
| 知识结构 | 事项、分支、环节、材料、提供要求、条件、规范条款、适用对应、别名和复核记录分别建模；提供 JSON Schema |
| 原文定位 | 原文 UTF-8 指纹、修订、逐字引文、Unicode 字符起止位置；不近似修补错误引用 |
| 复核绑定 | 复核指纹覆盖对象及其关联条件、适用关系、材料、原文等依赖；改变依据不能直接沿用旧记录 |
| 条件运算 | 受控 JSON 表达式，支持比较、集合判断、同时满足、任一满足和否定；结果为满足／不满足／未知 |
| 分支查询 | 逐层返回当前相关的已确认分支；选择分支编号不能替用户补出缺失条件 |
| 分环节要求 | 同一演练旧卡在申请时交验、领取时交回，作为两条独立要求判定 |
| 例外条件 | 电子表状态未知时，不默认要求纸质表；保留不依赖该条件的已确认内容 |
| 事实与适用性 | 待复核原文进入待确认区，不加入确定清单；没有确认时间适用性时返回未知 |
| 同义关联 | 仅已确认别名进入关联结果；待核对别名保留为候选，同一已确认别名不能指向不同材料 |
| 当前暂停检查 | 草稿固定知识快照；最终返回时再查当前暂停状态。原文、条件或材料暂停会影响对应要求及依赖项目 |
| 可选补充 | 需要用户条件时生成“补充情况”入口和缺少的字段；不自动转入连续追问 |

复核指纹用于完整性检查，不是实际人员身份认证或数字签名。真实发布服务仍需使用认证后的专业人员身份；本阶段不会把模拟记录当成真实业务批准。

## 运行

在项目目录执行：

```powershell
.venv/Scripts/python.exe scripts/run_decision_demo.py
```

会执行四组主要场景，并检查未覆盖分支、缺失条件、候选别名及 API 空配置等行为：

| 模拟情况 | 申请清单 | 领取清单 | 额外状态 |
| --- | --- | --- | --- |
| 电子表不可验证 | 提交纸质申请表、交验旧卡 | 交回旧卡、出示领取凭条 | 未核定居住证明只留待确认 |
| 电子表可验证 | 提交电子申请表、交验旧卡 | 交回旧卡、出示领取凭条 | 不把纸质表重复加入清单 |
| 电子表状态未知 | 仅交验旧卡 | 交回旧卡、出示领取凭条 | 纸质／电子表待确认，提供可选补充入口 |
| 草稿生成后发现交验条款冲突 | 暂停交验旧卡要求，其余独立项目照常提供 | 领取环节仍可提供 | 显示用户指定维护文案 |

“电子表可验证”在这里是模拟输入值，不代表系统已经核验真实电子材料。后续接入时应区分用户选择与可信工具核验结果，不将用户自报的 `true` 当作真实核验成功。

查看 [演练结果](../../evidence/decision-foundation/模拟规则演练.md)、[机器检查结果](../../evidence/decision-foundation/verification.json)和 [未知条件的完整输出](../../evidence/decision-foundation/example-3.json)。完整 JSON 保存每条要求的规则计算、依赖对象、依据路径、原文和版本。

可以单独输入一种模拟情况，避免 PowerShell 的 JSON 引号问题：

```powershell
.venv/Scripts/python.exe scripts/run_decision_demo.py --facts-file config/decision/examples/unknown.facts.json
.venv/Scripts/python.exe scripts/run_decision_demo.py --facts-file config/decision/examples/electronic.facts.json
```

单次输入结果仅保存至私有 `.runtime/decision-demo/<运行编号>/answer.json`。默认的固定演练会另生成可共享的工程证据；用户自定义输入不会自动写到公开证据目录。

## 文件位置

| 位置 | 用途 |
| --- | --- |
| `src/gov_mcp/decision/models.py` | 严格知识模型、引用检查和复核依赖绑定 |
| `src/gov_mcp/decision/logic.py` | 三值运算及表达式深度、数量和类型限制 |
| `src/gov_mcp/decision/service.py` | 分支查询、分环节清单、依据路径、当前暂停检查 |
| `config/decision/synthetic.snapshot.json` | 三份模拟原文、六条提供要求和模拟复核记录 |
| `config/decision/snapshot.schema.json` | 知识快照 JSON Schema |
| `config/decision/providers.template.json` | 全部留空且未启用的 API 配置模板 |
| `scripts/build_decision_fixture.py` | 重建模拟快照和 Schema；拒绝覆盖内容不同的既有版本文件 |
| `scripts/run_decision_demo.py` | 固定演练或自定义条件的离线运行入口 |

模拟有效区间明确写在演练原文中。日期字段使用包含起点、不包含终点的程序表示，不自动将真实政策里的“截至”等文字换算为这个边界。其他字段的缺失、类型错误、未确认例外都不会自动变成满足。

程序不执行表达式中的任意 Python、SQL 或文档指令。输入只使用登记字段；未知运算或超出预算的表达式整体返回未知，不能靠另一个为真的分支绕过定义错误。

## 验证结果与边界

本轮新增 65 项规则与知识结构测试通过；包含全部三值真值组合、未知例外、布尔与数字混淆、日期、失效复核记录、缺失依赖、候选关系、跨资料来源及生成期间暂停等检查。全项目回归 281 项通过，保留 3 条既有依赖警告。离线演练另有 16/16 项场景检查通过。

这里的依据路径来自已确认模拟对象及其引用关系，属于程序层关系追踪。尚未接入三角色 Agent 的真实调度、语义检索与最多三轮补查，也未证明真实跨文档推理效果。

当前暂停状态和草稿任务仅保存在本次进程内，用于验证接口和判定逻辑，尚未持久化为业务服务。它不是已有知识库心跳数据库的替代实现，也不提供认证、正式发布或解除暂停接口。

下一阶段先接查询侧三角色契约、检索补查与逐层选择页面；再把变更包、专业人员截止时间和复核发布接到持久化任务与版本管理。真实业务核对、真实模型效果及独立验收仍按用户选择放在后续阶段。
