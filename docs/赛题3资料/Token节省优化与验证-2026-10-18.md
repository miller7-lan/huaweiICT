# Token 节省优化与验证

日期：2026-10-18。基线提交：`c5b083407fbb29c48c3fb7c42e40b66cb5263226`。本轮优先减少无关输入与重复模型请求，不压缩政策原文、不减少独立核验、不扩大外发范围，不启用真实推理，不安装新依赖。

## 1. 本轮落地

| 调整 | 节省方式 | 保留的边界 |
| --- | --- | --- |
| DeepSeek 角色、英译和填表输入统一紧凑 JSON | 删除 JSON 结构分隔符周围的无意义空格，不重复转义中文 | 字符串正文、否定、条件、数字、字段类型与顺序不变；不是摘要或截断 |
| 填表核查只发送当前选中值的标准映射 | 每个字段只发选中值、该值标准显示及字段 ID，不再发送未选中的其他选项 | 全部字段仍发送；`null` 保留；完整模板的私密标签检查先于投影；模型只核查映射与显示格式，不判断资格 |
| 同一草稿的精确候选缓存 | 同版本、同模板、同规范值、同模型配置与提示词的已验证候选，可在修改同义回答后复用 | 不是跨会话/跨草稿缓存，不按语义相似度复用，不复用别人的人工确认 |
| 保留供应商缓存命中明细 | DeepSeek 返回时记录 `input_cache_hit_tokens`、`input_cache_miss_tokens`，便于后续核算输入费 | 未返回明细时不虚报为零；返回明细须为非负整数，且命中＋未命中等于输入总量；不会因统计失败自动重试 |
| 页面明确标记精确缓存 | 显示本次未调用模型，缓存复核本轮输入/输出用量为零 | 不把缓存命中包装成新模型核查；仍要求本人逐项检查、确认 |

角色请求的上下文内容未做通用字段白名单裁剪，因为当前还没有每个未来原生任务的完整字段契约。贸然删除依据可能省 token 却损坏推理；这类优化应结合真实链路及留出任务实施，不能现在声称已经完成。

## 2. 精确缓存的安全契约

- 缓存在 `GuidedForm` 对象内，每个草稿最多 4 份候选；沿用草稿 30 分钟逻辑有效期，过期访问及提交后清除。删除、退出或进程退出后不通过 API 恢复；没有新增持久化、云记忆或跨用户缓存。
- 缓存只保存校验通过的模型结果、标准字段值、模型标识与数值用量，不包含原始回答、会话/草稿标识、访问口令或人工确认。
- 缓存键绑定知识版本、完整模板、规范值及核查器身份。真实核查器身份包含受限官方 profile、提示词和投影后的标准映射；每次查缓存前重新检查开关、官方路由及模板/值的隐私约束。
- 候选仍要重新通过完整字段、精确类型、事实不变、标准显示、未知项和当前知识版本检查。失败、恶意改写、缺字段及版本变化的结果不入缓存。
- 编辑始终使旧人工检查失效；复用候选也会生成新的随机 `review_id`，旧标识不能提交，新标识仍须精确布尔人工确认。没有修改原有知识版本事务检查和实时暂停门。
- HTTP 接口仍要求明确同意。为保持原有保守限流，新的复核尝试即使命中候选缓存，也仍计入同会话 3 次、进程 20 次的尝试限制；同 revision 的重复点击继续使用原有幂等结果，不新增尝试。没有新增“命中缓存就能无限重试”的通道。
- 供应商前缀缓存与本地候选缓存不同：前者依然调用模型，只可能降低部分输入费用；后者确实不发本次模型请求。本地缓存不证明供应商删除或不保存原有请求，也不自动授权真实个人资料。

Jev 英译链现有字符串去重和缓存继续保留。本轮只紧凑序列化英译输入，没有新增全局翻译缓存，没有改变英文路线、原文保留、数字检查、预算或账号失败阻断。

## 3. 验证结果与不能夸大的部分

证据目录：`evidence/token-savings-20261018/`。

| 验证 | 结果 | 范围 |
| --- | --- | --- |
| 填表完整 system＋user 消息内容 | 基线 **1,303 bytes** → 当前 **1,006 bytes**，减少 **22.79%** | 固定模拟案例的 UTF-8 字节，不是供应商实际 token，也不是费用下降比例；计算已包含新增安全说明 |
| 初次核查→同规范值修改原回答→再次核查 | 基线需 2 次请求，当前 **1 次 MockTransport 请求** | 节省的是这个特定重复场景，不能推广成所有请求减半；原先同 revision 重复点击本来已幂等 |
| 节省与边界专用演练 | **8/8 通过** | 假模型、模拟用量；实际远程模型调用 **0** |
| 完整回归 | **579 项通过**，3 条既有依赖警告 | 新增 17 个用例；不能代替真实模型质量或业务准确率 |
| 新入口 HTTP 生命周期 | **14/14 通过** | 仍是显式假核查器、模拟资料与本地咨询 |
| 原工作流完整生命周期 | **21/21 通过** | 查询、未知、来源失败、暂停、分项发布、历史和回退 |
| 前端脚本 | `node --check` 通过 | 本轮未重跑浏览器视觉验收 |

新增测试覆盖紧凑序列化的原文/类型/顺序不变、缓存明细缺失和伪造、缓存隔离、值/模板/版本/提示词变化、关闭开关、路由限制、未选项的嵌套私密标签、恶意候选拒绝、过期及提交清除、4 份容量上限、外发同意和尝试预算、旧确认拒绝及重新人工确认。

本轮没有供应商 tokenizer 或实际推理用量，**不能把“字节减少 22.79%”写成“token/账单减少 22.79%”**。缓存统计中的示例数字也是本地 HTTP 假响应，不是实际缓存命中率。真实授权联调后，应同时比较输入/输出 tokens、供应商命中/未命中、调用次数、延迟、总费用、引用完整性和错误确定项，计算整体净收益。

## 4. 复现与生效

```powershell
.venv/Scripts/python.exe scripts/verify_token_savings.py
.venv/Scripts/python.exe -m pytest -q --junitxml=evidence/token-savings-20261018/regression.xml
.venv/Scripts/python.exe scripts/verify_guided_intake.py --output evidence/token-savings-20261018/intake/verification.json
.venv/Scripts/python.exe scripts/verify_agent_workflow.py --output evidence/token-savings-20261018/existing-workflow
node --check src/gov_mcp/decision/intake.js
```

演练仅使用临时数据库、MockTransport 和虚构占位密钥，不读取本机密钥；只在该临时工作流内开启假核查器，不改磁盘上的启用配置。旧证据目录保持不变；旧源码指纹属于旧基线，新实现验收以本轮目录为准。

已经运行的工作台需要由维护者择机重启以加载新代码；本轮没有重启现有服务，避免清除正在填写的内存草稿。磁盘配置的 `inference_enabled` 和 `form_verifier_enabled` 均继续为 `false`，改进代码不会自动授权模型外发。

## 5. 后续优先级

1. 在明确授权后，对小批模拟资料做真实用量对照；先确认哪里耗费，不能用估计代替账单。
2. 给真实主/子 Agent 接口定义任务级最小证据包，只发送当前必要依据；必要条件、例外、规范和精确引用不能删。
3. 根据实测再决定是否采用 TOON 或本地压缩模型。当前 DeepSeek 输入较便宜，引入模型下载、额外推理和潜在误删未必划算。

本轮借鉴的是 [GPTCache 的精确缓存机制](https://github.com/zilliztech/GPTCache)、[上下文按需管理](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/short-term-memory.mdx)和 [DeepSeek 官方缓存用量说明](https://api-docs.deepseek.com/guides/kv_cache/)，没有引入这些库或第三方记忆服务。后续仍按大赛主线补真实资产、本体演化、跨文档推理和业务评测，不为节省 token 取消核心验收环节。
