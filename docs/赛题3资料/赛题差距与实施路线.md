# 第三题对照：当前缺什么、下一步怎么落地

核对日期：2026-10-13。正式要求及权重见 [官方赛题摘录](官方赛题摘录.md)。本报告基于当前目录的实现、配置和已有验收记录；本轮没有重新运行原生 Agent、M1 全套测试或业务评测。

2026-10-14 进展：此处以下为前轮基线，运行状态以最新记录为准。Docker 已恢复，独立 Skill 的上传/绑定/原生执行/导出已验证；新增中文向量模型通过 Nexent 连通性，模拟文本、CSV、图片 OCR 共 9 片段与向量检索演练通过，本体种子及评测模板已准备。真实资产、半自动本体、多跳和动态更新的缺项仍成立。详见 [基础准备与课程说明](基础准备与课程说明.md)。

**判断：项目已有 Nexent 多 Agent、MCP、角色隔离及异常处理基础，但尚未证明第三题要求的“资产认知→半自动本体→多跳推理→动态演化→Skills 复用”闭环。仅完成现有 M2 单事项办事引导，还不足以覆盖全部核心要求。**

证据定位：`src/gov_mcp/extension.py` 在业务库非空时返回 `BLANK_BOUNDARY_VIOLATED`，更新输入非空时返回 `M1_INPUT_NOT_ALLOWED`；`core.py` 和两份 Agent 配置围绕空白验收；`workbench.html` 当前展示空材料和空知识。`evidence/m1-completion-audit.json` 保存历史 PASS 和 116 项测试记录，不是本轮新执行结果。

本机现状：vendor 已有 v2.7.0 源码及本地修改，`.runtime` 中存在原环境配置；`.runtime/m1` 不存在，本轮 Docker Linux 引擎未运行。因此没有宣称本机已打开、登录或复测项目网站。前期 G 盘机器与当前 C 盘目录的运行状态不能混用。

## 应调整现有计划的地方

1. 把多模态资产处理从“文字闭环后再评估”改为首轮核心交付。控制样本规模，但文本、表格、图文都应真实跑通。
2. 在 M2 引导/交接之外增加资产登记、本体候选和规范对齐；M3 同时覆盖本体结构演化和知识内容演化。
3. 把自定义 Skills 导入、绑定、真实执行列为独立验收；单纯增加 Agent 数量不能证明 Skill 深度集成。
4. 把算法与效率评测前置。初赛算法维度占 25%，需要方法、对照及真实结果，不能只写架构愿景。
5. 首版只做政务一个行业；多行业迁移放在核心闭环完成之后，作为总决赛加分验证。

## 建议的最小演示范围

保留“单地区、单事项”的可控边界，但选择一个确实需要跨资料、条件分支和表格/图文理解的任务。现有身份证换领候选可以先检查资料是否足够；如全部答案来自同一份短指南，它就不足以支撑本题的多跳与演化演示。是否更换事项由团队核定，不在本轮自动改业务范围。

准备三类来源：官方规范/政策文本、官方材料清单或流程表格、真实公开图文/扫描件。公众指南能用于原型，但“沉睡存量资产”的业务价值还需要说明资料散落、重复整理、人工关联的实际成本；不要把几页网上资料包装成已经接入政府内部档案。争取学校、合作单位或公开渠道的可使用脱敏存量资料，记录实际来源。

演示链路建议：

1. 导入一组资料，显示每个 asset_id、来源、格式、页/段/单元格/图像区域和解析状态。
2. 少量人工定义的种子本体引导候选抽取，人工检查新增类型、关系、同义项和标准条款映射后发布。
3. 提出一条需两份以上文档联合回答的业务问题，显示检索证据、经验证的多跳路径、规则条件和未确认项。
4. 将群众请求保存为交接，工作人员查看同一版本依据并确认材料前提；结果仍限定为辅助核验。
5. 加入实际有来源的更新资料，展示本体/内容差异、影响任务、人工复核及发布；旧任务按旧版本回放。
6. 在另一个干净实例导入 Agent、MCP 配置和 Skill 包，重复上述核心任务，证明可部署复用。

如果没有第二份真实版本，只能演示明确标注的人工构造工程变化，并另列真实政策演化验证未完成；不能把模拟文件当作官方更新。

## 可检验的算法方向

建议研究“种子本体约束下的候选抽取、复核优先级和局部更新”。这是工程研究假设，不能未经对照或查新就称为原创算法。

- 利用少量人工确认的类型、关系及规范条款作为约束，从不同模态抽取带定位和置信信息的候选。
- 先做类型/关系合法性、同义合并和冲突检测，再按模型不确定性及业务影响排序人工复核队列。
- 更新资料时依据实际来源指纹及关联关系重处理受影响片段；结构不兼容时产生本体迁移候选，禁止静默改历史任务。
- 对照无约束模型抽取、种子约束但无优先排序，以及加入排序/局部更新的版本；保持模型、资料和人工标注预算一致。

“低资源”应明确是标注/专家知识不足，并记录标注样本数、人工分钟数和模型调用量。当前使用 4B 模型或单卡部署，不能单独证明低资源本体构建优势。

## 首轮验收与指标

以下为项目建议，不是官方评分线；先建立可复核数据，再设目标值。

| 验证 | 方法 |
| --- | --- |
| 多模态统一资产 | 三类实际来源均产出可定位片段；检查关键字段、表格结构、OCR 错误及失败处理 |
| 半自动本体 | 人工标准下的类型/关系准确性、候选采纳率、每个确认项的复核时间和标注成本 |
| 标准对齐 | 映射正确数/已复核映射数；冲突和未对齐单独统计 |
| 多跳推理 | 独立任务下的答案、路径及逐步引用支持性；来源不够时的停止率 |
| 动态演化 | 本体与内容变更检测、影响范围精确率/召回率、局部更新时间、旧任务回放 |
| Skills 集成 | 导入、绑定、加载、MCP 调用及结果的真实轨迹；改变配置后能复用 |
| 业务价值 | 同任务人工基线与系统辅助的完成时间、材料遗漏/误报和人工纠正成本 |
| 性能复现 | 同模型/硬件下的中位及高分位耗时、失败率、资源占用；每项报告样本数 |

按独立案例组留出测试任务，标准答案不用于调提示词。现有 4B/8B 空库对照可继续说明模型选择，但不能当作多跳、本体或资产激活的效果评测。内部 95% 目标仍需团队核定，不写成官方要求。

## 下一批具体产物

1. 范围核定表和真实来源清单：能覆盖三类模态、两份以上文档的联合推理及至少一类标准映射。
2. 统一资产与本体字段契约：类型、约束、定位、版本、人工状态和变更影响规则。
3. 一条完整推理任务的人工标准：逐步事实、条件、关系、引用、最终输出及无依据时的停止行为。
4. 三份 Skill 的工作流设计和 Agent/MCP 调用关系图，再在独立环境逐一实现并验证。
5. 正式模板 Word 的栏目映射：每项要求对应代码、配置、资料、截图或指标；未实施内容明确标注设计阶段。

目前最值得先落实的是第 1–3 项。它们决定选定的业务是否能真实承载赛题要求，也能避免先画完页面后发现缺少本体、多跳和演化证据。
