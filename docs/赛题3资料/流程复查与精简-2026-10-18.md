# 流程复查与精简

日期：2026-10-18。范围：查询、分阶段 MCP、知识更新、翻译/Jev 调用、人工复核发布及恢复流程。本轮修改代码、模板和离线验证，不开启模型推理、不更新已部署 Agent、不提交或推送仓库。

## 调整原则

只减少不产生新证据、不改变决策或已知无法成功的重复工作。独立核验、当前暂停、人工复核、发布前重查及恢复检查各自承担不同职责，继续保留。角色数不是本轮的精简指标。

## 已修改

| 环节 | 先前行为 | 本轮调整 | 保留的保障 |
| --- | --- | --- | --- |
| 首轮检索 | 先取要求直接引用，再取已知分支、条件、范围和规范依据，正常样例固定两轮 | 根据固定草稿已有的完整证据依赖，一轮获取；仅在核验确有缺口时补查 | 所有引用、条件、版本和精确原文核验不减少，最多三轮仍生效 |
| 完整查询与分阶段 MCP | 两处各自实现证据计划与核验逻辑 | 共用 `_evidence_request` 与 `_verify_retrieval`，保持两种入口各自的持久化和响应契约 | 已验证依赖的集合一致；缺口只补未取到的证据 |
| 没有要求的任务 | 仍调用检索与核验空证据 | 跳过无意义取证；分阶段入口允许进入最终程序判断 | 仍检查快照和当前暂停；返回没有已确认要求、继续选分支等状态，绝不解释为免交材料 |
| 分阶段核验重试 | 结果写入后重试可能因阶段前进而报不允许 | 已完成的核验返回持久化结果，不增加轮次；重启后按未完成证据继续 | 最终返回仍重读当前暂停，不缓存过期的可服务结论 |
| Jev 前的翻译 | 即使 Jev 实例已经鉴权失败或预算耗尽，新文本仍可能先请求翻译 | 先执行 Jev `check_ready`，再翻译；无模型权限、固定模型不符或预算不足时直接失败待复核 | 翻译失败不回退中文；问题、标签、数字和译后大小检查保留 |
| 明确的账号失败 | DeepSeek 翻译及 TypeSafe 直连可能逐份资料重复同样的 401/402/403 | 同一供应商实例遇到此类失败后阻止后续相同账号调用；Vercel 原有阻断继续保留 | 本轮未移除原有超时/限流处理；错误继续使用固定代码，不保留服务错误正文 |
| 原生草稿与 Skill | 控制动作默认总会调一次检索/核验子角色 | 模板和本地 JSON 同步检查持久化状态，已经可返回时不启动空任务 | 有真实取证需求时仍依次调度独立检索、核验角色；没有发布权限 |
| 验证产物 | 完整演练默认写入原有最新目录 | 增加 `--output`，本轮保存独立证据目录 | 旧验收证据保持不变，不拿历史平台运行冒充当前模型联调 |

`check_ready` 的账号失败阻断作用于供应商实例。修正凭据或权限后，应重新创建实例或重启相关服务再试；不会自动增加后台付费重试。

## 检查后明确保留的环节

| 环节 | 保留原因 |
| --- | --- |
| 查询主控、检索、核验三个职责 | 规划、获取证据与验证证据是不同职责；合并取证批次不代表取消核验 |
| 缺口最多三轮 | 自定义或未来外部检索可能先缺后补，不能因为本地快照通常一轮完整而删除恢复空间 |
| 未知事实与证据缺口分别处理 | 没填的用户事实不能靠再次检索猜测；缺少引用则不能发布确定结论 |
| 发现变更时预先约束候选、提交时再验证结构 | 前者支持立即暂停，后者防止阶段间内容被改变；两次检查位于不同边界 |
| 来源有效性、租约和发布前版本检查 | 处理期间来源、执行者或知识版本可能改变，起始检查不能替代提交时重查 |
| 人工复核与发布分开 | “已看过并接受”不等于“正式生效”，保留分项发布与独立审计 |
| 历史与回退仍检查当前暂停 | 不能通过旧快照或重试绕过当前冲突 |
| 原文层、候选层、正式知识层分开 | 允许新原文可查，同时防止未经确认的要求进入确定清单 |
| 翻译与 Jev 分工、原始中文保留 | 用户已选定英文判断路线；本轮优化可用性预检，不删除翻译或改写中文出处 |

来源检查、没有正文变化时不执行模型角色、按阶段恢复、分类批量判断及译文缓存已有实现，本轮复查后继续沿用，不重复包装成新增能力。

## 优化后的查询顺序

1. 固定事实、分支和知识版本，程序形成要求草稿及完整证据依赖。
2. 有要求时一批获取当前已知的直接和依赖证据；没有要求时进入最终程序判断。
3. 独立核验精确原文、条件和适用性。缺引用才补查未完成部分，最多三轮。
4. 未知用户事实保持未知，必要时提示补充，不额外盲查。
5. 返回前重新检查当前暂停，并在事务中保存答案与追溯记录。

这项优化没有新增通用跨文档推理算法；它利用的是当前固定快照中已经列明的依赖。未来真实检索发现新关系或新证据需求时，仍需由真实执行适配器按边界补充，不能宣称已由一轮取证实现自动多跳。

上述耗时只是小规模模拟程序观察，受机器状态、缓存及样本量影响，不是云模型端到端、大库、业务精度或赛事性能保证。全过程真实模型调用为 0；没有重跑真实 Nexent 平台接线，也没有重新上传草稿。
