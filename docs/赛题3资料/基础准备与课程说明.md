## 当前打开的课程是什么

当前页面是官方《Nexent智能体开发（医疗行业为例）》的课程学习页，来自第十一届创新赛学习空间第三题。已加入，最近核查进度为 0%，播放器尚未完成学习。

官方课程介绍涉及提示词工程、MCP、Skills、Nexent 平台设计与使用方法；以医疗案例说明智能体开发路径。政务项目可以复用平台操作和工具编排方法，政务原文、规则、本体及评测需要自行准备。课程目录列出一个同名选修内容。不能仅凭介绍推定视频包含额外的数据包、代码或算力申请入口。

## 如何跑一遍

在项目根目录运行：

```powershell
# 重建隔离依赖、下载或校验模型、生成模拟数据、解析/向量化，接入既有本地 Nexent
.\scripts\setup_topic3_preparation.ps1

# 已准备好的本机直接重新执行资料演练
& '.runtime/preparation/.venv/Scripts/python.exe' scripts/prepare_topic3_data.py --generate-demo --embed
```

该演练先登记三个原件，提取文本/表格记录/OCR 片段，再用向量模型计算与查询的相似度并返回片段 ID。它是资料处理与检索基础，不是办事推理、图谱多跳或完整 Agent 业务验收。

输入与输出位置：

- 模拟原件：`.runtime/preparation/demo/`。文件显式标注模拟；已存在时生成入口不覆盖。
- 私有解析结果：`.runtime/preparation/run/assets.json`，保留原文和定位。
- 私有向量与检索排序：`.runtime/preparation/run/embedding.json`。
- 公开执行摘要：`evidence/toolchain/preparation-20261014/summary.json`，只保留来源 ID、指纹、数量和结果。
- Nexent 向量模型验收：`evidence/toolchain/preparation-20261014/embedding-native.json`。
- 原件、OCR 与向量独立复核：`evidence/toolchain/preparation-20261014/fixture-verification.json`。新增解析输入完整性检查 7 项通过，覆盖路径范围、空行定位、CSV 错列/重复列/跨行记录与不支持的 Office 文件。

原有 MCP 虚拟环境、原三个 Agent 的模型和发布版本均未因基础准备而修改。新增模型为独立条目；没有发布业务规则或把模拟资料写入原空白业务库。

## 后续换数据的步骤

1. 把新原件放在工作区专用资料目录；保留原件。复制 `assets.real.template.json`，填入地区、事项和 assets 列表。
2. 逐份填写 source_id、path、title、modality、source_url、review_status；无法核查的发布日期和生效日期保留 null。登记使用依据和复核人。`modality` 采用 text、table 或 image。
3. 运行 `prepare_topic3_data.py --manifest <清单路径> --embed`，不带 `--generate-demo`。输出目录可以在复制的 profile 中调整，但原文结果必须留在 `.runtime/preparation/`。
4. 人工核对 OCR、表格结构和段落定位。当前支持 txt/md、CSV、PNG/JPEG；PDF、Word、Excel 等应增加专用解析器或接入 Nexent data-process 后再验证，不通过改后缀假装解析。
5. 依据新数据修订本体种子，产生带来源的候选并复核；准备跨文档任务和标准答案，再实现半自动本体、推理、动态更新和正式 Skills。

当前示例 manifest 的路径和模态见对应 JSON。示例种子不与某个身份证事项绑定；更换数据时要重新核定规则、本体映射和评测答案，不能只换原文而沿用旧业务结论。
