## 三、最影响达标的四个具体问题

1. **“准备了模型端口”还没有变成“当前业务由 Nexent 执行”。** `workflow.py:57` 构造离线角色，`connections.py:202` 的 `WiredRoles.invoke` 只准备路由元数据后执行离线 callable。`request_nexent` 有传输实现，但本次搜索未发现当前业务调用它，匹配只出现在定义和测试中。应实现并验收原生执行路径，不能只修改 `inference_enabled`。
2. **当前本体建议不会改变答案。** `workflow.py:684` 把已确认建议存为不可执行；种子本体与固定快照也未形成通用执行契约。应选择一个业务确需的新关系或约束，让它真正改变受影响查询。固定规则可以作为受约束执行基础，关键是新结构能被验证并实际使用。
3. **现有关系路径不等于已经证明跨文档推理。** `service.py:193` 起按事项、分支、要求、材料、环节和条款拼装路径。它能解释固定规则，但还需证明独立问题的结果确实依赖多份原文及多步关系。无需先更换图数据库；先让现有可审查数据结构完成一条真实任务。
4. **换真实资料不只是填一份清单。** 准备脚本允许登记 `public/private`，但 `asset_query.py:48`、`connections.py:36` 和模型请求路径仍限定 `synthetic`。应为已审查的公开来源建立独立数据接入与外发策略，保留默认拒绝、来源撤权和审计；不得把真实数据标成模拟来绕过限制。稠密向量服务未配置，但官方任务并未强制某种向量实现，可先用可解释检索完成闭环。

补充边界：DeepSeek 最新归档为配置完成、真实推理尝试 0、原生草稿未绑定；两个模型开关当前均关闭。Jev 最新归档为 10-17 的 403 权限受限，本次没有重试。Jev 和英文翻译不是赛题强制组件，不应成为核心建设的前置条件。

## 四、下一步实施顺序与停止条件

以下数量均为项目建议，不是官方最低样本数或官方通过线。先交付真实、可检查的小闭环，再按观察到的失败扩充。

### 阶段 A：固定真实事项、来源包和独立答案

优先检查现有身份证换领候选能否支撑跨资料、条件例外和三类模态；若资料不够，再提出替代事项供团队核定。避免先开发完后才发现所有答案都在同一页。

交付：

- 一页范围表：地区、事项、使用者、要解决的人工查找问题、允许回答及停止范围。
- 一组经审查资料：规范文本、材料表格、真实图文说明，登记原件、来源、使用依据、适用日期、指纹及定位。网页截图可以作为图文输入，但不能冒称来自业务扫描档案；如转存 CSV，要保留原表、转换记录并检查结构。
- 建议先准备 20 个独立验收案例，覆盖正常、跨文档、条件未知、图表、冲突、越界、更新及历史回放；其中至少 3 个确需不同文档的多步关系。由未调试该答案的人复核，按原始案例组留出。
- 一条核心任务的人工推导：每步事实、关系、条件、原文、最终结论和不能确定的部分。此时先形成答案，不等模型跑完才编标准。

停止条件：资料确实能承载赛题要求，核心任务没有关键依据空缺，使用边界和独立答案可复核。未通过时继续补资料，不继续扩页面。

### 阶段 B：接通资产、候选本体和规范映射

复用 `prepare_topic3_data.py` 的资产和定位设计，建立“解析结果→带来源候选→人工裁定→正式图谱”的导入契约。候选包括实例与类型、关系、约束，分别管理，不能只抽取材料名称。

交付：经审核公开数据的接入策略；候选及裁定记录；本体与知识版本；真实条款映射。模型只提建议，程序约束检查和人工发布继续保留。自动候选生成在获准模型调用后验收；静态接口和人工标准可以提前准备。

停止条件：三类真实资料均能贡献可定位的候选；无来源或未确认的候选不能进入确定结论；记录种子数量、人工标注量、复核分钟数、正确采纳和错误采纳数量。

### 阶段 C：实现一条多文档推理和一次可执行演化

先实现受约束关系组合与逐跳核验，不先追求任意自然语言政务问答。每跳记录输入事实、边、来源、适用条件和版本；缺失、冲突或未知时保留待核实。

从阶段 A 的真实业务选择一种所需结构变化，例如某种有条件替代关系；此处仅为机制示例，不能写成真实政策事实。让它经历候选、复核、发布、兼容检查，并改变实际查询结果；依据来源与依赖计算受影响项，而非在包中预填答案。

停止条件：有一条至少依赖两份原文的逐跳结果，移除关键资料后无法给出原确定结论；新增结构实际生效，影响范围可解释；历史可查，回退和当前暂停门仍有效。无真实新旧政策时只报告受控模拟变化，真实动态更新效果单列未验证。

### 阶段 D：完成当前业务的 Nexent 原生闭环

代码与契约可在前述阶段准备，真实调用仍按当前“最后启用 API”的约定，在明确授权后进行。实现对原生主控、检索、核验及更新路径的调用和持久化状态对接；沿用现有角色数量，是否拆为独立子 Agent 以可验证的实际调用需要为准。

交付：固定版本的 Agent JSON、MCP 配置、实际绑定的 Skill 包、模型与工具说明；至少一次真实咨询轨迹、一次更新候选到人工发布轨迹，以及必要失败路径。记录平台、模型、Skill、知识和本体版本，移除凭据和个人信息后保存证据。

停止条件：Nexent 页面能启动当前业务；轨迹能证明 Skill 加载和所声称的主/子 Agent、MCP 调用；返回结果与程序保存状态一致；模型不能自行发布。默认关闭的填表核查是单独路径，需要其真实证据才能展示完整成功流程。

### 阶段 E：效果对照、复用、复现与材料收尾

最小效果证明先做两组，保持资料、模型和专家投入可比较：

| 需要证明的价值 | 对照 | 记录 |
| --- | --- | --- |
| 少量种子能减少本体整理成本 | 相同少量示例和专家时间下，普通候选复核与种子约束方案 | 每专家分钟正确采纳项、错误采纳、规范映射正确性、模型调用量 |
| 关系和边界检查能改善业务决策 | 同资料同模型下，普通 RAG 与项目方案；小部分任务补人工查找耗时 | 错误确定项、遗漏、逐跳和引用支持、恰当待核实、耗时及真实用量 |

再做一次演化检查和一次第二事项/地区迁移，记录影响遗漏、处理成本、配置与代码改动；先不为材料增加庞大实验矩阵。样本少就报告样本数与适用范围，不外推高准确率。更复杂的复核排序算法和全量重建对照放在有时间且基础结果可用后。

并行取得官方 Word 原件、核定作品提交时间和模板栏目；正式材料写入实际结果后收尾。初赛包应能对应设计、图谱、智能体、原始数据、处理、模型工具与知识库、调用关系、调试截图，以及 Agent JSON、知识库、MCP 和 Skills 配套文件。内部实施计划书不能替代官方模板。决赛 PPT 按阶段要求准备。

停止条件：独立效果结果可复核、干净环境能按说明复现核心演示、包内无密钥和未授权数据、材料声明与实测一致。满足后停止扩展；正式上传和 Git 推送按当次授权执行。
