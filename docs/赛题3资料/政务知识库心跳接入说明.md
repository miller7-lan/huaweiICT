# 政务知识库心跳接入说明

2026-10-16。本分支增加独立的来源检查、主控/子 Agent 调度、候选复核及版本管理模块。正式来源列表初始为空，页面显示等待配置；模拟演示与正式资料目录分开保存。

本机已在 2026-10-15 实际跑通 8B 主控调用两个 4B 子 Agent，以及分类、提交候选、核验、完成任务的 MCP 操作。官网使用模拟页面，Jev 使用明确标注的接口回放；这份证据不包含真实官网采集或真实 Jev 中文分类效果。真实模型调用见 `evidence/knowledge-heartbeat/native-20261015T110751Z.json`；分级发布、回退、无变化跳过等 16 项检查见 `evidence/knowledge-heartbeat/lifecycle.json`。

## 日常怎么使用

先启动已有 Nexent、Ollama 和 Docker 环境，再在项目目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_knowledge.ps1
```

正式工作台为 <http://127.0.0.1:8775>。使用已有本地开发账号登录，查看来源、任务阶段、待复核候选、原文和历史版本；可以立即检查、暂停、恢复、确认发布及回退。来源原文缓存也要求登录。服务账号不能进入维护工作台。

工程演示独立启动：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_knowledge.ps1 -Demo
```

演示工作台为 <http://127.0.0.1:8778>，明确显示模拟网站及 Jev 回放标记，默认暂停。立即检查可以执行一次。演示数据和正式数据分别位于私有 `.runtime/knowledge-demo` 与 `.runtime/knowledge`；不能把演示回放用于真实资料。

## 各部分做什么

程序默认每小时检查一次已登记官网，每 30 秒保存服务存活状态。演示可以每分钟检查。没有正文或附件变化时不调用模型，不创建重复版本；导航文字变化不会单独触发内容更新。断网、403、验证码、空正文、解析失败均记为失败，保留旧版本。

发现变化后，程序建立持久化任务，Nexent 8B 主控调用 Jev 做三维分类，派 4B 整理子 Agent 提交带出处的知识候选，再派 4B 核验子 Agent 检查遗漏和冲突。Jev 另给出原文支持判断。程序验证引用确实属于本轮原文后建立候选。网页中的指令不能获得新增工具权限。

每轮最多 3 个子文档、20 个片段，执行预算 10 分钟。较长原文按每个子文档最多 6 个片段拆分，所有部分处理完成才切换该来源的资料版本。超额任务继续排队，不丢弃余文。同一库使用租约和递增执行编号限制为一轮；中断后恢复未完成阶段，失效执行者不能继续提交或切换版本。

三种更新须区分：

| 内容 | 处理方式 |
| --- | --- |
| 新原文、向量、机器分类 | 校验完成后自动进入资料检索，显示机器候选状态 |
| 条件、材料、部门、步骤等知识 | 维护者明确确认后进入正式业务知识层 |
| 本体类别、关系或标准对应提案 | 维护者确认后写入本体版本，后续处理使用新定义 |

模型没有正式发布或回退工具。模型之间一致、Jev 概率较高都不能代替确认。发现原文正文已经变化后，当前正式查询暂缓返回旧正文对应的规则，等待新候选复核；显式历史版本仍可追溯。来源检查失败会显示状态，不据此宣称规则失效。

版本内容不可修改。程序构建完成后比较基础版本再切换当前引用；回退只切换引用，不删除旧原文或历史版本。每次查询固定使用所选版本。

## 怎样登记真实官网

运行时配置位于 `.runtime/knowledge/heartbeat.json`，样例见 `config/knowledge/source.example.json`。逐项填写固定网址、正文选择器、允许的域名、附件精确网址和格式，并确认来源允许处理后启用。模型不能自行扩展来源。

当前正式来源限公开、已登记的 HTTPS 政务网站；正文支持 HTML，附件支持 TXT、CSV、PNG/JPEG，图片实际调用 OCR。PDF、Word、Excel 和需要动态交互的页面会明确报不支持。团队另一分支已经扩展的 PDF 资料链路尚未合并到本模块，不能据此宣称本模块已支持 PDF。

Jev 仍固定 `jev-1.13.0`。密钥放在本机环境或私有 `.runtime/knowledge/providers.env` 的 `TYPESAFE_API_KEY`，不写入 Git、界面或提示词。缺少密钥时显示等待凭据，不虚报分类或更新成功。配置或密钥调整后重跑启动入口，容器重建但任务目录保留。

## 模型与工具配置

主控、整理、核验三个角色在 `config/knowledge/heartbeat.json` 的 `models` 内分别配置。默认沿用本地 8B/4B 固定参数模型，串行调度并在阶段切换时释放聊天模型。实际运行仍受机器资源限制；后续可以在 Nexent 登记云模型，再替换对应角色配置。

嵌入模型默认使用本地 `qwen3-embedding:0.6b`。另封装 HTTPS 的 `openai_compatible` 嵌入接口，凭据使用环境变量引用；没有执行过真实云端迁移验证。嵌入配置改变时重新生成整库向量，避免不同向量空间混用。

独立 MCP 暴露以下维护工具，使用专用服务身份和本轮任务范围：

- `govkb_get_change_batch`：获取本轮变化和原文定位。
- `govkb_classify_changes`：分类并保存分流结果。
- `govkb_submit_candidates`：提交带原文出处的候选及可选本体提案。
- `govkb_validate_candidates`：检查结构、引用、冲突和支持判断。
- `govkb_finish_run`：提交任务汇总，供程序执行允许的后续处理。
- `govkb_search_evidence`：按资料层或正式知识层及版本查询证据。

另提供独立资料查询 Agent 配置，原有空库验收 Agent 和原资料演练工具接口保持其边界。Skill 负责工作顺序，每个 Agent 的 MCP 工具 ID 按具体服务绑定；不在 Skill 元数据中跨服务隐式合并同名工具，以避免正式/演示环境的工具重名。

## 已验证与还缺什么

工程测试覆盖来源无变化、导航噪声、正文变化、失败状态、缺密钥、任务分批、租约失效、中断恢复、严格原文引用、无效向量、人工发布、回退、身份与访问原文。TXT、CSV、中文图片解析实际执行结果见 `evidence/knowledge-heartbeat/parser-verification.json`。

真实主控和子 Agent 已实际执行；早期输出预算过大、子 Agent 未提交可执行动作、Skill 隐式合并同名工具等失败记录保留，修正后重新验证。`lifecycle.json` 的发布确认是隔离模拟资料的自动验收操作，不是假称有人确认了真实政策。

还需：选定真实来源、配置真实 Jev 密钥、测量中文分类和原文支持判断效果、核对真实来源适用关系，以及独立业务验收。通用知识实体关系图、多跳决策与规范对齐的完整业务效果仍不由本轮心跳工程证明。

复现脚本：

```powershell
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe scripts/verify_knowledge_formats.py
.venv/Scripts/python.exe scripts/verify_knowledge_native.py
.venv/Scripts/python.exe scripts/verify_knowledge_lifecycle.py
```

后三项需要相应服务运行；真实模型验收会调用本机模型，并在演示目录新增带时间标记的模拟来源版本。最后一项会对演示候选执行确认、回退和恢复，结束后暂停演示。不要把执行依赖未就绪解释为业务不变或检查成功。
