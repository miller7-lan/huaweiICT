## 问题与修改

此前温度试验中，三个温度均在 `quotation_unknown_injection` 多返回 `type: json_object`。旧评分正确保留了失败，但共享适配器仅检查返回可解析为对象，无法声明每次任务的精确字段。额外字段的生成原因没有得到独立证实；不能认定调低温度已修复。

新增 `StrictOutput` 输出契约。`chat(..., response_model=...)` 将应用定义的 JSON Schema 加入系统提示，明确要求输出实例、必填字段齐全、禁止附加字段，并说明 `response_format` 的协议元数据不属于答案。请求仍使用已有 JSON 对象模式，没有假设供应商支持新的严格 Schema API，也没有安装依赖。原始消息和证据不修改。

返回先严格解析，再按契约验证。所有共享 JSON 调用拒绝重复键、NaN、Infinity、溢出为无穷的数字、代码围栏及非对象；提供契约时还会拒绝多余字段、缺失字段和错误类型，不把数字转成布尔值、不把字符串转成数字、不删字段补判通过。契约错误仅返回固定错误码，不自动重试或切换供应商。

默认 DeepSeek 英译及区域预览英译已接入动态契约：只允许 `translations`，内部恰好为本次请求的所有键，值为字符串。原有英文、非空、数字、语义边界、凭据、预算和 Jev 前置检查继续保留。英译不合规时不会调用 Jev 或写入翻译缓存。

实验调用在遇到已解析但违反契约的返回时，可从异常的 `candidate_result` 保存未修改候选、用量及模型名，供脱敏证据追溯；它不是正常返回值。普通调用仍只处理固定错误码。无法唯一解析的重复键等返回不会被修补成候选。
