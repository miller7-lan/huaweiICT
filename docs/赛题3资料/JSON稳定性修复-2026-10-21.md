# JSON 稳定性修复（2026-10-21）

用户要求修复[核查发现的四类问题](JSON稳定性核查-2026-10-21.md)。四类代码缺口均已修复，相关离线检查通过。本轮未调用真实模型、HTTP或原生服务，不改变推理开关、暂停、人工确认、预算和平台Agent配置，不发布或推送。

## 修复结果

| 问题 | 当前行为 | 验证 |
| --- | --- | --- |

| 外部解析不统一 | [Jev官方](../../src/gov_mcp/classification.py)、[历史网关](../../src/gov_mcp/jev_gateway.py)、[备用Qwen及Nexent端口](../../src/gov_mcp/decision/connections.py)，以及本次涉及的原生final/SSE入口使用严格解析器，拒绝重复键、非有限数和错误根形状。Jev直接对象校验也拒绝非法JSON值及未声明字段；保留明确的供应商元数据命名空间和英译审计字段。 | 重复 `noul`、重复网关metadata字段、嵌套NaN、溢出、非法根形状、循环对象均阻断；合法官方历史回执、choice/noul和供应商metadata保留。 |

| 角色输出缺少Schema | [八组角色/工具契约](../../src/gov_mcp/decision/output_contracts.py)覆盖六个非Jev角色。DeepSeek传入具体 `response_model`，Qwen提示及响应采用相同契约；保留引用、unknown、暂停、人工复核和禁止发布约束。布尔常量另验证身份，避免 `Literal[False]` 接受整数0。 | 八组端口均检验合法候选原样返回、无关对象拒绝、缺失/额外字段与嵌套错类型拒绝；权限、隐私、开关、引用和暂停相关检查继续通过。 |

Jev的深层合法元数据可能在复制阶段触发 `RecursionError`；交叉复核后已将复制也纳入同一受控异常边界，保留合法元数据，不静默丢弃内容。两套旧预览测试桩缺少实际英译适配器一直提供的 `english_input.version`，已补齐桩数据，没有放宽业务校验器。

角色契约约束的是可选模型候选端口。当前 `Connections.request` 没有业务调用方，`WiredRoles` 继续执行本地程序；平台原生Agent不自动继承这些Schema。原生流程仍依赖其实际工具、持久回执、严格final解析和暂停/人工确认门。候选格式通过不等于原文真实、推理正确或业务批准。

## 保留的边界

旧严格契约4/4真实响应和旧原生成功属于各自执行指纹，本轮源码已变化，不能将其改称修复后的新模型生成试验。离线回放不增加真实样本分母，不证明长期遵循率，也未联网核定运行中服务当前加载的代码。

二进制float的舍入与下溢边界保持，未在缺乏业务契约时擅自改用Decimal。未来精确金额等字段应单独定义十进制表示。原有原件、引用、人工确认、当前版本和业务暂停门不因Schema或比较通过而解除。

之前的工程ZIP和平台导出仍是原冻结快照，没有重打包；它们不包含本轮Python修复。已消费的预算仍关闭，不为本次代码修复自动追加付费验证。
