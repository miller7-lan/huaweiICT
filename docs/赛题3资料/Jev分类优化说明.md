# Jev 分类判断优化

日期：2026-10-17。

2026-10-18 更新见 [Jev 英文翻译层](Jev英文翻译层.md)：默认供应商已加入英文适配，规则版本更新为 `gov-classification-3`，真实翻译沿用关闭的推理开关。下方请求节省来自不含翻译的原回放，不包含翻译调用与费用。

## 适合本项目的用法

Jev 根据给定资料和问题返回有限类别、分数或真假概率，适合高频的小判断。项目里优先承担资料分类、片段用途多标签和候选原文支持核验；DeepSeek 继续负责生成、提取和复杂推理。固定字段、权限、编号和正式发布条件由程序检查。

官方依据：Vercel 的 [Jev 应用场景](https://vercel.com/i/jev-use-cases)列出资料分类、路由、回答核验和共享资料批量判断；[Decision 接口](https://vercel.com/docs/ai-gateway/modalities/decision)说明结构化决策；[Jev 1.14 公告](https://vercel.com/changelog/typesafe-ais-jev-1-14-is-now-available-on-ai-gateway)确认一份 state 可以并行回答多个问题。以上核查于本说明日期。

## 已落地的调整

- 规则版本更新为 `gov-classification-2`。默认合并资料类型 Choice、业务领域 Noul 和各片段用途 Noul，同一份正文只在该请求中传输一次。
- 多片段问题通过数组位置独立关联，明确只按对应片段判断用途，返回结果仍绑定原片段编号。当前标签表下，一个请求最多合并两个片段，共 26 个问题；实际数量还受字节预算限制。
- 同时按原字符窗口、最多 32 个问题及 14,000 UTF-8 请求字节分组。字节计数包含模型、标题、问题和正文，为网关附加字段留出余量；不是模型 token 上限。长标题、中文和 JSON 转义都参与计数。
- 合并单片段请求过大时，尝试原来的资料判断、片段判断两次请求。仍然过大则在联网前报告 `MODEL_INPUT_TOO_LARGE`，原文完整留在待复核包中，需重新分块；不静默截断。
- 继续使用 Jev 返回的 Choice `confidence`；另检查最高两个选项的概率差，低于 0.15 时记录 `DOCUMENT_AMBIGUOUS`。用途同时选择“其他”和明确用途时记录 `PURPOSE_CONFLICT`。这些结果进入复核区。
- 汇总新增请求策略、分开处理的请求基准和请求减少数量；调用记录新增问题数和输入字节数。失败运行不报告请求减少收益。现有原文、定位、指纹、机器候选状态和发布复核继续保留。

配置在 `config/preparation/classification.json`。设置 `batch_segment_questions: false` 可使用原来的分开请求策略，大小限制和复核规则仍生效。0.8 置信度阈值、0.8/0.2 概率阈值和新增 0.15 差值都只是初始工程参数，需要独立中文标注集校准。

## 验证与效果边界

离线接口回放中，9 份单片段样例的分类请求从 18 次减少到 9 次；加上原文支持冒烟检查和倒序选项检查，网关测试套件从 28 次减少到 19 次。五片段的独立用途回放从原来 6 次请求变成 3 次，保留逐片段用途标签、分流和全部原文。请求次数减少不代表准确率、费用或实际延迟已经改善。

可执行以下不联网检查：

```powershell
.\.venv\Scripts\python.exe scripts/verify_classification.py
.\.venv\Scripts\python.exe -m pytest -q
```

本轮完整回归 **399 项通过**，有 3 条既有依赖警告，见 [回归记录](../../evidence/jev-optimization/regression.xml)。[正序及倒序接口回放](../../evidence/jev-classification/contract-replay-b5a415ce0e0e4862bef3c37f60a74101.json)均为 9 次分类调用，全部原文保留；这份回放没有发出 HTTP 请求。

本轮没有调用付费模型。此前网关实测返回 `FREE_TIER_MODEL_RESTRICTED`，详见 [Vercel 接入记录](Vercel-Jev接入与实测.md)。真实中文准确率、概率校准、费用与端到端延迟仍待权限恢复后测量，尤其需要比较合并前后以及窗口细分后的错误和待复核比例。

Jev 1.14 已发布，新增图片输入和实验性长上下文；本轮保持项目原有固定版本 `jev-1.13.0`。未来可用扫描件对照现有 OCR 路线测试 1.14，但需同步适配器、响应合同和固定样例验证，不能只修改一个模型字符串。图片能力不等于直接支持 PDF，也不能据发布说明推断中文精度。

现有知识维护引擎已对候选执行原文支持 Noul 核验，继续作为复核信号；本轮没有扩大到新 Agent 路由或改变正式知识发布条件。后续最有价值的扩展是对“用户问题＋召回片段”和“候选结论＋引用原文”做小批量相关性与支持判断，先用人工标签验证收益，再接入主查询链路。
