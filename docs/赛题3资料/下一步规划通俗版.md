下一步先做出一个能连续演示的小系统：把资料放进去，系统整理出办事条件和材料关系，回答时展示依据；资料更新后，能指出哪些规则和答案需要修改。具体政务事项暂不定，先用模拟资料把流程走通，随后换成真实资料验证。

## 一 现在到哪一步了

目前平台能运行，工具调用和技能加载已测试，文本、表格、图片文字也能提取，能按问题找到相关片段。数据登记格式、本体种子和评测模板已经准备好了。

接下来要把这些基础接成一条业务流程。系统目前还没有真正自动整理知识关系、结合多份资料判断、处理规则变化，也没有证明能为实际办事节省多少时间。

## 二 先理解几个词

| 名称 | 通俗理解 | 我们要做的事 |
| --- | --- | --- |
| Nexent | 智能体运行的平台 | 在里面实际完成提问、调用工具和显示结果 |
| MCP | 智能体调用工具的接口 | 让它调用读资料、找依据、查关系和检查变化的工具 |
| Skill | 可重复使用的办事步骤说明 | 把资料整理、问题判断、知识更新分别做成可复用流程 |
| 本体 | 知识的分类和关系规则 | 规定哪些是事项、材料、条件，以及它们怎样关联 |
| 知识图谱 | 按上述规则整理出的具体知识 | 例如某事项需要申请表，某种情况还需要另一份证明 |
| 多跳推理 | 顺着几步关系、结合多份资料判断 | 先确认适用条件，再查材料要求，再检查材料的具体要求 |

## 三 下一步按这个顺序做

下面是计划中的工作，完成标准都需要实际操作验证。

### 第一步 在 Nexent 里真正使用资料

把已经准备好的文本、表格和图片解析结果，接到一个独立的资料工具中，再让 Nexent 的智能体通过 MCP 和 Skill 调用它。先用现有三份模拟资料，之后通过资料清单更换输入。

**要交付：** 一个资料查询工具、一个能调用它的智能体、一份资料整理 Skill，以及实际运行记录。

**怎样算完成：** 在 Nexent 页面提问后，能找到资料内容，并打开对应的原文位置；输入没有依据的问题时，明确说资料不足。每份资料都能看到编号、来源、文件类型和处理状态。

这一阶段使用独立的数据目录和配置，保留现有空库验收环境。已有解析脚本可以继续复用，不需要重新搭一套平台。

### 第二步 让系统先整理 人再确认

先给系统少量分类示例，让它从资料里提出“事项、材料、适用条件”等候选内容，以及可能需要新增的类别和关系。每条候选都附上原文，人工选择接受、修改或驳回。

**要交付：** 候选整理工具、人工复核页面、复核后的知识版本。

**怎样算完成：** 模型提出的内容和人工确认的内容能分清；没有出处的关系不能进入正式版本；遇到新类别或新关系时，系统能提出建议供人确认。

同时记录人用了多少分钟、改了多少条。比赛里的“低资源”要落到少量标注和较少人工投入上，这些记录将用于后面的效果比较。

### 第三步 回答问题时展示完整依据

让智能体同时使用原文检索和知识关系，完成一个确实需要多份资料的问题。它要展示判断步骤，以及每一步的出处。

演练问题可以是：“选择分支甲，需要哪些材料，申请表有什么要求？”系统先查适用分支，再查材料表，最后结合图片说明确认申请表的要求。条件不清楚或资料有冲突时，转给人工复核。

**要交付：** 问题判断 Skill、关系查询工具、答案和证据展示页面。

**怎样算完成：** 能看出为什么需要某项材料，每一步都有原文支持。至少有一条任务必须结合多份资料和关系才能得出结论。

把结果保存为交接记录，工作人员打开后能看到同一个问题、同一份依据、同一个版本，并确认仍需核对的内容。

### 第四步 展示资料变化怎样影响答案

准备新旧两版资料，让系统找出变化，列出受影响的知识关系和已有任务，经人工确认后发布新版。旧任务仍保留当时使用的版本和答案。

要同时演示两类变化：一类是某项材料要求改变；另一类是出现新的知识类别或关系。例如在演练资料中加入“电子证明可以替代纸质材料”，系统应提出新的类别或替代关系，而不只是增加一段文字。

**要交付：** 变化检查工具、知识更新 Skill、新旧版本对比和受影响任务列表。

**怎样算完成：** 能说明改了什么、哪些答案受影响、为什么受影响，以及旧答案当时依据什么。只显示文件内容变化，还没有完成这一步。

构造的变化标为模拟演练。后续使用真实资料时，另外核对实际版本变化和对应规范条款。

### 第五步 换成真实资料验证

当上述流程稳定后，选一个有足够官方资料的政务事项。优先选择有条件分支、需要跨资料判断、包含表格或图文，并能找到规范依据的场景。

通过资料清单替换输入，复核来源、日期、适用地区和规则，再重新运行。此时把知识与对应政策或标准条款连接起来，让人能检查它依据哪条规定。

**要交付：** 真实来源包、规则与条款对应表、人工标准答案、真实业务演示。

**怎样算完成：** 系统的关键说法能回到官方原文；换资料时需要改哪些配置、哪些规则都有记录；不把模拟数据结果当作真实业务效果。

### 第六步 用比较结果说明价值和创新

准备人工核对过的问题，比较基础方法和改进方法。先做三组最有用的比较：

| 想证明什么 | 怎么比较 | 记录什么 |
| --- | --- | --- |
| 人整理知识更省力 | 普通候选复核，对比加入分类约束和重点复核排序 | 相同时间内确认正确内容的数量、错误数和人工分钟数 |
| 跨资料回答更可靠 | 普通文档检索，对比文档加关系和条件检查 | 答案是否正确、出处是否支持结论、资料不足时是否乱答 |
| 更新知识更省时 | 全部重新处理，对比只处理受影响部分 | 更新时间、遗漏变化、误判影响，以及旧结果能否重放 |

使用相同资料、问题和模型进行比较。用于最后检查的问题，不拿来反复调提示词。先记录实际结果，再决定能写出什么创新结论。

## 五 这一轮先做的四件事

本轮先完成第一步，让大家看到基础工具真正进入 Nexent。排期按实际投入调整，完成后再推进后续步骤。

1. 确定资料查询工具的输入和返回内容：问题、相关片段、原文位置、资料版本、失败原因。
2. 把已有解析和向量检索接成独立 MCP 工具，用三份模拟资料运行。
3. 在 Nexent 配置资料查询 Agent 和 Skill，页面展示相关内容及原文位置。
4. 检查四种情况：正常查询、没有依据、资料处理失败、工具暂时不可用。保存实际过程，确认失败时不会显示成功。

先用少量问题把流程检查清楚，后续再建立独立验收题库。具体题目数量属于项目安排，不是官方规定。

## 六 最后演示给评委看什么

完整演示按以下顺序进行：

1. 导入文本、表格和图文资料，查看来源及处理结果。
2. 系统提出知识分类和关系候选，人工确认其中一部分。
3. 提一个需要跨资料判断的问题，展示步骤和原文依据。
4. 工作人员查看同一版本的交接并进行人工确认。
5. 加入新版资料，展示关系变化、受影响答案和旧版回放。
6. 导出 Agent 与 Skills，在独立环境复现，再展示实际效果比较。

最终应留下可运行工程、实际导出的配置和 Skills、资料说明、比较结果、问答截图、演示录屏及开发设计文档。

## 七 创新重点怎样说

重点放在两个可以验证的问题：**少量人工怎样更快整理出可靠知识，以及知识变化后怎样找到受影响的答案。**

分类约束、复核排序、变化传播和答案回放，要有具体实现和比较结果。平台接入、OCR、向量检索以及增加智能体数量，可以说明工程能力；创新结论要由后续实验支撑。
