## 日常启动

在 PowerShell 中执行：

```powershell
Set-Location 'G:\桌面\codex项目\华为ICT\huaweiICT'
$env:PATH = 'C:\Program Files\Docker\Docker\resources\bin;' + $env:PATH
Start-Process 'C:\Program Files\Docker\Docker\Docker Desktop.exe' -WindowStyle Hidden
# 等待 Docker Linux 引擎启动，再执行后续检查。
docker info --format '{{.ServerVersion}}'
powershell -ExecutionPolicy Bypass -File scripts\configure_ollama.ps1 -EnableIntegratedGpu
.\.venv\Scripts\python.exe scripts\runtime_sandbox.py
.\.venv\Scripts\python.exe scripts\check_native_ready.py
```

所有就绪项为 `true` 后，访问 `http://127.0.0.1:3000`。

`configure_ollama.ps1` 会重启本机 Ollama 服务。它使用 localhost、单模型、单并发、上下文 8192、温度 0.1 和输出上限 1024；保留已有模型和账号信息。验收期间不要运行其他模型或另开 Agent 会话。

开发、群众、工作人员和测试管理员使用初始化脚本创建的独立账号。其凭据保存在本机私有 `.runtime/accounts.json`，该目录已受 Windows ACL 保护并被 Git 忽略。个人注册页面与这些测试账号分开使用。

## 本机适配

- Git 位于 `E:\Git`；相关入口现在按 `git.exe` 的实际安装位置查找 Git Bash。
- QQ 占用 `127.0.0.1:9210`。本机 `vendor/nexent/deploy/docker/compose/docker-compose.yml` 的 Elasticsearch 宿主机端口改为 `19210`，`vendor/nexent/deploy/common/common.sh` 的预检查也同步为 `19210`。容器内部仍使用 `nexent-elasticsearch:9200`。
- 端口检查只识别监听连接，避免访问远端 3000 端口被误判为本地网页端口冲突。
- 本地 SSE 验证明确绕过系统代理。系统代理不会再把 localhost 请求转成 502。
- MCP 构建支持 `GOV_MCP_PYTHON_IMAGE` 环境变量，默认仍为官方 `python:3.11-slim`。本机最终成功使用官方镜像；若构建阶段 Docker Hub 授权请求超时，可先 `docker pull python:3.11-slim` 再构建。
- 本机成功部署使用 `-RegistryProfile general`。MinIO 源码构建产物已配置到两个镜像源中。

`vendor/`、虚拟环境和 `.runtime/` 均不随共享仓库提交；因此换机器需要重新准备这些环境。本机端口覆盖只属于本地部署副本，重新下载固定上游源码后需重新应用。
