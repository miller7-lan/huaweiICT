### 干净环境复现命令（陈子炫）

```powershell
git clone https://github.com/miller7-lan/huaweiICT.git
cd huaweiICT
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
.\.venv\Scripts\python.exe scripts\build_competition_package.py
.\.venv\Scripts\python.exe scripts\build_competition_package.py --verify-only
```

把 `artifacts\competition-20261021\ict-topic3-public-engineering-20261021.zip` 解压到一个**新目录**，然后在该目录执行。`$py` 换成克隆目录下 `.venv\Scripts\python.exe` 的绝对路径；`PYTHONPATH` 用来确保测试跑的是解压出来的源码：

```powershell
$py = "D:\work\huaweiICT\.venv\Scripts\python.exe"
$env:PYTHONPATH = "$PWD\src;$PWD"
& $py scripts\build_competition_package.py
& $py -m pytest -q tests
```

10月30日核查时的结果是：包内重建通过；测试354 passed、15 skipped，跳过的15项依赖私有原件，属于预期。之后按[复现与交付说明](复现与交付说明-2026-10-21.md)用 `scripts\deploy.ps1` 部署 Nexent，再用 Nexent 界面导入 `artifacts/competition-20261021/nexent-ontology-crossdoc-native-export.zip` 和 `artifacts/competition-20261022/nexent-henan-multimodal-native-export.zip`。没有模型 API 和本项目 MCP 服务时，工具连接失败、无法对话都属预期，做到"配置导入并截图"即可；原生运行由你补跑。部署需要拉取 Docker 镜像，如果网络只允许访问 GitHub，到这一步停下并写进回执。

## GitHub 协作方式

- 两位队员 fork 仓库，在自己的分支上修改，再向 `main` 发 PR；你审阅后合并。不熟悉 PR 的话，可以把文件发给你代为提交。
- 每个 PR 只改自己负责的目录：程千城改 `evaluation/independent-20261030/`、`evaluation/lowresource-20261030/records-程千城.md` 和自己的复核文档；陈子炫改 `docs/competition/` 下的回执、交互方案、截图，以及 `evaluation/independent-20261030/screening.md`。源码 `src/`、`scripts/` 和 Skill 由你修改。
- 生成的 ZIP、`.runtime`、`.venv`、模板原件和参考答案不要提交。
- 遇到问题开 GitHub Issue，写清命令、报错原文和截图，方便你远程定位。
