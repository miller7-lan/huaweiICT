## 六十秒演示分镜

下表为拟录制视频的时长分配，不是当前系统响应实测。先录制完整实机操作，再制作展示版本；如果删去等待或使用倍速，在视频与口播中明确标注。

| 片段 | 时长 | 画面 | 口播要点 |
| --- | --- | --- | --- |
| 说明场景 | 0至8秒 | 工程预览、事项名称、资料版本 | 这次演示使用一个候选事项和模拟材料状态 |
| 查到依据 | 8至22秒 | 群众问题、实际原文、来源链接与定位 | 建议能够回到具体来源，未核定规则保留提示 |
| 保存交接 | 22至34秒 | 两项材料声明、交接号和固定版本 | 问题、声明与引用共同保存 |
| 工作人员核验 | 34至50秒 | 同一交接号、缺项、未知项和待复核项 | 接收方继续检查同一份上下文 |
| 查看确认 | 50至60秒 | 结果指纹对应的演示确认、完成状态 | 确认机制已验证，正式业务意见需要实际复核 |

录制前使用独立测试账号，检查服务就绪、模型预热、当前任务和最新交接；不要拍到密码、令牌、个人邮箱或未授权资料。群众与工作人员各自登录，切换时保留角色标识。录制后登记代码提交、数据版本、拍摄日期、原始文件与剪辑说明。

现场方案A为本地演示视频，方案B为两张真实截图配合口播；若正式规则要求实时操作，则使用经过排练的实时流程并保留视频备份。实时演示的等待时间必须另行实测，不能直接套用60秒视频预算。服务异常时一句话说明并切换备份，不在台上调试容器。

## 答辩备问

| 评委可能问 | 当前可据实回答 | 后续最有说服力的补证 |
| --- | --- | --- |
| 为什么使用多个Agent | 按已认证角色分工，并通过工具和持久化交接连续传递依据；效果优势仍待对照 | 同模型同工具能力的单Agent对照 |
| 你们自研了哪些部分 | 实现MCP业务工具、权限、固定版本交接、预览工作台和审计；使用现有Nexent和Qwen3 | 模块代码、接口契约和可复现配置 |
| 当前RAG准确率多少 | 尚无独立业务准确率，当前检索采用字符片段匹配 | 人工复核任务、引用支持率与失败样例 |
| 小数据是否能说明价值 | 已证明流程可以贯通；扩大前先补齐一个事项的规则与条件 | 规则覆盖表和分组任务集 |
| 132项全通过意味着什么 | 自动回归通过，覆盖工程行为；不是132个真实业务案例 | 测试范围说明和独立业务评测 |
| 有没有自动审批 | 当前为材料状态预核验和演示确认，业务意见需相应工作人员判断 | 实际复核记录及明确职责边界 |
| 规则变化怎么处理 | 当前任务固定快照，后续计划真实新旧资料差异和人工复核 | 两版实际资料及历史任务回查 |
| 会不会把别区规则混进来 | 当前按范围筛选并保存分类；新增地区需单独核定 | 跨地区负向任务和引用检查 |
| 如何防止群众冒充工作人员 | 服务端读取真实登录身份，工具层再次检查；页面自称身份无授权效果 | 既有越权接口证据及独立复测 |
| 和现有政务问答的差别 | 我们重点设计跨角色交接、版本和可追溯结果；尚未做具体竞品实测 | 同任务功能对照，不虚构竞品缺点 |
| 用了哪些华为技术 | 已验证基于Nexent的原生调用；当前没有华为云或昇腾部署证据 | 按正式技术要求补真实适配记录 |
| 节省了多少时间和成本 | 当前尚未完成业务收益测量，后续记录复核时间、重复询问与资源消耗 | 同条件测试与真实参与者观察 |

## 素材维护规则

每项结果保存结论、证据路径、取得日期、适用范围、责任人和复核人。数据或代码更新后，重新检查截图、讲稿和结果表是否仍对应同一版本。保留失败和修复过程，避免仅收集成功画面。

本轮包内的验证记录核对文件存在性、引用链接、主要证据数字、讲稿时长及成品布局。它不是新的软件运行验收，不替代后续业务实验。
