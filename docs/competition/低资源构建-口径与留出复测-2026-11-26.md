# 低资源半自动本体构建：口径与留出复测（2026-11-26）

对应初赛评分点“算法创新性、低资源半自动本体构建效率”。本文做两件事：

1. 把“低资源”具体是什么、花多少讲清楚；
2. 报告 11 月 26 日在 6 个**从未用于开发的单元**上复测种子约束方法（B2）的结果。

数字来自[11 月 5 日对照](低资源构建架构对照-2026-11-05.md)和[本次复测证据](../../evidence/lowresource-20261105/architecture-comparison-20261126T072333Z.json)，均为机器侧指标，不含人工分钟。

## 一、“低资源”指什么

| 维度 | 本项目的做法 | 与常见做法的区别 |
| --- | --- | --- |
| 训练数据 | 不训练、不微调，不需要标注数据 | 不需要先标一批三元组再训练抽取模型 |
| 先验知识 | 一份小种子本体：7 类实体、6 类关系 | 不需要完整领域本体或大规模知识图谱 |
| 模型调用 | 每个资料单元 **1 次**调用，温度 0，关闭思考 | 不靠多次采样投票（投票法 B3 的成本约 3 倍，召回反而下降，已淘汰） |
| 质量把关 | 确定性门：引文必须是原文连续片段，数字必须能在引文里找到，重复去掉 | 不再用第二个大模型判对错，门本身不花模型调用 |
| 人的角色 | 只确认候选，确认后才成为新版本，可回退 | 不从零阅读整理 |
| 单元花费 | B2 每单元约 0.73k 输入 + 0.66k 输出 token，约 3 秒；按 deepseek-flash 标价（输入 ¥2、输出 ¥8 每百万 token）约 **¥0.007**，不到 1 分钱 | — |

单元花费由本次复测折算：B2 一轮 6 个单元的输入、输出 token 与耗时，除以 6。

## 二、方法在做什么

种子本体约束（B2）是在“单元目标 + 逐字引文”（B1）的基础上，再给模型三条约束：

- 只用种子里的实体类型和关系名；
- 一条候选只写一个事实；
- 数值和单位照原文写，不补“工作日 / 自然日”这类原文没写的类型。

候选先过确定性门，再交给人确认。效果体现在两处：候选能不能**直接对上本体结构**（省掉人工归一），以及**长单元是否稳定**。

## 三、结果

### 3.1 开发单元（11 月 5 日，U1—U6，每种方法 3 轮）

| 指标 | B1 原方法 | B2 种子约束 |
| --- | --- | --- |
| 能直接对上种子关系的比例 | 11.9% | **43.5%** |
| 机器可用关系名比例 | 17.8% | **52.4%** |
| 关键要素召回 | 91.7% | **97.0%** |
| 分支数值绑定（9 项） | 7/9 | **9/9** |
| 3 轮稳定性（Jaccard） | 0.887 | **0.941** |

局限：U4—U6 在开发中使用过，结果可能偏乐观。

### 3.2 留出复测（11 月 26 日，H1—H6，每种方法 3 轮，36 次调用，0 错误）

**单元怎么选。** 用 `scripts/select_holdout_units.py` 按固定种子 `20261126-holdout` 机械抽取，选定后才开始跑：

- 分层抽取：河南户籍规范条文 3 个，2018 年通知、2024 年措施、收费目录各 1 个；
- 排除 U1—U6 的全部定位，长度限定在 80—800 字；
- 每个单元的目标按关键词规则由原文自动指定，不看输出、不按结果调整。

单元清单见 [units-holdout.json](../../evaluation/lowresource-20261126/units-holdout.json)。模型与 11 月 5 日相同，为 deepseek-flash。

| 指标 | B1 原方法 | B2 种子约束 |
| --- | --- | --- |
| 能直接对上种子关系的比例 | 9.2% | **50.7%** |
| 机器可用关系名比例 | 17.2% | **65.5%** |
| 3 轮稳定性（Jaccard） | 0.945 | **1.000** |
| 平均引文长度（字） | 36.0 | **17.4** |
| 引文逐字一致率 | 100% | 97.9% |
| 门通过率 | 82.9% | 75.5% |
| 关键要素召回（4 个有要素的单元，共 8 个要素） | 95.8% | 87.5% |
| 每轮通过门的候选数 | 29.0 | 47.3 |
| 每轮输入 / 输出 token | 3,084 / 2,628 | 4,356 / 3,967 |
| 每轮模型耗时 | 14.1 秒 | 19.3 秒 |

**结论。**

1. **种子约束的主要好处在新单元上复现了。** 能直接对上本体结构的候选从约 1/10 提高到约 1/2，3 轮结果完全一致，引文缩短一半，人工核对引文更快。
2. **召回没有复现开发单元上的提升。** B2 在 H4 上 3 轮都漏了 2 个要素中的 1 个，宏平均因此从 95.8% 降到 87.5%。新单元可机械抽取的要素很少（6 个单元共 8 个，两个单元为 0），这个指标的分母小，波动大。
3. **代价**：候选更多（每轮 47 条对 29 条），token 约多 40%；门通过率略低，被拦下的主要是数字没出现在引文里的候选。
4. 留出单元没有开发期确认过的分支数值事实，**绑定项本次不计**。

## 五、材料可以怎么写

| 可以写 | 不能写 |
| --- | --- |
| 不训练、不标注，每单元 1 次调用，约 3 秒、不到 1 分钱 | “零成本”“完全自动” |
| 种子约束使能直接入本体的候选从约 1/10 提高到约 1/2，开发单元与留出单元两次结果一致 | 把要素召回的提升说成在留出单元上也成立 |
| 留出单元上 3 轮结果完全一致、引文缩短一半 | 留出复测“全面优于”原方法 |
| 人工复核比纯人工整理少约 88% 时间（单次小样本、本人填报） | “效率提升 8 倍”“普遍节省 88%” |
