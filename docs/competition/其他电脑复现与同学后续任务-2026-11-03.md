## 三 在另一台Windows电脑取得同一版本工程

当前步骤按Windows PowerShell编写。其他系统先调整环境脚本，不能把Windows说明直接称作跨系统已复现。准备Git、Python 3.12、Docker Desktop和WSL2；项目声明支持Python 3.11及以上，但默认准备脚本选择3.12。

### 1 建立独立目录并克隆

选择自己有写权限的新父目录，在该目录打开PowerShell。不要覆盖已有工程。

```powershell
git clone --branch codex/sync-m1-m2 --single-branch https://github.com/miller7-lan/huaweiICT.git ICT-reproduce
Set-Location -LiteralPath './ICT-reproduce'
git rev-parse HEAD
git status --short
git switch -c codex/reproduce-henan-20261103
```

记录克隆时的完整提交号。本文随本次提交一起出现，不在正文预写一个尚未产生的提交号。后续队长或同学更新分支时，不应悄悄改变已经开始验收的版本；如需更新，另记新提交和原因。

如果用ZIP取得源码，先对照队长提供的SHA-256：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '<代码ZIP的完整路径>'
```

`<…>`表示需要替换的实际路径，不要把尖括号直接执行。11月3日首份完整代码ZIP的SHA-256为：

```text
23893e759c7126e7bf85abb853952e155ac1064f618d55621d0b0e1064f3cac1
```

该散列仅对应那一份507文件附件；重新生成后的ZIP以新的校验文件为准。若使用Git，不需要为了继续开发先生成这份历史ZIP。

### 2 检查原始平台ZIP

这两份二进制文件由队长单独提供，**不保证克隆后出现在Git目录中**。

| 文件 | SHA-256 |
| --- | --- |
| `nexent-ontology-crossdoc-native-export.zip` | `0a7377f1aeef2296338e77bc093466eb70c59cd4a1b73abf015b39816ae89122` |
| `nexent-henan-multimodal-native-export.zip` | `9bc19582710dd044921de2f72e8ef0ac56415d4369a39f304d9d9f58eab41808` |

河南优先使用第二份；南京包保留备查。可用上面的`Get-FileHash`逐一核对。散列不同先保留文件和实际散列，问清版本，不改预期值绕过检查。

### 3 安装项目依赖和固定Nexent源码

下面命令会下载源码/依赖并创建新机器自己的`.venv`和私有运行目录；不是只读检查。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
.\.venv\Scripts\python.exe -m pip install -r requirements-knowledge.lock
git -C vendor/nexent rev-parse HEAD
```

预期Nexent为v2.7.0，提交：

```text
519b9b17c7f4cbc623256ac318ea96a20f33772e
```

安装失败就先记录当前步骤与脱敏错误。网络访问使用机器已有代理设置，保留HTTPS证书校验；不要用关闭证书校验解决下载问题。本地服务保留直连/NO_PROXY，不把个人代理地址写入源码。

### 4 启动Docker并准备平台

先由操作人打开Docker Desktop，确认Linux引擎可用：

```powershell
docker version
docker info --format '{{.OSType}}'
```

应能看到服务端信息，系统类型为`linux`。只有客户端版本或提示找不到管道，不算Docker准备好。

然后在新工程目录执行基础部署：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy.ps1
```

该命令会启动本机容器和MCP基础服务，配置运行环境；本轮**不要附加`-ProvisionAccounts`或`-RequireLocalModels`**。这些开关走历史双Qwen前提，不是河南云端链的通用初始化步骤。MinIO镜像构建、WSL或Docker错误按实际情况处理，不为绕过健康检查修改脚本的成功条件。

部署后检查：

```powershell
.\.venv\Scripts\python.exe scripts/check_native_ready.py
```

记录每个布尔项。config/runtime/ui为基础平台；这里的mcp是8765基础服务，**全部为真也不代表河南专用业务MCP已接好**。本机界面入口通常是`http://127.0.0.1:3000`，配置与运行服务分别使用5010、5014；实际端口变化须记录。

账号通过新平台自己的合法初始化/注册流程建立，使用新租户。本项目`initialize_accounts.ps1`仍包含历史双Qwen前提，不能直接当作这条云端复现的下一条命令；遇到平台无管理员或无法注册时，将该项交实现负责人处理，不复制原机器`.runtime/accounts.json`。

**本阶段完成标准：**记录源码提交、系统/Python/Docker版本、固定平台提交、健康检查结果，并能登录新平台。它只说明环境准备完成，尚未开始真实业务复现。

## 六 只跑一次关键闭环 然后回退

由实现负责人核对新活动配置与授权后，再由另一台机器的实际操作人执行。没有新活动适配以前，**不要直接运行历史`--live`或`--confirmed`入口**。取得可执行入口时，在报告中记录实际命令、实现提交和新活动编号，不能只写“按指南运行”。

### 正向演示要观察什么

1. 使用河南固定历史归档的虚构情境，不输入真实身份证号或个人材料。
2. 主控读取Skill，开任务取得真实任务ID，依次委派检索、核验，读取状态并完成。
3. 同一任务ID贯穿调用；角色和工具调用顺序正确，最终内容与持久回执一致。
4. 三份真实资料共同进入四节点依赖计划，每步有来源与定位；表格是规范依据定位，不把文号当金额；扫描条款不冒充收费依据。
5. 保持“历史归档解释”的范围，现行适用性未知、实际应缴额未知、当前办理时限未知；不因演示成功改变正式业务状态。

### 停止和清理要观察什么

- 在新活动的隔离检查中，现行业务提问、其他地区/分支、关键来源缺失或暂停应适当停止。先做不调用模型的相关工具检查；只有需要时才另约定模型验证，不自动增加多轮调用。
- 保留第一次失败和实际错误码；发生模型、工具、版本或来源错误立即停止，不改提示后反复跑同一活动挑最好结果。
- 成功或失败后都检查：活动已结束、本体head回到事先记录的baseline、相关执行关系不再激活、临时辅助进程退出、草稿恢复禁用、业务暂停仍在、未产生正式发布。
- 若停止、回退或禁用状态无法确认，结果写“清理未确认/未通过”，联系实现负责人处理；不要删除数据掩盖问题，也不要清空接收方其他项目的容器或卷。

历史记录的“15项检查、7次模型启动、13.234秒”只用于说明原实验，不能预填本轮成绩。实际调用数、耗时和费用如实填写，费用取不到就写未知。
