## 一、项目概述

### 1. 场景与问题

本项目选择政务行业，以居民身份证换领公开资料为试点，研究如何把散落的指南、问答、政策解读、表格和扫描附件转为有来源、可复核、可演化的资产与决策依据。原型服务资料维护者、咨询用户和工作人员：维护者登记与复核来源，查询链路提供依据及未知项，工作人员通过固定知识版本复核交接内容。

资料中的地区、事项分支、对象、时间单位和例外会影响结论。网页发布日期不等于施行日期；从一份资料抽出的描述也不等于现行办事承诺。因此，本项目将精确引用、人工确认、版本与暂停状态贯穿抽取和推理。资料不全或适用性未核定时返回未知、待核或暂停，保留后续人工处理入口。

### 2. 目标与实际阶段

目标是基于 Nexent 的 MCP 与 Skills，形成“资产识别与登记→本体候选→人工确认与版本管理→检索与推理→逐跳引用→更新复核”的执行体系。当前已验证以下局部能力，尚未完成整套参赛作品的业务验收。

### 3. 可展示主张

本项目当前可以展示：原文约束进入可执行关系；两份资料各提供必要前提的有界多跳；云端子 Agent 从完整原文提取并核验更新候选；来源、版本、暂停或实现变化能够阻断旧结果。尚无证据支持业务准确率、人工成本下降比例、真实办结收益或普遍领先性等结论。

## 二、整体方案

### 1. 模块与职责

| 模块 | 已实现职责 | 关键边界 |
| --- | --- | --- |
| 来源与资产处理 | 固定来源登记、正常采集、原件留存、哈希、修订、正文片段及附件关系 | 访问限制或解析失败必须保留；不将日期观察自动写为施行日期 |
| 本体工作区 | 种子类型与关系、有界候选构建、候选摘要、不可变版本、CAS、审计和回退 | 新结构须人工确认；结构确认不充当专业业务审核 |
| 检索与推理 | 地区、事项和来源绑定；受限关系求值；三值判断与逐跳依赖 | 不跨地区套用参数；缺少来源或事实时不能补猜 |
| Nexent 编排 | CodeAgent 主控、检索/整理/核验子 Agent、Skill 读取和角色工具白名单 | 模型调度与确定性计算分别记录；错误、上限和外部阻断停止 |
| 版本与复核 | 候选待审、版本头核对、最终返回前复查、暂停与回退 | 待审资料不得进入正式办事承诺；历史任务的依据可追溯 |
| 运行与证据 | 心跳、恢复任务、独立来源观察、预算预留、SSE 和回执摘要 | 心跳存活不等于业务可用；一次原生运行可能包含多次模型调用 |

本机 Nexent 配置端为 `127.0.0.1:5010`，运行端为 `127.0.0.1:5014`；项目为不同实验提供独立 MCP 和私有运行目录。当前通用工作台配置的推理与表单核验开关仍关闭，`connections.json` 的模拟工作流与公开资料隔离预览不能混用。参数来源见[配置文件](../../config/decision/connections.json)。

### 2. 两类执行流

查询流由主控读取 Skill、创建受限任务，检索子 Agent 取得绑定来源，核验子 Agent 校验推理及引文；主控读取持久状态，通过完成门后原样返回最终工具结果。模型负责受控编排，南京三跳的数值、依赖与来源校验由确定性执行器完成，未把它表述为模型独立业务判断。

更新流由持久任务发现资料到达，主控读取阶段状态，整理子 Agent 顺序读取旧、新完整视图并提交结构化差异；核验子 Agent 独立读取两份证据及候选后提交核验；主控仅在完成门通过时生成最终回执。成功结果停在 `pending_review`，不继承旧批准、不发布知识。

两类流已各有真实执行证据，当前尚未证明全部资产、本体、查询、更新和前端在同一演示任务中贯通。参赛最终演示需保留这一整合验收项。

### 3. 数据与权限约束

公开资料按 `data_class=public` 管理；模拟资料明确标为 synthetic，不能用于证明真实业务效果。演示使用固定虚构输入，不采集居民证件号或真实个人回答。云端通过用户已有环境变量或系统代理连接，保留 HTTPS 证书验证；本机和 Docker 服务保持本地直连，不在业务源码写死代理地址。公开材料只保留必要引文、虚构输入、摘要与哈希，令牌、凭据、完整运行库留在私有目录。

## 三、图谱本体设计与演化

### 1. 种子结构

[本体种子](../../config/preparation/ontology.seed.json)定义 `Matter`、`Condition`、`Material`、`Department`、`Procedure`、`StandardClause`、`Asset` 七类对象及 `requires`、`applies_when`、`handled_by`、`has_step`、`aligned_to`、`supported_by` 六类关系。种子为工程设计，`is_official_standard=false`，不能宣称等同政务行业标准。

业务关系要求绑定来源片段；地区合并需显式复核；条件结果为 `true/false/unknown`；历史版本不可变；发布前须人工审核。该结构用于承载地区、事项、条件、材料、规范及资产之间的连接，不以种子存在证明所有关系已有真实可执行实例。

### 2. 半自动构建方法

当前采取少量人工语法种子引导的有界抽取。北京样例识别“符合以下条件可在网上办理”的标题及紧邻完整续段，从原文捕获年龄、办证时间、照片时间和指纹等条件，生成 `ServiceChannel` 新类型、`Matter → available_via → ServiceChannel` 关系及候选实例。数值来自原文，独立改数文本检查验证执行器没有查表返回预写答案。

人工确认对象包含候选摘要、预期版本头、来源修订及引用，确认后才在隔离库登记为可执行结构。执行时读取已确认版本中的类型、关系与条件，回退到未登记结构的种子后重新返回 `UNSUPPORTED_RELATION`。本次确实完成激活、六场景及回退，见[候选](../../evidence/ontology-evolution-20261019/candidate.json)、[演示](../../evidence/ontology-evolution-20261019/demonstration-20261019T113614729977Z.json)和[回退](../../evidence/ontology-evolution-20261019/rollback-result.json)。

这是一类受限抽取和执行方法，没有使用 LLM 自动发现任意关系，也未测量相对人工标注的专家分钟、正确采纳率或成本下降。低资源效率仍需相同来源、相同复核标准的人工对照。

### 3. 南京统一本体候选

南京新增候选类型 `IntervalComparison` 和 `Matter → compares_coverage → IntervalComparison`，关系内保存带类型、来源和依赖的三步计划。执行器内置的 `WorkingDayDuration` 与 `ThreeValueCoverage` 是标量输出类型，不能计为新本体实体类别。

候选由两份真实原件五段完整正文生成。2026-10-21 获得本次人工结构确认后，实际完成激活、虚构情境推理、来源暂停阻断及回退，结果 `PASS_LOCAL_ONTOLOGY_CROSSDOC`，12/12 项检查通过。已确认版本为 `48f05b634313aec6c18d781681c001b1dc2a08bfaf955055e938cbb667d63755`；最终版本头恢复原基线 `1ca18aa9d0a9e85032b633bb11e0b4dcfe4aef40518c46a1b4c238fe8a7b0933`，查询重新阻断。

具体类型与原始候选见[结构复核说明](../赛题3资料/本体跨文档集成复核-2026-10-20.md)和[候选](../../evidence/ontology-crossdoc-20261020/candidate.json)，当时待审状态按准备日期理解。本地演示模型调用为零；随后单独授权的原生流程实际1次、观察7次模型启动，两个阶段分别保留证据。旧预算保持封闭，新预算1/1已消费。

### 4. 演化与标准对齐

本体结构变化与来源内容变化分开管理：前者改变类型、关系和执行语义，后者产生资料修订及差异候选。河南成功证明新旧原文的提取、核验与待审候选，没有据此证明本体自动升级或旧政策已失效。

当前已有 `StandardClause`、`aligned_to` 和来源版本结构，但尚未完成“真实规范条款—字段或关系—地区与对象—生效范围—例外—人工复核”的正式映射验收。南京两个事项标识的工程映射不是行业标准对齐证明。后续应先完成少量可复核映射，再展示规范变化对受影响查询路径的提示。

## 四、智能体与检索推理

### 1. Nexent MCP / Skill 集成

旧南京原生查询草稿为主控28、检索26、核验27；新增已确认本体链为主控34、检索32、核验33；河南更新为主控31、整理29、核验30。ID属于本机平台实例，跨机器需重新创建并回读绑定。草稿均禁用、未发布，真实运行通过受控接口执行。

Skill 将来源视为不可信数据，限定工具、顺序、输入和错误处理；MCP 再次实施来源、任务、阶段和版本约束。仅凭提示词不会获得发布、任意网络、文件或凭据访问权限。角色分工和实际工具轨迹见[配置证据说明](当前Nexent配置与证据说明-2026-10-21.md)。

### 2. 南京跨文档三跳

固定虚构情境为南京受理、省外户籍、普通换证、非考生加急、旧证未挂失，并明确假定同一受理起点下旧证剩余区间为 22 个工作日。程序不把真实有效期日期换算为工作日。

| 跳 | 必要依据与运算 | 结果用途 |
| --- | --- | --- |
| c1 | 周期问答提取省内 20 工作日及省外增加 5 工作日 | 得到归档原文描述的常规区间 25 工作日 |
| u1，依赖 c1 | 旧证问答限定“未超期”；与 c1 区间取交集 | 得到来源能够支持的有效覆盖区间 |
| j1，依赖 c1、u1 | 比较两区间 | 输出 `cannot_establish_full_cycle_coverage` |

来源数字 20、5 与演示输入 22 分别记录；结论不能改写为实际缺证 3 天、实际领证日期或旧证全部法律效力。覆盖区间足够时仍返回 unknown，不能推为全程实际可用。

两份原文俱全时形成三跳；移除任一文档均为 unknown，见[实际文档移除检查](../../evidence/crossdoc-native-preview-20261019/actual-ablation.json)。2026-10-20 的一次真实 Nexent 运行耗时 13.4401 秒，观察到主控四步、两个子 Agent 各一步，最终 JSON 与数据库答案一致。完整结果、逐跳依据和绑定见[原生答案](../../evidence/crossdoc-native-preview-20261019/native-verified-answer.json)与[轨迹摘要](../../evidence/crossdoc-native-preview-20261019/native-trace-summary.json)。

### 3. 更新与运行保障

河南回放使用两份不同 URL 的真实官方归档。Worker 首次建立旧资料基线，脚本登记新归档后，按自然到期间隔 60.175 秒发现变化，再触发 Nexent 整理与核验。成功轮云端阶段 16.453 秒，观察到八次模型启动，生成一条 pending_review、正式版本零，见[验收结果](../../evidence/agent-autonomy-repair-20261020-a6/result.json)。

原文中的 25 自然日、15 工作日、绿色通道 5 工作日保留单位、对象、期间和渠道，不做异单位相减。精确施行日期未知；模型原始备注中“仅时限条款被取代”未经法律效力核定，继续作为待审备注保全。

10-21 计划任务已实际验证项目主控进程退出后的恢复、去重与暂停保护；独立观察库首次正常采集南京固定公开来源并生成待审修订。尚未测试真实 OS 重启后的恢复，尚未自然观察到真实网站内容变化及变化后云端更新。不能以部署成功填补这些时间和业务证据。

## 六、数据处理

### 1. 登记、提取和定位

每份资产关联稳定标识、原始 URL、原件哈希、来源配置、取得时间、修订、内容类型与片段定位。HTML 保留完整选用段及紧邻限定；CSV 保留记录位置；图片 OCR 保留区域；PDF 保留页序与可见 CropBox 对应页码。OCR 原始文本与检索衍生文本分开，不能静默改正条号或日期后当作原件。

扫描 PDF 路径使用本地 Windows OCR，记录 `confidence_available=false`、`requires_visual_review=true`，文本仍待核对。文本层与 OCR 有明确页数、体积和处理时限；平台或语言不满足时应失败，不能宣称 Linux 或任意 PDF 均可用。附件发现保留父页面、父修订和指纹，不因发现一个附件链接自动继承对未知域名的访问许可。实现范围见[附件发现说明](../知识库PDF附件自动发现说明.md)。

### 2. 语义与质量处理

处理结果保留对象、单位、起止、渠道、例外、地区、事项及日期类型。重复转载与重复原件不计为新增独立依据；缺失正文、动态空壳、未知适用性、冲突与解析失败进入待核或阻断。筛选候选与来源支持评分不能替代业务审核。

当前真实 HTML 和扫描 PDF 已有各自处理证据，但“真实文本＋表格＋图文共同支撑同一条本体与业务答案”仍未完成。OCR 成功、文件上传或模拟 CSV 检索均不能替代多模态统一业务闭环。

### 3. 输出、审计和复现

结果绑定来源原件、引用、输入、程序实现及知识或本体版本，最终返回前复查当前暂停与来源。预算发出前持久预留，失败记录与旧预算保留；不删除状态重开实验。公开回执提供必要的结果与哈希，私有运行目录保留请求、原始事件和原件，用于授权范围内复核。

当前脚本与锁定依赖可供工程准备，尚无另一名队员在干净环境独立导入并复现核心展示的记录。可复现提交包还需整理导出 Agent JSON、Skill、MCP、可共享原件、环境说明及截图，并实际执行一次团队独立复现。
