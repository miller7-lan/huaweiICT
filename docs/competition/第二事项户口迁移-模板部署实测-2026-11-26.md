# 第二个事项：户口迁移，用模板部署到 Nexent 的实测（2026-11-26）

对应初赛评分点“系统交互体验与可复用 Skill 沉淀”。目的是检验 Skill 工作流模板能不能真的复用到一个新事项，并实测从开始到原生跑通要多久。

证据：
- [部署摘要](../../evidence/henan-transfer-20261126/deployment-summary.json)：计时、代码量、候选编号与散列；
- [原生运行](../../evidence/henan-transfer-native-20261126/20261126T073949808623Z.json)：15 项检查。

候选和演示的完整记录含原文，只存在私有目录。

## 一、事项怎么选

- **候选池**：日常需求大、冻结原件里至少有两份独立文件能支撑的事项。不新抓资料，因此不涉及新的爬取和 robots 问题。
- 符合条件的有三个：居住证办理、户口迁移、居民户口簿补领。
- 用固定种子 `20261126-second-matter` 随机抽到 **户口迁移**。

## 二、场景

> 河南省内迁移户口，在哪里办、按什么步骤办？户口迁移证丢了怎么补？补领收不收费、依据是什么？

| 计划节点 | 依赖 | 来源 | 输出 |
| --- | --- | --- | --- |
| 一站式范围 | — | 户籍规范第四十八条 | 省内迁移实行“一站式”，在拟迁入地派出所申请 |
| 不具备一站式时的程序 | 一站式范围 | 第四十九条 | 准予迁入证明 → 户口迁移证 → 落户，共四步，原文照录 |
| 迁移证件补领 | — | 第五十条 | 遗失或超期向签发公安机关补领、换领 |
| 证件收费依据 | 迁移证件补领 | 收费目录第 33—35 行 | 属于“户籍管理证件工本费（限于丢失、补办和过期失效重办）”，列出 4 个依据文号；目录里没有金额，金额记为 null |
| 汇总 | 程序、收费依据 | 以上全部 | 带原文和定位的依据包 |

- 来源是 2 份冻结原件（规范网页、收费目录 Excel），共 16 处定位，构建时不调用模型。
- 不作结论、列为未知的：现行效力、收费金额、当地落户条件、具体派出所能否一站式、各情形所需材料、之后的规范变化。
- 问现行办理、问其他地区、问跨省迁移、带个人信息的，一律停止。

## 三、哪些是复用的，哪些是新写的

| 层 | 本次 |
| --- | --- |
| 平台层（主控与检索、核验两个子 Agent 及参数） | **复用**：模板的 `profile_provisioner` 读一份规格，就生成登记模块（名称、端口、Skill、协议、第一步动作） |
| 编排层（Skill 五步与停止规则） | **复用**：模板渲染；校验 0.09 秒，渲染 0.09 秒 |
| 协议层（主控协议） | **复用**：模板渲染 |
| 工具层（5 个 MCP 工具及其来源门、版本和指纹检查） | **复用**，没有改动；服务分派处只加了 8 行登记新 profile |
| 激活、回退、原生运行检查 | **复用** |
| 执行层（来源适配、候选构建、计划算子） | **新写**：执行层 235 行，来源适配 138 行 |
| 预览、准备脚本、原生运行脚本 | 照河南版改写：131 + 141 + 425 行 |
| 规格与测试 | 规格 57 行，测试 100 行 |

结论：编排、协议、平台、工具四层没有写新代码，填一份规格就能生成。新事项真正要开发的是执行层，约 370 行，这与模板说明里“执行层仍需开发”一致。

## 四、过程与计时

时间为服务器记录的 UTC 时刻。

| 时刻 | 步骤 |
| --- | --- |
| 07:30:21 | 负责人批准场景设计，开始 |
| 07:33:10 | 执行层与来源适配写完，测试通过 |
| 07:33:27 | 规格写完，Skill 渲染完成 |
| 07:34:53 | 在 Windows 上准备好候选：未激活，不调用模型 |
| 07:36:12 | 原生运行脚本写完 |
| 07:37:31 | 负责人确认结构（陈子炫） |
| 07:37:40 | 本地激活演示通过（含越界停止和回退），随即回退 |
| 07:40:25 | Nexent 原生运行通过 |

- 从批准设计到原生跑通共 **10 分 4 秒**，其中等待人工确认结构 79 秒。
- 选事项和设计场景在此之前进行，没有单独计时。
- 原生运行中途停了 3 次，原因都是 10 月后 Windows 上的 Nexent 重装过：旧状态文件里的租户编号过期，旧记录里有 27 个已不存在的智能体编号。处理方法是让运行脚本按项目自己的智能体识别当前租户，跳过不存在的编号，**不改旧文件**。这 3 次都停在模型调用之前，没有占用运行次数。

**口径。** 这是 AI 写代码、负责人确认结构的实际耗时，不能写成“一个人几分钟就能部署新事项”。人工从零开发执行层所需的时间没有测。

## 五、原生运行结果

- 1 次运行，8 次模型启动，Nexent 内执行 17.0 秒，全程 27.8 秒；模型为 deepseek-flash。
- 工具顺序：读 Skill → 打开任务 → 检索（子 Agent）→ 核验（子 Agent）→ 读状态 → 完成，每步恰好一次，没有多余调用。
- **15 项检查全部通过**，包括：
  - 已审结构的 5 个节点按依赖执行；
  - 16 处引文全部与原件逐字节绑定；
  - 没有出现金额；
  - 业务保持暂停、现行效力未知、未发布。
- 运行后回退到基线；其他智能体（包括已发布的问答智能体）的配置签名不变。
