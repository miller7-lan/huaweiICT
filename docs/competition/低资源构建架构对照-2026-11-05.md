# 低资源本体候选构建架构对照（机器侧）

记录日期：2026-11-05（Asia/Shanghai）。运行编号`20261105T074630Z`，证据见[architecture-comparison-20261105T074630Z.json](../../evidence/lowresource-20261105/architecture-comparison-20261105T074630Z.json)，脚本为[compare_construction_methods.py](../../scripts/compare_construction_methods.py)。

这是对6个低资源单元的**机器侧**对照：比较不同候选构建架构的候选质量、稳定性和模型成本。它不测人工主动分钟，不能换算为人工效率提升百分比；6单元方法A/B的真人计时对照仍待两位队友回交，已存证的方法B候选不因本对照替换。

## 隔离方式

- 只读冻结语料`corpus.json`和[units.json](../../evaluation/lowresource-20261030/units.json)，逐单元按定位和`text_sha256`复核原文；不访问Nexent、原生知识库或本体工作区，不改动任何正式状态。
- 云端模型沿用项目已配置的`deepseek-flash`（官方接口、思考关闭），走已有环境变量与系统代理，保留HTTPS证书校验。
- 原始候选只写入私有目录`.runtime/lowresource-architecture/20261105T074630Z/`。两人方法A交回前不公开候选正文；公开证据只含计数、比率和散列。

## 对照的四种架构

| 编号 | 架构 | 调用 |
| --- | --- | --- |
| B0 | 通用三元组抽取：无单元目标、无种子本体、不要求逐字引文 | 每单元1次，温度0 |
| B1 | 现行方法B：单元目标加逐字引文（与11月5日存证候选同一提示词） | 每单元1次，温度0 |
| B2 | 种子本体约束：B1加7类实体、6类关系、一事实一条、数值单位原样且不补日类型、最短引文 | 每单元1次，温度0 |
| B3 | B2三次采样（温度0.7）多数投票，少于两票的候选标为低置信 | 每单元3次 |

四种架构的输出都经过同一组确定性门：引文须为原文连续片段；主体、客体和限定项中的数字须能在引文中找到；完全重复的候选去掉。每种架构完整重复3轮，共108次调用，1次输出格式错误（B3某轮U6的一次采样），按空结果计入分母。4路并发，总墙钟75.6秒。

## 指标口径

- **要素召回**：从原文机械抽取日期、金额、期限、文号、文件标题和分支词（6单元共39个），统计在通过门的候选结构字段（不含引文）中出现的比例，按单元平均。它检查结构化覆盖，不判断语义正确。
- **分支数值绑定**：U4—U6共9项开发期已确认的事实（附录3.3.5、3.4已公开），如“遗失补领、损坏换领对应40元”“15个工作日不属于绿色通道”“30日不补日类型”。同一候选内值与分支对应才算绑定；值对但分支或单位错算误绑。
- **种子关系率 / 机器可用关系名率**：通过门的候选中，关系直接使用种子关系名、或为小写下划线英文名的比例，反映进入本体前还需多少人工归一。
- **稳定性**：3轮之间所召回要素集合的平均两两Jaccard。
- 以下数值均为每轮（6单元合计）的3轮平均。

## 结论与采用

1. 6个单元原文都较短（83—769字），在同一云端模型下，各架构对字面要素的覆盖都较高；引文逐字一致接近100%，未出现分支数值误绑。差别主要在**能否直接成为本体结构**和**长单元的稳定性**。
2. **B2种子本体约束是有效的优化**：与现行方法B相比，可直接使用种子关系的候选由11.9%升至43.5%，机器可用关系名由17.8%升至52.4%；要素召回91.7%→97.0%，绑定7/9→9/9；最长的U4由50%（最低12.5%）稳定到3轮均100%，引文更短。代价是输入tokens多约36%、输出多约34%，通过门的候选多约42%，人工要读的候选更多。
3. **B3多数投票不采用**：按“关系＋要素”签名投票时，温度0.7的三次采样措辞差异大，多数候选被判低置信，召回降至75.6%，成本约为B2的3倍。
4. **B0通用抽取召回不低但不可直接入库**：关系名全部为自由中文，种子关系率0%，每条都要人工改写为本体结构。
5. 后续若采用B2，应在未参与开发的新单元上重新冻结评测；U4—U6在开发中使用过，本次结果可能偏乐观。

## 不能据此声称的内容
