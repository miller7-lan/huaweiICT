# 模型选型对比（V4.0，2026-11-25）

适用：华为 ICT 大赛中国创新赛第三题，河南大学参赛队。本文记录 V4.0 为什么把问答模型从 `deepseek-flash` 换成 `kimi-k3.1-pro`，以及配套的“过渡停止规则”。数字全部来自 [证据汇总](../../evidence/model-comparison-20261125/summary.json)，只含题号与计数，不含题目、参考要点或答复原文。

**定性：** 这是 24 道开发题上的**开发对比**，指标由程序自动计算，**不是正式评测，也不是人工评分**。正式效果以独立出题的 A4 评测和双人盲评为准（见[最后阶段任务](最后阶段任务-独立评测-截图-漏核心分析.md)）。

---

## 一、结论

1. **问答模型改为 `kimi-k3.1-pro`**（阿里云百炼 OpenAI 兼容接口，关闭思考模式，输出上限 2048）。两轮运行中，应答复题全部有答复（16/16，两轮相同），无缺项的完整答复 8 道（两轮相同）；`deepseek-flash` 为 14/16 和 3—4 道。
2. **新增过渡停止规则**（`TRANSITION_NOT_ESTABLISHED`）。两种模型都曾在 X21 上给出答复，而该题按参考应停止。规则作用后，四轮的应停止题均为 8/8。对 210 份历史草稿零调用回放，只有 X21 的 3 份结果改变，无新增误停止。
3. **保留 `deepseek-flash` 作为备用配置**，代码中两套配置并存，可一键切回。
4. **淘汰**：`kimi-k3`、`glm-5.3`（只有思考模式，输出被截断，单次调用 75—175 秒）；`qwen4-max`（不遵守结构化输出约定，且不用给定证据作答）；`deepseek-v4-pro`（公开评测弱于 V4.1-Flash，未运行）。

## 二、与大赛要求的对应

**提交材料。** 官方要求的“Nexent Agent 配置说明”需写明模型、工具、知识库、调用关系、**调试过程**和问答截图。本文是“模型”与“调试过程”两项的依据：候选范围、筛选理由、对比方法、结果与取舍。

**初赛四项评分点（各 25%）：**

| 评分点 | 本次对比的关系 |
| --- | --- |
| 智能体编排与 MCP/Skill 深度集成 | 编排不变：同一 V3.1 流程（检索→作答→核验→修复一次→补查一次，每题最多 3 次调用），只替换写草稿的模型；模型通过统一的 `deepseek.chat` 接口和配置切换，体现模块解耦。过渡规则在脚本流程、原生 MCP 服务端和离线回放三处共用一个函数 |
| 资产激活的业务价值验证 | 主要收益：完整答复增多、误停止消失，直接针对 30 题盲评暴露的短板（跨文档应答复题误停止，见[30题盲评结果](30题盲评结果-2026-11-07.md)） |
| 算法创新性、低资源半自动本体构建效率 | 不涉及本体构建。成本对比见第五节：每题约 ¥0.09，仍属低资源 |
| 系统交互体验与可复用 Skill 沉淀 | 响应时间：中位数约 13 秒（flash 约 4 秒），仍在可交互范围；思考型模型因单次 75—175 秒被淘汰 |

## 三、候选与筛选

| 模型 | 渠道 | 处理 | 理由 |
| --- | --- | --- | --- |
| `deepseek-flash`（DeepSeek-V4.1-Flash） | DeepSeek 官方 | **对照组，跑两轮** | V3.1 的现用模型 |
| `kimi-k3.1-pro` | 百炼 | **跑两轮，选用** | 公开综合指数在开源模型中最高；支持关闭思考 |
| `kimi-k3` | 百炼 | 试跑后中止 | 只有思考模式；首题单次调用 175 秒，输出在 8192 上限被截断 |
| `glm-5.3` | 百炼 | 试跑后中止 | 百炼上只允许思考模式；前两题均被截断，单次 74—77 秒 |
| `qwen4-max` | 百炼 | 结构化输出探测后不运行 | 返回一段对话记录而不是要求的 JSON，并凭自身知识作答、未用给定证据 |
| `deepseek-v4-pro` | DeepSeek 官方 / 百炼 | 不运行 | 公开评测中 V4.1-Flash 在两者都有成绩的 16 项里赢 14 项；Pro 只在闭卷知识题略强，本场景以检索原文为准 |
| `qwen3.8-flash` | 百炼 | 不运行 | 只作低成本备选，未纳入本轮 |

渠道可用性均已实测：每个候选模型各发一次“只回复 OK”的请求，全部 200，用量合计不到 700 token。

## 四、对比方法

| 项 | 设置 |
| --- | --- |
| 题目 | 11 月 14 日的 24 道开发题 X01—X24：比较 8、时间 4、推理 4、应停止 8。题目散列 `9ea19318…`，参考散列 `9aa497c2…` |
| 语料 | 593 单元冻结语料，单元散列 `5e30a8d4…`；Linux 测试机 L1 指纹与原机一致（`same: true`） |
| 流程 | V3.1 代码（核心模块同 `459e459`），规则 `strict`，每题最多 3 次调用，温度 0，关闭思考 |
| 输出上限 | flash 1024（原配置）；kimi 第一轮 1024，X01、X21 因截断改 2048 补跑；kimi 第二轮 2048 |
| 轮次 | 每个模型独立跑两轮，同一天、同一份代码和语料 |
| 不同模型怎么接入 | 百炼模型通过仓库外的包装脚本替换调用函数，流程、检索、核验代码不改；V4.0 已把百炼配置正式加入 `deepseek.py` |

**指标（全部程序自动计算，不调用模型）：**

- 应答复题有答复数：16 道应答复题中没有被停止的数量；
- 答复类型：完整答复（`answer`）、带缺项（`answer_with_gaps`）、部分答复（`partial_answer`）；
- 应停止题停止数：8 道应停止题中停止的数量；
- 必需原文引用率：参考答案列出的来源与定位，被最终答复引用到的比例；
- 参考要点重合率：参考要点与答复文字按字的二元组重合，重合率不低于 0.6 记为覆盖。这是“漏核心”的粗略代理，**不能代替人工判断**。

### 5.4 草稿被核验拦下的主要原因

两种模型被拦下的原因相同，都是数字、数量、文号没有逐字出现在所引原文中（`NUMBER_NOT_QUOTED`、`QUANTITY_NOT_QUOTED`、`DOCUMENT_NUMBER_NOT_QUOTED`）。这是核验规则本身的严格度，不随模型改变。Kimi 被删除的结论更少（6—8 条，flash 为 10 条），说明它更多地按原文写数字。

## 六、过渡停止规则（X21）

**现象。** X21 问的是：新的办理时限对新措施发布前已受理的旧申请是否适用。参考判定为应停止，因为两份归档文件都没有过渡条款。两种模型检索到的证据相同，也都在缺项里写明“缺少过渡条款”或“适用哪一时限缺少依据”，但流程把它当作带缺项的答复放出。四轮中有三轮如此，是否停止随模型输出波动。

**规则。** 问题在问此前事项适用新规还是旧规，而答复自己的缺项写着缺少过渡条款、施行日期或无法判断适用时，结果改为停止，显示固定说明：“归档资料没有写明过渡安排或施行日期，不能判断此前已受理的事项适用新规定还是旧规定，本题停止；请向办理机关确认。”

**通用性。** 判断只用通用措辞，不含题号或具体事项。三批题（X 24、旧 30、新 24）中，满足问题条件的只有 X13、X21 两题。X13 讲临时身份证的办理环节，缺项不涉及过渡，不受影响。

**验证。** 对 210 份历史草稿零调用回放（新 24 题 70 份、旧 30 题 57 份、本次对比 83 份）：只有 X21 的 3 份由答复改为停止，无应答复题受影响。

**风险。** 规则是在看过 X21 之后加的，开发题上的 8/8 含有针对性。它是否有效，要在 A4 独立题上检验。

## 七、局限

1. **开发题。** X 批 24 题此前被多次查看；过渡规则对照 X21 设计。
2. **自动指标。** 没有人工评审；“结论是否正确”“引文是否支撑结论”要靠双人盲评。参考要点重合率只按字面重合，会漏判同义改写，也会误判字面相同而含义不同。
3. **样本小。** 每个模型两轮、每轮 24 题，模型输出有随机性（温度 0 也不保证确定）。
4. **渠道不同。** flash 走 DeepSeek 官方，kimi 走百炼。同一模型在不同渠道的表现可能不同；本轮未做 flash 的百炼渠道对照。
5. **思考型模型只做了最小试跑。** 结论是“延迟和截断使其不适合本流程”，不是“效果更差”。

| 可以写 | 不能写 |
