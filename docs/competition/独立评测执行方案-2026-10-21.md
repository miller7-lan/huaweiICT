## 先导与正式评测规模

| 阶段 | 最小安排 | 目的与停止条件 |
| --- | --- | --- |
| 8题先导，属于开发检查 | 只用已登记的开发样例；2题单文档定位、2题跨文档/跨模态、2题范围/例外、2题缺件/冲突/变化停止；一题一轮，两方案成对。具体题目从现有开发记录挑选，本方案不新增 | 验证原件、输入输出、计时、匿名评阅和报告字段是否齐全；发现阻断先修本次问题，不继续消耗正式留出题，不报告总体业务准确率 |
| 30题正式独立比较 | 参考作者独立形成30条可判定、未用于开发的题；建议20答复、10停止。答复中建议8单文档、8跨文档、4真实多模态；停止中建议4范围/分支、3证据不足、3来源/版本/冲突边界 | 这是覆盖建议，并非官方题数或固定分层标准。最终配比在看输出前冻结；来源不足就调整范围或暂缓，不编造答案填满题数 |
| 低资源构建小对照 | 选6个预先封闭的映射单元，包含类型/关系、完整跨页边界、数值单位/例外、版本变化等；两种方法各有一次实际操作 | 得到本次小样本专家分钟、修改量、正确采纳量；此规模只能描述操作观察，不能外推全行业效率 |

每种方案每题一次，不靠多次生成取最好结果。若正式30题已用于故障定位或修改提示，相关题退役并进入开发登记；修复后使用另外独立冻结的新题，保留第一次失败，不以同题复跑覆盖。一次环境级阻断可在修复后按事先规则恢复未看到答案的题，恢复原因与实际次数必须记录。

## 冻结到评阅的实际步骤

1. **确定资料与被测版本。** 选定地区、事项、人员分支、资料信息截至日期，以及是否只评历史资料解释。固定全部原件/修订、取回单元、本体版本与候选、源码/配置、MCP/Skill、模型参数、发布策略及来源配置指纹。过期或变化的来源按原门暂停；不得为了实验关闭暂停检查。
2. **准备交接包。** 由保管人建立独立私有评测目录，分开 `reference/`、`questions-only/`、`observations/baseline/`、`observations/proposed/`、`reviews/`。此处只是目录约定，本轮未创建运行包。只交可共享的官方资料，不整包复制运行令牌、账号、个人输入或其他会话。
3. **登记开发历史。** 从实际目标库导出全部开发题登记，并纳入后来北京、南京、跨文档与多模态演示已用问题；公开旧草案中的40题不能自动当作今天完整登记。使用 [knowledge_review.py](../../src/gov_mcp/knowledge_review.py) 的统一 `question_fingerprint` 和只追加登记流程，记录来源，不删除失败或已用题。
4. **独立编写与筛查。** 作者只根据冻结原文产生题目、答案、`expected_outcome`、关键断言和 `revision+locator`；停止题写明应停止的边界与缺口，不附可用于回答的业务事实。独立性复核人核对哈希、语义与泄漏，剔除已用题。参考不能只写“与系统答案相同”。
5. **冻结并交题。** 保管人先记录带时区 `reference_frozen_at`、作者真实身份、快照绑定，按 `reference_fingerprint()` 计算标准指纹。运行操作人只取得 `id/question` 与必需情境、相同来源和相同预算；原文可见、参考答案不可见。输入应据真实请求核查 `reference_answers_in_model_input=false`，不能只手填声明。
6. **成对运行。** 在冻结版本上运行普通检索和本方案。用预先固定的随机种子交替先后顺序，同一硬件/模型/参数、相同资料、相同每题最大证据条数及同等调用上限；禁止跨题答案缓存与跨方案共享会话。记录冷/热状态，若有模型缓存分别报告。采集每题实际输入SHA、轨迹SHA、起止时间、回答/停止、前五证据、失败与用量；错误题也进入分母。
7. **匿名评阅与异议。** 评阅人先不知方法名，逐个关键断言核对原文，记录漏项、单位/地域/版本/例外错误及停止是否正确。存在歧义交资料审核者裁定，未决则如实列出；不能一律补成pass。完成后记录 `reference_reviewed_at`，时间顺序须为冻结≤开始≤完成≤评阅。
8. **分别出报告。** 比较报告保留每种方法全部结果与配对差异；项目正式发布报告还必须满足其固定契约、实际快照绑定和逐题质量门。`status=reviewed`不是通过证明；未通过的题和原因保留在比较报告中，不删题凑达标。
9. **最小收尾。** 核对真实身份、原件和定位、时序、输入/轨迹指纹、范围/版本/暂停门及统计公式。通过阶段标准后停止重复运行；结果可进入正式材料时标注样本、版本、审核者类型和未验证范围。

## 对照定义与指标

普通检索基线：使用相同真实原件、相同文本/OCR/XLSX取回单元和同一模型，仅检索前五证据后按固定提示生成；不使用本体关系执行和显式多跳计划。基线仍保留相同来源、权限、隐私和暂停门。这样能把本体/推理组织的贡献与“基线根本没拿到OCR”分开；若另做文本格式限定的消融，另命名并单独计数，不冒充公平主对照。

本方案：在相同资料、单元、模型和预算条件下，使用已确认本体、逐跳依赖、规则求值和返回前核验。若本体未获确认，不能把先导的固定脚本输出写成本方案正式业务成绩。

| 指标 | 算法 / 分母 | 报告方式 |
| --- | --- | --- |
| 严格整题正确率 | 结果类型正确，全部关键断言有支持、无关键遗漏且所有范围边界正确的题数 / 全部题数 | 两方法各列计数与百分比，错误/超时计失败；分别列答复题和停止题 |
| 断言支持率 | 有证据且语义一致的关键断言数 / 全部关键断言数 | 保留断言清单与对应修订定位；“引用存在”不等于“断言被支持” |
| Recall@5 | 每道答复题 `标准相关证据∩实际前五 / 标准相关证据` 后对答复题求均值 | 去重使用 `revision+locator`，列答复分母；停止题不混入该均值 |
| 关键漏项与范围错误 | 关键要求漏项、错误地区、失效规则作现行、无支持断言逐项计数 | 保留题ID及原文；不得用高平均分抵消这些错误 |
| 正确停止率 / 误停止率 | 应停且实际停 / 应停题；应答却停 / 应答题 | 两个分母分开，避免全拒答取得表面高分 |
| 跨文档/多模态贡献 | 冻结题中实际需要每一来源的关键断言是否支持；移除关键证据能否适当降级 | 主对照只跑一次；必要的移除证据检查另算开发检查，不回填正式成绩 |
| 处理时间 | 实际开始到可审阅结果的墙钟时间；另列人工主动查找/复核分钟 | 报告配对每题及中位数/范围，环境等待和人工主动操作分开；不把API耗时当办理耗时 |
| 资源消耗 | 每题实际调用/重试、输入输出tokens、可获得的账单金额 | 缺费用就填未知；请求减少不自动等于费用减少 |

本项目正式业务发布同时要求至少30题、每道答复的全部断言有支持、四类零错误、正向题平均Recall@5≥90%，非空语料必须同时有答复和停止，来源新鲜度继续有效。这是代码中可核查的门槛，不是比赛官方规定，也不是本次已取得的成绩。30题小样本即使全对也不能证明长期100%正确；报告以观察结果为限。

## 低资源人工投入记录表

构建对照按同一批冻结原文和同一目标结构操作。方法A从原文人工整理；方法B先生成候选再人工复核。尽量由两位背景相近的复核者交叉分配难度相当、内容不同的单元；如果只有一人，先后学习效应无法消除，必须披露，不能把第二次更熟练完全归因于系统。

采纳率 = 正确直接采纳 / 候选总数；可用候选率 =（正确直接采纳+修改后正确）/候选总数，二者分开。还要记录参考应有结构数，计算漏项，防止只报高精度而遗漏多数关系。人工投入 = 阅读+整理+复核修改的主动分钟，另列工具等待与前期规则编写成本；不可把本次六单元的固定抽取器开发成本藏掉。只有存在实际A/B值，才报告分钟差和比例；分母为0或未测时不计算。
