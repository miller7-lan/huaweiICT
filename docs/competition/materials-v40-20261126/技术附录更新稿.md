### 3.2 调用关系

```
用户提问（Nexent 对话页）
  → 智能体第 1 步：govkb_flow_open(question)
        MCP 服务端：地区与范围门控 → 检索冻结语料 → 返回证据、作答规则和 task_id
        范围外或无证据：返回 STOP / BLOCKED，智能体直接给出停止说明
  → 智能体第 2 步：govkb_flow_submit(task_id, outcome, answer, assertions, stop_reason, unknowns)
        MCP 服务端：逐条核验结论与逐字引文（数字、数量、文号、日期须出现在所引原文中）
        未通过：返回 revise（FAILED_CHECKS 改稿 / MORE_EVIDENCE 补查一次），智能体再次提交
        通过或改稿次数用尽：返回 final，含核验后的 display、结果类型和未知项
  → 智能体最后一步：final_answer，只用 final 对象的内容，附“归档解释、需人工复核”说明
```

每题最多 3 次模型草稿（初稿、改稿、补查后一稿）。智能体不能自行改动核验结果：未通过核验的结论被删除，或改为直接摘录原文并标注“部分答复”。

## 六、局限

1. **没有正式评测。** Y12 由开发会话出题，预检 `BLOCKED`；X 组题被多次查看过。正式评测需要未接触项目的人出题。
2. **漏停风险。** V4.0 放宽作答后，Y12 应停止题只停住 1/3（Y1、Y2 一致），这与 30 题盲评时“过于保守”的问题方向相反，需人工评审确认放出的答复是否越界。
3. **V4.0.1 只在开发题上对比过。** 每种配置每题只跑一次，模型输出有随机性。
4. **异机 L1 未完成。**
5. **自动指标与 Jev 都不是人工判断。** Jev 只记录，不改任何结果。
6. **Nexent 自带的 Elasticsearch 组件** 在 Windows 上未修复；本流程的检索在 MCP 服务端用冻结语料完成，不依赖它。计划在提交后改用命名卷修复。
7. 已有局限继续按[局限表](../已知局限与材料表述边界-V4.0-2026-11-26.md)披露：三类语义漏检、推理仅提示、目录元数据未逐项人工核对等。
