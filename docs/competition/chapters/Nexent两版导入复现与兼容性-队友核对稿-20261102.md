# Nexent 两版导入复现与兼容性记录（队友核对稿）

整理：李嘉杰负责的复现工作；历史测试日期 2026-10-31，补充源码离线检查 2026-11-02。此文依据本机复现回执与兼容性记录整理，未经陈子炫或程千城复核。没有在本次整理中启动 Docker、调用模型或业务服务。

## 测试对象和边界

- 导出包：南京 SHA-256 `0a7377f1aeef2296338e77bc093466eb70c59cd4a1b73abf015b39816ae89122`；河南 SHA-256 `9bc19582710dd044921de2f72e8ef0ac56415d4369a39f304d9d9f58eab41808`。
- 两版分别使用独立 Compose 项目、容器、网络、工作卷和数据目录，网页端口仅绑定本机回环；没有挂载宿主 Docker socket。测试配置与官方原始部署并不完全相同，v2.8.2 还使用了本机构建的 MinIO 替代镜像。
- 两版导入均将真实模型改绑为只响应固定探针的占位模型，注册只返回阻断状态的同名 MCP 测试工具；不运行真实模型问答或业务工具。隔离环境的本地版本状态不等于正式业务发布。

## 需要维护者核对的问题

1. **导入后的 V1 快照**：两版草稿保留关联，而自动创建的本地 V1 读回缺少主控 Skill 和子 Agent 关联。源码观察的导入次序与这一现象一致，但实际运行后果尚未测试。请检查发布时机、版本快照及预期行为。
2. **同名工具选择**：v2.8.2 原导入函数在内存桩和虚构同名工具目录下，选中结果随查询结果顺序变化。该离线反例没有注册真实双 MCP 或访问真实数据库；不能断言实际平台发生误绑定。复核脚本 `verify_nexent_import_collision.py` 与第 7 章一同提供。
3. **真实接入与演示**：两地导出包复用同名工具，但真实服务的 profile、来源和本体由运行环境决定。团队需确认正确接线、权限和运行计划；当前不由李嘉杰调用模型或继续配置 Docker，按队友反馈先处理其他材料。

本次证明的是在上述替代环境和占位依赖下，两份配置的导入及所列字段比对结果；**不能据此宣称真实模型问答、真实 MCP 双地路由、正式上线或整体兼容性通过**。项目第 7 章、历史截图讲稿及调用图位于同一合稿 PR；详细时间线及本机截图仍保存在李嘉杰的本地交付目录。导入截图应标明测试日期、版本、占位依赖和自动生成 V1 的缺项，并检查账号和私有路径遮挡。
