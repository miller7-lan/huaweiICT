## 4.5 Skill 设计与模板化

系统将可复用的编排规则与事项执行逻辑分开。平台层配置主控、检索和核验三个角色；编排层由 Skill 规定读取流程、开任务、检索、核验和完成的顺序；协议层约束代码动作格式、工具回执处理及停止行为；工具层提供统一的 MCP 接口；执行层负责各事项的来源适配、本体计划和领域算子。各层职责与表2-4对应。

主控首先读取 Skill，再调用开任务工具取得真实任务编号，依次委派检索和核验子智能体，读取持久状态，最后调用完成工具交付。工具共有开任务、检索、核验、状态和完成五种。模型输出不能代替完成工具的持久回执；上一阶段未完成时，主控不能继续推进下一阶段。

模板由 Skill 骨架、主控协议骨架和事项规格组成。规格填写情境标识、三个角色名称、检索与核验要求、输出不变量以及实现指纹函数。渲染前检查必填项、名称、路径、占位符和指纹入口，已有内容与渲染结果不同时拒绝覆盖，避免覆盖已经验收的 Skill。

河南规格渲染出的 Skill 和主控协议，与2026年10月22日原生验收所用版本逐字一致；通用接线工厂生成的关键配置也与河南专用加载器一致。南京主控协议可以逐字复现，南京旧 Skill 与新模板文字不同，工具按设计拒绝覆盖。14项模板检查连同两组接线检查共63项通过。这些检查证明模板与已知配置的一致性，不代表新事项已部署成功。

新事项部署需要依次完成规格填写、校验与渲染、来源适配和算子开发、候选结构确认、隔离激活及平台接线。当前能够复用平台、编排、协议和工具结构，执行层仍需开发。新事项从零部署的人工操作用时与实际原生运行尚未测量，不能据此宣称实现纯配置迁移或已取得部署效率提升。

## 4.6 MCP 工具实现与关键代码

MCP 服务把模型的动作请求转换为受约束的程序操作。下面三段代码分别说明服务实现变化检查、来源引用核验和本体计划依赖执行；完整实现保留在工程中。

**服务实现变化时阻断。** 服务启动时保存实现指纹，每次调用前复查。指纹发生变化时要求重启服务，异常返回阻断状态，避免同一服务实例在不知情的情况下混用实现。

```python
    def execute(operation, *args):
        try:
            if fingerprints() != startup:
                raise ValueError("SERVICE_SOURCE_CHANGED_RESTART_REQUIRED")
            return operation(*args)
        except Exception as error:
            code = str(error) if isinstance(error, ValueError) and re.fullmatch(r"[A-Z_]+", str(error)) else "ONTOLOGY_CROSSDOC_UNAVAILABLE"
            return {"status": "blocked", "error_code": code, "published": False}
```

来源：[本体查询MCP服务](../../../src/gov_mcp/ontology_crossdoc_preview_server.py)的 `create_app.execute`。这一层检查实现指纹；来源状态、本体版本和任务阶段由各业务操作继续检查，不能仅凭服务指纹一致就认定业务可执行。

**引用必须落在已检索证据中。** 自由提问核验器使用来源编号与定位匹配证据，在去除空白后检查引文是否为原文连续片段。数字与天数单位的后续检查使用通过此步骤的引文。

**按已确认计划执行依赖。** 本体执行器先检查当前节点的父节点是否已有结果，再读取登记的算子与参数。未登记或输出类型不兼容的算子被拒绝，每个节点的输入、输出和来源证据进入执行轨迹。

## 4.7 输出契约与容错

系统分别约束模型候选、工具回执和最终交付。外部 JSON 严格解析拒绝重复键、非有限数值和不合法结构；回执比较递归核对类型和值，区分布尔值与整数、整数与浮点数。DeepSeek 适配器检查响应外壳、文本内容和用量字段，畸形响应进入受控错误。自由提问输出包含答复或停止状态、答复文本、逐条引用、停止原因和未知项，字段不合法时不生成成功答复。

平台智能体不自动继承所有 Python 候选 Schema，因此原生链还依赖实际工具顺序、持久任务阶段、严格最终回执和来源版本复查。主控按协议原样交付工具结果，不以模型重写后的文字替换持久结果；候选符合格式也不等于已获业务批准。

原生流程的模型或业务工具错误会使本轮停止，不自动重复已经成功的业务动作。已有特定实验曾允许有界的无动作格式修复，次数计入对应预算；该规则不是通用重试授权。自由提问调用失败记录模型错误并停止，本方案的引文或数字核验失败也改为停止；比较基线保留原输出并记录同样的核验结果，以观察后置核验的影响。

调用上限按各运行器实际实现控制。自由提问运行器在调用前增加本进程计数，批量运行最多按每题两种方法规划调用；原生实验另有活动预留、启动次数与关闭状态。不同运行器的预算机制不能混称为统一的跨进程账本。已消费预算不因修复或重启自动恢复，新增真实运行须另定范围。

JSON修复完成了632个不同定向用例覆盖及旧真实轨迹只读复核，没有因此新增真实模型样本。浮点表示精度、语义正确性和长期运行稳定率仍须单独验证。
