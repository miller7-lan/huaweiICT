# 第4章 智能体构建方案（分章稿）

> 合稿草稿，依据截至 2026-10-30 的仓库记录编写。第 4.5—4.7 节由陈子炫负责；本稿中的历史运行并不证明现行政策有效，也不代表业务审批或正式发布。请团队核对后合稿。

## 4.1 智能体总体设计

系统围绕来源约束下的检索和核验，分别设计本体推理、知识更新以及冻结资料自由问答三条链路。本体推理组和知识更新组采用主控与两个子 Agent 分工：主控依据任务和持久状态调度，子 Agent 分别负责检索或整理、独立核验。职责和可用工具按角色限定，有助于在步骤失败或状态未满足时阻断后续交付。自由问答采用一个智能体配合检索和核验两个工具，其调用关系与三角色链不同。

## 4.2 本体推理智能体组

### 4.2.1 角色与提示词设计

本体推理组由主控、检索和核验角色组成。主控读取 Skill、创建查询、调度两个子 Agent 并读取状态与结束任务；检索角色读取约束范围内的来源，核验角色检查结果和依据。提示词限制各角色使用对应工具，要求以实际返回的任务标识继续执行，并原样交付工具结果。运行环境限制沙箱内模块导入，流程以工具提供的结构化结果衔接，避免智能体自行改写工具结果。

| 角色 | 提示词中的职责与工具约束 | 配置步数上限 |
| --- | --- | --- |
| 主控 | 读取 `govkb-ontology-crossdoc-preview`；只开放查询、状态和结束工具；用工具返回的实际 `task_id` 调度子 Agent | 6 |
| 检索 | 只调用 `govkb_ontology_crossdoc_retrieve`，同一动作以 `final_answer` 原样返回结果 | 3 |
| 核验 | 只调用 `govkb_ontology_crossdoc_verify`，同一动作以 `final_answer` 原样返回结果 | 3 |

例如，南京预览的首个动作读取上述 Skill，再以固定情境 `nanjing_outside_old_card` 调用 `open_query`；后续必须使用该次实际返回的任务标识，不自行编造。提示词禁止导入模块和将可能为 JSON 字符串的工具结果当作字典索引，结束时直接交付工具原始返回，避免模型重写引用或改变结果类型。错误、阻断或步数耗尽时停止；仅对尚未执行动作的格式错误允许有界协议修复，不重复已执行的业务调用。

### 4.2.2 执行流程与完成门

2026-10-21 南京原生运行的顺序为：读取 Skill → 主控 `govkb_ontology_crossdoc_open_query` → 检索子 Agent 调用 `govkb_ontology_crossdoc_retrieve` → 核验子 Agent 调用 `govkb_ontology_crossdoc_verify` → 主控 `govkb_ontology_crossdoc_state` → `govkb_ontology_crossdoc_finalize` → 结束。只有持久化阶段满足要求才可完成；实际轨迹中的两个子 Agent 分别有独立调用记录。该次运行依据冻结来源解释虚构情境，最终本体演示已回退，不推断真实领证时间或现行业务资格。

## 4.3 知识更新智能体组

更新链由主控、整理和核验角色构成。整理角色分别读取旧、新资料完整视图并提交差异候选；核验角色再次分别读取两份视图，独立核查候选及证据。主控读取持久阶段：整理完成后才调核验，完成门满足后才结束。超长视图或工具错误应阻断流程，避免观察内容截断后继续作结论。

整理角色的差异对象包括旧、新和特殊情形的数值、单位、来源与完整引文，以及适用人群、期间、例外范围、后继关系和生效日期等字段；未建立准确施行日期时保持空值，不把网页日期当成生效日期，也不把不同单位的天数直接相减。核验角色分别报告是否可接受、遗漏、冲突和说明；接受仅表示来源支持的待审工程候选，不代表人工批准。主控依据实际 `run_id` 读取阶段，并在未满足整理或核验门槛时停止。

2026-10-21 的河南归档后继资料实验产生一条待审候选、零正式版本。候选保留对象、时间单位和适用条件，不继承旧资料的批准状态；这次实验不能证明官网持续监测、现行法律效力或正式发布。

## 4.4 冻结资料自由提问问答助手

河南冻结资料问答使用单个 Nexent 智能体，先通过 `govkb_frozen_retrieve` 检索和检查范围，再在可继续时调用 `govkb_frozen_verify` 核验候选答复与引用。答复应展示结论、逐条来源与定位、未知项及状态；无法确认范围、现行效力或依据时停止或提示人工复核。该问答链使用来源约束规则，但没有执行固定情境链中的已确认本体依赖计划。

确定性核验检查来源定位、去空白后的引文，以及答复中数字和“工作日”“自然日”是否出现在通过匹配的引文合并结果中；它不逐条判断结论是否在语义上被引用支持，也不核定现行效力。核验通过不等于业务正确或人工复核通过。

对仓库历史版本的离线合成检查还发现数字子串边界：当虚构引文为“200”时，答复中的“20”也能通过当前字符串包含检查，而“21”被阻断。该检查直接调用现有核验函数、未调用模型；它不说明真实问答案例已发生这一错误。数字匹配与对应断言的支持关系需实现负责人修复并复测，界面继续保留人工复核提示。

2026-10-30 界面调试中，现行效力问题触发停止后智能体仍多调用一次核验，核验也返回停止；应保留这一偏差。已有两个界面样例不足以推导总体准确率。
