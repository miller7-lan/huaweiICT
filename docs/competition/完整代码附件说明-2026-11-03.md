所有历史实验、采集和部署脚本也保留，但不会在打包时执行。不要批量运行脚本；其中部分入口会写私有目录、调用模型或改变平台，需要先阅读对应说明并核对当前来源、授权、预算及暂停状态。

## 生成与核验

在项目根目录运行，只生成本地附件，不启动服务、访问网络或调用模型：

```powershell
.\.venv\Scripts\python.exe scripts\build_complete_source_package.py
.\.venv\Scripts\python.exe scripts\build_complete_source_package.py --verify-only
```

输出位于`artifacts/complete-source-20261103/`，包括`ict-topic3-complete-source-20261103.zip`、逐文件清单、校验清单、ZIP整体散列和检查摘要。完整代码ZIP是独立附件；当前白名单工程复现基础包仍保留原用途，不替换或改名冒充本附件。

**2026年11月5日重新生成。** 代码有修改后用`--stamp`另生成带日期的新附件，旧附件及其已记录的散列保持不变：

```powershell
.\.venv\Scripts\python.exe scripts\build_complete_source_package.py --stamp 20261105
.\.venv\Scripts\python.exe scripts\build_complete_source_package.py --stamp 20261105 --verify-only
```

11月5日版输出在`artifacts/complete-source-20261105/`，文件仍为507个，Python语法检查380个。与11月3日版相比没有增删文件，内容有变化的是：`src/gov_mcp/frozen_qa.py`（先导评测中发现的定位编号误停止修复）及其测试、打包脚本本身，以及本说明。正式提交以最新日期的附件为准，官方正文中的附件文件名须同步改成对应日期。

11月5日同日修订使用`--stamp 20261105-r2`，生成`artifacts/complete-source-20261105-r2/ict-topic3-complete-source-20261105-r2.zip`；原11月5日附件保持。修订纳入知识库接线、原生文件绑定、两份问答草稿JSON及评审脚本，实际数量和散列见新包清单，不沿用507文件和380个Python文件的旧计数。核验新包时使用`--stamp 20261105-r2 --verify-only`，或按下方命令显式传入ZIP路径。

接收方先核对发送方提供的ZIP整体散列，再解压到新目录。使用已有Python 3.11及以上版本，在解压根目录执行：

```powershell
python scripts/build_complete_source_package.py --verify-only --archive <原ZIP的完整路径>
```

此命令不需要安装业务依赖，只核对附件清单、文件散列、Python源码语法及已知凭据特征。校验清单不能替代可信发送方或数字签名。重新生成附件需要Git工作区，单独解压目录只用于读取、核验和按说明准备环境。

## 准备运行

按[复现与交付说明](复现与交付说明-2026-10-21.md)分层准备环境。`scripts/setup.ps1`会下载依赖、固定Nexent源码并建立私有目录；`scripts/deploy.ps1`会改变本机环境并启动Docker服务，均不是打包步骤。云端使用接收方已有环境变量或系统代理，保留HTTPS证书校验；本地服务按NO_PROXY直连。不要复制旧机部署卷或凭据。

模型默认禁用与未审暂停门保持，账号、工具、Skill、来源和计划绑定需重新核对。正式提交前仍需补个人信息与合照、三人审阅、原始平台导出材料，以及另一名队友的真实环境复现记录；独立评测与真人资料复核的缺口分别保留。
