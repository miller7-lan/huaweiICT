# V4.0.2：作答留缺口后补查一次（2026-11-26）

**状态：已生效（2026-11-26）。** 负责人当日决定采用；Windows 服务已带新参数重启，原生开发题核对通过（第四节）。

## 一、改了什么

| 项 | V4.0.1 | V4.0.2 |
| --- | --- | --- |
| MCP 服务 `govkb_frozen_flow` 启动参数 | `--rules strict` | `--rules strict --follow-up-after-answer` |
| 作答但列了缺项（`answer_with_gaps`） | 直接返回 | 按模型列出的缺项补查一次；取到新证据才让模型重写，每题模型调用上限仍为 3 |
| 源码（`src`） | 冻结 `460a2be` | **不变**，冻结回执与 L1 指纹 `b50ffc5b…` 不变 |
| Nexent 智能体（提示词、示例栏、模型） | 版本号 3 | 不变 |
| 原生运行器 `frozen_flow_native.py run` | 不检查补查设置 | 默认要求服务 `follow_up_after_answer=true`，不一致即拒绝运行；跑 V4.0.1 用 `--follow-up off` |

补查本来就有（模型停止时一定补查一次），V4.0.2 只是把同一机制扩展到“作答但留缺口”。脚本对比 `compare_frozen_flow_v3.py` 的默认值保持关闭，以便复现 V4.0 / V4.0.1 的既有结果；V4.0.2 的运行加 `--follow-up-after-answer`。

## 二、为什么

Y12 双人评审中 V4.0 漏核心 3 题，其中 Y02、Y08 是所需条文没进证据池，而模型已在未知项里写明缺什么。零调用回放：用这些未知项补查，所需单元都排在前两位。详见 [漏核心原因分析](Y12漏核心原因分析-2026-11-26.md)。

## 三、证据与边界

开发题 X24，V4.0 冻结代码，开关关、开各一次（[计数](../../evidence/crossdoc-flow-v3/FU-X24-follow-up-after-answer-20261126.json)）：

- 开关实际触发 2 次（X06、X08）：X08 由留缺口变为完整，X06 仍留缺口；
- 没有使任何应停止题放出答复（开关只在作答后触发，停止题本来就补查）；
- 模型调用 32→36；同一配置两次运行另有 2 题因随机性改变（X13、X21），与效果同量级。

可以写：“开发题上触发 2 次，1 次由留缺口变完整，未放出应停止题；每次触发多 1 次模型调用”。不能写：“已验证有效”“解决漏核心”“在 Y12 上验证”（Y12 已用于评测，不在其上调参）。
