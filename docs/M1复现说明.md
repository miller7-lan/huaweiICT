# M1 隔离扩展复现说明

本目录新增的工程仅执行空白技术验收。原三工具、原 Agent 配置、原角色映射和原业务库保留；不得向原库或扩展库导入政策、案例、事项及材料。当前完成情况以 `evidence/m1-acceptance.json` 和 `M1执行进度.md` 为准，测试通过数不是 BT 通过数。

## 准备与启动

先按本机运行说明启动原平台、Docker 与 Ollama，并完成原账号初始化。M1 入口只使用本机私有测试账号；新建的群众 USER 用于首次无历史会话验证。个人账号不参与。

在项目目录运行：

```powershell
$env:PATH = 'C:\Program Files\Docker\Docker\resources\bin;' + $env:PATH
.\.venv\Scripts\python.exe scripts\prepare_m1.py
docker compose -f compose.m1.yml -p gov-m1 up -d --build
.\.venv\Scripts\python.exe scripts\provision_m1.py
.\.venv\Scripts\python.exe scripts\prepare_m1_runtime.py
docker compose -f .runtime/m1/native-runtime/compose.json -p gov-m1-runtime up -d
.\.venv\Scripts\python.exe -m gov_mcp.workbench --runtime .runtime/m1
```

实施前检查 8766、8767、5016 是否已有监听；不要替换其他服务。最后一个命令持续运行工作台。访问 `http://127.0.0.1:8767`，使用已有测试账号登录。六个 MCP 工具使用 govx 前缀，原服务仍在 8765。M1 原生问答使用下文的 3001 独立入口，选择“M1隔离空白主Agent”。原 Nexent 页面仍使用 3000 和原运行容器 5014。

`prepare_m1.py` 先设置私有 ACL，再生成独立令牌、角色映射、连接配置与空 SQLite。首次保存原代码、配置及数据库的指纹；重复运行不重新授予权限或覆盖已有映射。`provision_m1.py` 创建独立名称的 Agent 和新 USER，不重新发布原 Agent。

`prepare_m1_runtime.py` 从固定原运行镜像取得配置，先设置私有 ACL，再生成不进入仓库的 Compose。它使用同一已验证镜像 ID，新增 5016 运行容器、独立沙箱名称和工作区卷、日志与 Skills 目录；平台认证和配置基础设施继续共享。两个 SDK 模块从固定源码生成：错误映射只匹配 govx 地址；沙箱只改两个名称及本机容器回调主机。未知源码指纹拒绝生成。原 SDK 覆盖、原运行容器及原沙箱保留。源和实际运行指纹见 `evidence/m1-runtime-overlay.json`。

## 角色与停止条件

启动准备入口也会核对 SDK 的控制网络是 internal bridge；首次不存在时按固定上游定义创建，已有但不符合要求时拒绝修改。重复空更新的网页证据入口 `record_m1_repeat_empty_ui.py` 要求 CLI workbench 浏览器以独立维护账号进入“知识状态”，实际连续点击三次并核对数据库指纹、七表数量及每个响应的真实审计。

原 citizen/staff 账号在扩展环境仍为群众/工作人员，均无知识维护授权。测试 developer 在独立受控映射中拥有工作人员业务角色和单独的 `knowledge_maintainer=true` 授权。tenant_admin 未映射，应返回 `ROLE_NOT_CONFIGURED`。平台 DEV/ADMIN 角色、聊天自称身份及页面导航均不是维护授权来源。

- 空图谱返回 `EMPTY/NO_GRAPH`，节点和边为空。未配置图谱返回 `ERROR/CONNECTION_NOT_CONFIGURED`，不得混同空数据。
- 空更新返回 `EMPTY/NO_CHANGES`，仅说明本次无输入，不说明外部政策无变化。无候选发布、无确认发布及不存在候选均阻断。
- M1 非空输入返回 `BLOCKED/M1_INPUT_NOT_ALLOWED`，不读取输入文件、不解析业务资料、不创建候选或版本。
- 工作人员缺事项、材料、证据时返回 BLOCKED。工作台展示零事项、零材料、零待办，不给审批结论。
- 任意业务、图谱、候选或版本表意外非空时拒绝使用。真实存储锁最多尝试两次，随后 ERROR；不把异常解释成业务条件不满足。
- 工作台通过 Nexent 当前用户接口逐次核验登录会话，再由服务端注入身份调用实际 MCP。请求体中的身份或图谱写操作被拒绝；Cookie 为 HttpOnly、SameSite=strict，POST 须同源。环境 ERROR/BLOCKED 后页面停止后续工具调用。

网页记录沿用透明代理：

```powershell
.\.venv\Scripts\python.exe scripts\m1_ui_trace_proxy.py
```

浏览器登录 `http://127.0.0.1:3001`，进入新会话、选择 M1 主 Agent、使用执行模式。这个入口只将私有登记的 govx Agent 执行送到 5016；其他页面/API 和原 Agent 继续走官方 3000 入口。转发遵循固定上游 server.js 的 HttpOnly Cookie 到 Authorization 转换，由运行 API 验证实际 JWT，不注入测试账号密码或猜测身份。停止操作仅按实际观察的 M1 会话号路由。它记录真实 SSE，不生成 Agent 答复。

首次入口必须先保存无历史截图，再做其他操作。截图放在 `output/playwright/`；CLI 的缓存及登录状态在 Git 忽略的 `.playwright-cli/`，浏览器登录辅助入口给该目录设置私有 ACL，令牌和密码不得进入公开证据。空输入检查入口 `record_m1_empty_input.py` 依赖名为 m1 的 CLI 浏览器已经进入该空输入页面；它检查空/空白 Enter 的发送状态、Agent 请求数量及真实工具审计增量。最初无历史证据已归档；当前新账号已有后续技术会话，不能重复称为首次无历史。

UI 完成后，用实际会话号登记，不复制示例号码：

```powershell
.\.venv\Scripts\python.exe scripts\record_m1_ui_trace.py --conversation <实际会话号> --screenshot output/playwright/m1-BT03.png
```

此入口保留原始 govx 轨迹，仅在校验副本中映射名称以复用原严格验收器；子 Agent 实际 ID、工具顺序、身份、最终字段与审计匹配规则不放宽。每个截图还应实际查看，脚本的哈希检查不能证明图片语义。

旧 3001 透明入口的第一次记录在 `.runtime/m1/ui-traces/`；新独立入口记录在 `.runtime/m1/sidecar-ui-traces/`。登记新的记录时，传 `--trace-dir .runtime/m1/sidecar-ui-traces --output evidence/<本轮记录名>.json`；截图必须已真实保存。

## 真实异常和网页停止

`verify_m1_native_faults.py` 要求 sidecar-success 已通过，并要求 CLI workbench 浏览器以群众身份登录正常工作台。它在 govx 容器内取得独占锁，实际核对工具两次尝试后的 ERROR、原生主 Agent 停止和工作台提示，释放后用新会话复测；再停止 govx 容器，核对原生 SDK 的一次连接尝试、无 Agent 模型/工具调用及工作台提示，最后在 finally 中恢复并再次复测。只操作扩展容器，不停原 MCP。对工作台而言不可用状态使用 `CONNECTION_OR_TOOL_UNAVAILABLE`；对原生 SDK 的纯连接错误使用 `CONNECTION_TIMEOUT`，各自前端与各自日志严格匹配。

`verify_m1_native_ui_faults.py` 要求 CLI m1 浏览器已进入 M1 主 Agent 执行页。它对真实原生页面再执行锁与断连，同样有 finally 释放和恢复，保存完整 SSE 与实际截图；断连发生于工具执行前，没有 MCP request_id，记录真实页面会话号和认证主体摘要，不编造工具审计。

M1 维护界面验收入口 `record_m1_citizen_maintenance.py` 要求 CLI workbench 浏览器已以新群众账号进入“知识状态”。真实点击更新和发布，两个响应均需 FORBIDDEN，并与 MCP 审计逐项匹配。

## 完成检查与范围

BT01–BT16 的统一记录和文件指纹在 `evidence/m1-acceptance.json`。完成前执行 `scripts/audit_m1_completion.py`，复核当前服务、两库为空、原服务指纹、真实轨迹、异常恢复、回归测试及公开文件中已知账号/服务/基础设施凭据。Gate 通过不能替代实际截图的语义检查。正式完成状态见 `evidence/m1-completion-audit.json` 和执行进度。

首次 M1 群众 UI 会话在子模型首段响应超时重试后被停止，失败轨迹保留。恢复现有固定 Ollama 配置后，新会话通过，原三工具原生回归也通过。失败轮次不计通过或性能样本。

独立运行容器的首轮沙箱配置和回调连接失败也保留。运行沙箱范围按固定上游设为 system，回调主机只在私有 SDK 中改为新容器；网页入口初次遗漏 Cookie 认证转换的 HTTP 500 被保留为失败记录，修正后实际异常页面通过。所有这些修复均没有重发原 Agent、改写原 SDK 或导入业务内容。

不进行远程推送、合并和正式提交。每轮完成后重新核对原服务指纹、原库与扩展库数量，以及公开文件是否含本机密码/服务令牌。
