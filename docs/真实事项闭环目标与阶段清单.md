# 真实事项业务闭环目标与阶段清单

2026-10-19，用户明确要求以“一个真实事项的规则核定 → 本体演化与多跳案例 → 更新发布及双端联调 → 独立评测和交付”为目标模式执行，并授权每完成一个可独立核查的小阶段提交、推送 GitHub。应用目标状态为 active，无指定 token 预算。

主工作分支：`feat/real-matter-closure`。整合起点为 `feat/m2-minimal-flow@f3b2256` 与 `codex/sync-m1-m2@d51a483`。OCR 由队友负责，本目标只约定其接口和下游联调，不重做 OCR。

## 范围选择

首个真实事项选南京市成年、具有完全民事行为能力居民本人办理居民身份证期满换领，先以江苏省内户籍、线下办理作为主成功分支。省外户籍、能力状态未知、遗失/损坏、监护、减免、历史日期等作为范围及停止边界；不默认套用主分支。

选择理由：已有南京真实原生预演，以及南京公安完整换证问答和2026市政府时限答复，可核对材料、窗口、费用、办理周期、网办排除及旧证使用条件。二七现有未决项继续保留，不迁移为南京结论，不要求先解决全部二七争议。

此处是开发范围选择，不是已完成人工业务批准。政策结论须绑定实际来源、原文、日期和适用范围；生效日期未知时不能以抓取日补齐。没有足够依据的字段保留未知/停止。

## 必须保持的边界

- 不把模拟、固定回放、测试数或Jev支持分数等同正式业务批准。
- 本地开发可以推进；正式业务复核记录必须有真实复核人及明确确认，不伪造人工、独立评测或现场材料。
- 不自动解除来源撤权、冲突、证据不足或失效暂停；当前停止策略叠加历史快照。
- 不收集居民姓名、证件号等真实个人资料；不向政务系统提交申请。
- Windows五分钟恢复任务继续停用，只有用户明确“开启”才启用；目标模式与GitHub推送授权不隐含该动作。
- 保留旧北京/二七/南京预演及失败预算，不删除或重置旧活动。后续确需新的真实运行须独立记录范围、调用预算与回执，不能借旧活动追加请求。
- 遵循根目录AGENTS.md及2026-10-18接续记录的最小必要测试约定，不循环刷新全量测试。
