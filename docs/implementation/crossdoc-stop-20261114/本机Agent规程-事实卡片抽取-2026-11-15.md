# 本机 Agent 规程：事实卡片抽取（F1—F4）

读者：在本机执行事实卡片抽取的 Agent。本文**新增**，前面各份规程与下一步文档一律不改、继续适用；[第一份规程](本机Agent执行规程-2026-11-14.md)的通用规则在这里全部有效。

## 这是什么

`scripts/extract_fact_cards.py` 用正则和规则，从冻结语料的每个单元里抽出“事实卡片”：

| 类型 | 例子 | 记录的值 |
| --- | --- | --- |
| `amount` 金额 | 每证20元 | 数字、单位 |
| `duration` 期限 | 15个工作日、40日（自然日）、三个月 | 数字、单位 |
| `count` 次数、年龄等 | 年满16岁 | 数字、单位 |
| `date` 日期 | 自2018年4月1日起 | 日期、类型（施行、发布、修改、文书日期或未标明） |
| `year` 年份 | 2021年通知 | 年份 |
| `document_number` 文号 | 豫公〔2021〕16号 | 文号、比较用的规范写法 |
| `table_cell` 表格单元格 | 收费标准＝20元 | 列名、单元格地址 |

每张卡片还记录：来源、定位、原文中的字符位置和那段原文、所在句子、同一分句里出现的业务对象（首次申领、换领、补领、临时证等）和限定词（不得、仅限、有条件、免收、停征等）。分句里没有业务对象时，取整句的对象，并标 `subjects_from: sentence`。

**它现在只是候选层**：问答流程不读取卡片，答复、核验、已有成绩都不受影响。它的用途是：作为“低资源半自动构建”的材料（规则抽取 + 人工抽样核对），以及以后接入提示词和核验之前先量出准确率。

## 硬性要求

1. **不调用模型，不联网。** 四项任务都是本地计算和人工核对。
2. **卡片文件和抽样表留在 `.runtime`。** 它们含原文片段。只有计数摘要和评分统计可以提交。
3. **“是否正确”一列只由人填写。** Agent 负责抽样、发表、检查、统计；不替人判断、不预填、不改人填的值。
4. **抽取结果必须可复现。** 同一语料跑两次，`cards_sha256` 必须相同。
5. **未完成就写未完成。** 某条完成标准没达到，报告里写“F? 未完成：<哪一条>，原因：<原因>”。
6. **优先级低于 T10 和 T15。** 24 题盲评和异机复现有 11 月 18 日的截止；这四项不占用这两项的人和时间。人工核对的那个人，不要是正在做 24 题评审的两位。

## F2 抽取（两次）

用 593 单元语料，跑两次，输出用不同文件名：

```powershell
.\.venv\Scripts\python.exe scripts/extract_fact_cards.py extract --corpus <593 语料目录>/corpus.json `
  --cards .runtime/fact-cards-20261115/cards-1.jsonl --summary evidence/fact-cards/summary-20261115-1.json
.\.venv\Scripts\python.exe scripts/extract_fact_cards.py extract --corpus <593 语料目录>/corpus.json `
  --cards .runtime/fact-cards-20261115/cards-2.jsonl --summary evidence/fact-cards/summary-20261115-2.json
```

**完成标准**（全部满足）：

- 两份摘要的 `units` 为 593，`corpus_unit_sha256` 为 `5e30a8d4e2239be4b52c5585bb456a2ac7f431f1f959295f28a1ba4b22eb7e05`；
- `span_mismatches` 为 0（不为 0 时脚本会直接报错退出，不写文件）；
- 两份摘要的 `cards_sha256` 相同。

**交回**：第一份摘要 `summary-20261115-1.json`；报告里写两次的 `cards_sha256` 是否相同。第二份摘要不用提交。

**同时在报告里抄下这几个数**，它们说明规则覆盖到哪里、缺在哪里：`by_type`、`units_without_cards`、`number_cards_without_subject`、`dates_by_role` 里 `unspecified` 的个数。

## F3 人工抽样核对

### 1 抽样（Agent）

```powershell
.\.venv\Scripts\python.exe scripts/extract_fact_cards.py sample --cards .runtime/fact-cards-20261115/cards-1.jsonl `
  --per-type 10 --output .runtime/fact-cards-20261115/sample-20261115.csv
```

每种类型随机抽 10 张，共约 70 行（某类不足 10 张就全取）。种子固定，同样的卡片文件每次抽出同样的样本。

### 2 人工核对（人）

把抽样表发给用户指定的一位核对人。核对人对每一行读 `sentence`（原句）和 `text`（抽到的片段），在 `correct` 列填一个值：

| 填 | 什么时候 |
| --- | --- |
| 是 | 类型对、值对，`subjects` 里列的业务对象确实是这个数字或日期所指的对象 |
| 部分 | 类型和值对，但业务对象列错了、多了或少了；或日期类型应能看出却标成 `unspecified` |
| 否 | 类型错（例如把文号的一部分当成期限），或值错 |

按类型的补充：

- `amount`、`duration`、`count`：单位要对，“40日（自然日）”的单位是“日”算对。
- `date`：日期对、类型对才算“是”；原句写了“施行”“发布”而卡片是 `unspecified`，填“部分”。
- `document_number`：文号完整才算“是”，前面多带了“依据”等字或少了发文字号，填“部分”。
- `table_cell`：列名必须与原表格表头一致。
- `subjects_from` 为 `sentence` 时，对象是从整句取的，更容易错，请特别看一眼。

`note` 列可写简短原因，不上传。

### 3 检查与统计（Agent）

核对人交回后先检查，有问题原样退回核对人本人：

```powershell
.\.venv\Scripts\python.exe scripts/extract_fact_cards.py score --cards .runtime/fact-cards-20261115/cards-1.jsonl `
  --sheet <交回的表>.csv
```

`problems` 为空后统计：

```powershell
.\.venv\Scripts\python.exe scripts/extract_fact_cards.py score --cards .runtime/fact-cards-20261115/cards-1.jsonl `
  --sheet <交回的表>.csv --output evidence/fact-cards/precision-20261115.json
```

**完成标准**：

- 抽样表由人填写并交回，`problems` 为空；
- 统计文件已生成，每种类型都有 `checked` 数。

**交回**：`precision-20261115.json`；报告里写核对人的角色（不写隐私）以及是否参与过出题或评审。

## F4 报告

文件名：`docs/implementation/crossdoc-stop-20261114/事实卡片抽取报告-<日期>.md`。开头固定：

```
名称：规则抽取（候选层，未接入问答流程）
被测提交 / 语料单元散列：
未完成：<逐项；没有写“无”>
调用：0
```

正文分 F1—F3 三节，每节第一行写“完成”或“未完成：<原因>”。然后单列一节“规则的缺口”，写：

- 每种类型标“否”和“部分”最多的原因（用自己的话概括，不贴原文）；
- `units_without_cards` 里大致是哪类单元（例如只有文字说明、没有数字的条款）；
- `subjects_from: sentence` 的卡片在样本里出错的比例。

**材料里只能写**：各类型在人工抽样上的正确比例（注明样本数、一位核对人、只量了精确率没量召回率），以及卡片总数与覆盖情况。不能写成“抽取准确率”而不带这些限定。

## 必须停下来问用户的情况

- `corpus_unit_sha256` 不是 593 语料的值，或 `units` 不是 593；
- 两次抽取的 `cards_sha256` 不同；
- 用户还没指定核对人；
- 核对人同时是 24 题评审中的一位；
- 抽样里某一类型标“否”超过一半：先报告，不进入任何后续接入工作。

## 之后（提交后再考虑，不在本轮）

按准确率决定哪些类型可以接入：先作为提示词里的阅读辅助（像表格列对照一样，不能被引用），再考虑用“对象 + 数量”组合做核验提示。每一步都要用新题验证，不回头用已有题目。
