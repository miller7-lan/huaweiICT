# 本机测试与上传清单

日期：2026-11-14。用途：云端这边看不到本机的 `.runtime` 私有记录，只能根据上传到 GitHub 的内容判断下一步改哪里。本文说明本机每一步跑什么、哪些结果上传、哪些不能上传。

命令在仓库根目录执行。Windows 上先设 `$env:PYTHONUTF8 = "1"`，否则读 UTF-8 文件可能失败（执行报告里出现过）。第 3、4 步消耗 DeepSeek 额度，须先取得用户确认。

## 一、本机步骤

### 1. 拉取并跑定向测试（不联网）

```powershell
git fetch origin
git switch claude/cross-document-process-optimization-71x1w4
git pull
.\.venv\Scripts\python.exe -m pytest tests/test_frozen_qa_flow_v3.py -q
.\.venv\Scripts\python.exe -m pytest tests/test_frozen_qa.py tests/test_frozen_retrieval.py tests/test_frozen_qa_flow_v2_comparison.py -q
```

预期：17 项和 74 项通过。

### 2. 从已有记录导出诊断（不调用模型，最优先）

对已经跑完的 8 题配对记录直接导出，不需要重跑：

```powershell
.\.venv\Scripts\python.exe scripts/export_flow_v3_diagnostics.py `
  --records .runtime/crossdoc-flow-v3/regression8-20261114/records.jsonl `
  --corpus <当时使用的 591 单元 corpus.json> `
  --output evidence/crossdoc-flow-v3/regression8-20261114-diagnostics.json
```

脚本做的事：按记录里的检索结果从语料重建证据，对最后一份模型草稿的每条结论单独重新核验，输出题号、结果类型、调用次数、失败码类型，以及每条结论的引用状态（有效 / 来源未检索 / 引文不在原文）、字数、所引单元的类型。**不输出任何题目、答案、结论、引文或证据文本。**

说明：

- 这批记录是旧版 V3 生成的，没有 `final_checks`、`claims_excerpted` 字段，导出里对应为空，属正常。
- 默认去掉失败码里的数值。加 `--with-values` 会保留（如 `QUANTITY_NOT_QUOTED:20元`），这些数值来自模型草稿，上传前请先看一遍。
- 输出必须是 `evidence/` 下的新文件，已存在则拒绝。

### 3. 用同一批 8 题回归当前代码（上限 32 次调用）

```powershell
.\.venv\Scripts\python.exe scripts/compare_frozen_flow_v3.py --questions <8题文件> `
  --corpus <corpus.json> --output .runtime/crossdoc-flow-v3/regression8-r2-20261114
# 确认计划后加 --live --max-calls 32 再执行一次；输出目录须是新的
```

跑完再执行一次第 2 步的导出，`--records` 指向新目录，`--output` 用新文件名。

### 4. 单题抽查（各 1 题，最多 3 次调用）

```powershell
.\.venv\Scripts\python.exe scripts/run_frozen_qa.py ask --flow --live --max-calls 3 "……"
```

选三类各一题：曾因年份或引用失败的、曾因证据不足停止的、应当停止的。

### 5. 人工判读（不调用模型）

对第 3 步的 16 份输出，两人各自填一张表，每份输出一行：

| 列 | 取值 |
| --- | --- |
| 题号、方法 | 如 N01、flow_v3 |
| 保留的结论是否正确 | 是 / 否 / 部分 |
| 是否漏掉必答要点 | 否 / 漏次要 / 漏核心 |
| 引文是否支持结论中的条件和限定语 | 是 / 否 |
| “原文摘录”条目是否与问题相关 | 是 / 否 / 无摘录 |

## 二、上传什么

提交到一个新分支（如 `codex/v3-validation-r2-20261114`）或直接提交到本分支，推送后告诉我分支名或提交号。

| 文件 | 来源 | 放到 |
| --- | --- | --- |
| 诊断导出 JSON（旧记录一份，新运行一份） | 第 2、3 步 | `evidence/crossdoc-flow-v3/` |
| `plan.json`、`summary.json` | 第 3 步输出目录，只含计数和散列 | `evidence/crossdoc-flow-v3/<运行名>/` |
| 定向测试结果 | 第 1 步，各一行“N passed”，失败时附失败项名称 | 执行报告 |
| 环境 | 提交号、Python 版本、`mcp` 版本、语料文件散列 | 执行报告 |
| 人工判读表 | 第 5 步，只含题号和上表各列 | `evidence/crossdoc-flow-v3/<运行名>/` |
| 执行报告 | 仿照 [V3 本地执行报告](V3本地执行报告-2026-11-14.md)，写清实际调用次数、失败与重试 | 本目录 |

如果某一道题需要我看具体内容，可以在执行报告里用自己的话描述“问的是哪类事项、丢掉的是哪类信息、失败码是什么”，不必贴原文。

## 三、不要上传

- `records.jsonl`、单题运行记录、原始模型输出；
- `corpus.json` 和任何证据原文；
- 带参考答案或必答要点的题目文件（题目本身在正式评测前也不要上传）；
- `.runtime/` 下的任何文件、API 日志、密钥、代理地址；
- 人工判读表里的评审备注原文（只传取值）。

## 四、我会怎么用这些数据

| 导出里看到的情况 | 说明什么 | 下一步 |
| --- | --- | --- |
| 失败结论的引用状态多为“来源未检索”或“引文不在原文” | 模型抄写出错 | 做指针式引用（深化方案 A） |
| 引用有效，但 `claim_fixed_by_source_citations` 占多数 | 只差文件标题或日期引用 | 后端补引已够，重点转向完整性 |
| 引用有效，失败集中在金额、期限 | 需要人工看是真错还是规则误拦 | 真错：摘录降级已覆盖；误拦：改核验规则 |
| 停止题里补查新增为 0 | 语料里检索不到缺项 | 检索召回问题，做语料打标（深化方案 B 第 2 步） |
| 部分答复被判“漏核心”占多数 | 逐条保留不足以构成可接受答复 | 优先做证据矩阵（深化方案 B） |
| 应停止题出现答复或部分答复 | 放行了不该答的题 | 先停下排查，优先于其他一切 |

设计依据见[深化方案与参考文献](深化方案与参考文献-2026-11-14.md)。
