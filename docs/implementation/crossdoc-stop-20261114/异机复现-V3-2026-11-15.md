## 一、三级目标

| 级别 | 证明什么 | 调用模型 | 估计用时 | 材料里可以写 |
| --- | --- | --- | --- | --- |
| L1 | 另一台电脑从同一提交、同一批原件，得到**逐字节相同**的语料、范围门判定、检索结果和核验结论 | 否 | 1—2 小时 | “源码与数据在另一台电脑上确定性复现” |
| L2 | L1 加上用自己的密钥真实跑通一道题 | 是，最多 3 次 | 15 分钟 | 加上“命令行真实模型运行” |
| L3 | L2 加上在新部署的 Nexent 上登记草稿 Agent 并在界面里问答一次 | 是，1 次原生运行 | 半天以上 | “Nexent 平台异机复现（S09）” |

**完成哪一级就只写哪一级。** 例如只做完 L1，材料里不写“S09 完成”，写“异机复现达到源码与数据层，平台层未完成及原因”。

L3 在新电脑的界面里问答一次，截下的图同时可以补上第三份文档 T9 缺的界面截图。

## 三、L1：源码与数据（不调用模型）

### 1 取得同一提交

在新电脑的空目录里，不覆盖任何已有工程：

```powershell
git clone https://github.com/miller7-lan/huaweiICT.git ICT-repro
Set-Location ICT-repro
git switch claude/cross-document-process-optimization-71x1w4
git checkout <被测提交号>
git status --short    # 应为空
```

### 2 准备 Python 环境

```powershell
$env:PYTHONUTF8 = "1"
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
```

Python 需 3.11 及以上。`mcp` 必须是锁文件里的 1.26.0。

### 3 测试

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_frozen_qa_flow_v3.py tests/test_frozen_qa_flow_server.py tests/test_frozen_flow_native.py tests/test_flow_v3_review_pack.py tests/test_flow_v3_preflight.py tests/test_reproduction_tools.py -q
.\.venv\Scripts\python.exe -m pytest tests/test_frozen_qa.py tests/test_frozen_retrieval.py tests/test_frozen_qa_flow_v2_comparison.py -q
```

**通过标准**：`50 passed` 和 `76 passed`（按本文所在提交；被测提交更晚时以该提交的文档为准）。

### 4 放入原件并构建两份语料

```powershell
.\.venv\Scripts\python.exe scripts/pack_frozen_originals.py unpack <原件包>.zip
.\.venv\Scripts\python.exe scripts/build_frozen_corpus.py --offline --output-runtime .runtime/repro-591
.\.venv\Scripts\python.exe scripts/build_frozen_corpus.py --offline --catalog-titles --output-runtime .runtime/repro-593
```

`unpack` 会逐个核对原件的散列与资料目录登记是否一致，不一致直接拒绝。构建同样会再核对一次。

**通过标准**：两次构建打印的 `corpus_sha256`（这是**单元散列**）分别等于：

| 语料 | 单元数 | 单元散列 |
| --- | --- | --- |
| 591 | 591 | `1e556dad8e703ada6c1680289415f6e74eeec772c856b0a542138874592c4fce` |
| 593（含目录标题） | 593 | `5e30a8d4e2239be4b52c5585bb456a2ac7f431f1f959295f28a1ba4b22eb7e05` |

注意：**`corpus.json` 文件本身的 SHA-256 每次构建都不同**（文件里记了构建时间），比较时只看单元散列。

### 5 生成并比较指纹

两台电脑用**同一个提交、同样的参数**各生成一次：

```powershell
.\.venv\Scripts\python.exe scripts/reproduction_fingerprint.py make `
  --corpus .runtime/repro-593/corpus.json `
  --questions evaluation/crossdoc-refactor-20261113/fresh-questions.json `
              evaluation/crossdoc-refactor-20261113/retrieval-probes.json `
              evaluation/independent-20261030/pilot/dev-pilot-questions.json `
  --output evidence/repro-<本机标识>-<日期>.json
```

三组题都在仓库里，共 27 道。有私下传来的 `records.jsonl` 时加 `--records <路径>`，指纹里会多出对这些草稿的核验结论。原机器生成时也要加同一份记录。

然后比较：

```powershell
.\.venv\Scripts\python.exe scripts/reproduction_fingerprint.py compare evidence/repro-origin-<日期>.json evidence/repro-<本机标识>-<日期>.json
```

**通过标准**：输出 `"same": true`。

不一致时，`differ` 会指出是哪一部分：语料、模块源码、哪一组题的哪一道、还是核验回放。把 `differ` 原样交回，不要改代码或数据去凑一致。

**L1 完成**：第 3、4、5 步的通过标准都满足。

## 四、L2：命令行真实运行（最多 3 次调用）

需要操作者自己的 DeepSeek 密钥，放在环境变量 `DEEPSEEK_API_KEY`，不写进命令、文件或截图。网络沿用本机代理设置。

先按第二份规程预检，再从 `fresh-questions.json` 里选一道题：

```powershell
.\.venv\Scripts\python.exe scripts/run_frozen_qa.py ask --flow --live --max-calls 3 --runtime .runtime/repro-593 "<题面>"
```

**通过标准**：

- 运行结束，没有 `MODEL_ERROR`；
- 记录里的检索证据与指纹文件中这道题的证据一致（`retrieval.evidence` 的来源与定位）；
- 结果类型、调用次数、`final_checks` 已记录。

结果类型和原机器可以不同，因为模型生成有波动；检索和核验必须一致，这一点已由 L1 保证。

## 五、L3：Nexent 平台（1 次原生运行）

### 1 部署平台

按 11 月 3 日指南第三节第 3、4 小节执行（`scripts/setup.ps1`、`scripts/deploy.ps1`、`scripts/check_native_ready.py`）。Nexent 版本以那份指南为准，版本不同先记录，不自动升级。

**平台账号用新平台自己的初始化或注册流程建立。** 不复制原机器的 `.runtime/accounts.json` 或 `.runtime/nexent-state.json`。11 月 3 日指南已说明 `initialize_accounts.ps1` 含历史前提，不能直接用；这一步卡住就交给实现负责人处理，L3 记为“未完成：平台账号”。

### 2 在平台里登记模型

在 Nexent 的模型管理界面里添加一个 OpenAI 兼容模型，**模型名必须是 `deepseek-flash`，地址必须是 `https://api.deepseek.com/v1`**，并确认连接状态为可用。登记脚本会按这两项查找，名称或地址不一致会报 `ONE_AVAILABLE_OFFICIAL_DEEPSEEK_FLASH_REQUIRED`。

### 3 启动 V3 服务并登记草稿

```powershell
# 新终端，保持运行
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m gov_mcp.frozen_qa_flow_server --corpus .runtime/repro-593/corpus.json

# 另一个终端
curl.exe --noproxy "*" http://127.0.0.1:8787/health
.\.venv\Scripts\python.exe scripts/frozen_flow_native.py provision --apply
```

**通过标准**：健康检查里 `rules` 为 `strict`、`corpus_sha256` 为 593 的单元散列；登记输出 `"configured": true`、`"published": false`，草稿为禁用状态。

### 4 界面问答一次并截图

在 Nexent 网页里打开新登记的草稿的调试界面，问 L2 用过的那道题。截两张图：工具调用过程（能看到 `govkb_flow_open` 和 `govkb_flow_submit`）、最终答复。截图里不能出现令牌、账号、密钥。

**L3 完成**：第 1—4 步都满足，两张截图已保存。

## 八、需要停下来问队长的情况

- 原件包 `unpack` 被拒绝，或两份语料的单元散列与上表不符；

- 平台账号或模型登记卡住；
