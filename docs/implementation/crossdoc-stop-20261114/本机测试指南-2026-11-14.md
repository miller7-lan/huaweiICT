这次导出比上次多一项**离线回放**（`last_draft_replayed`）：把记录里已有的最后一份模型草稿交给当前代码做后处理（补来源引用、核验、逐条保留、原文摘录），看不再调用模型时会展示什么。它回答两个之前没有数据的问题：

回放用的是已有草稿，不是新的模型运行，结果不能当作新一轮成绩。

第 7 步可选运行的输出目录用新名字，如 `.runtime/crossdoc-flow-v3/regression8-r3-20261114`；跑完同样导出一份诊断。

## 五、步骤 4：从已有记录导出诊断（不调用模型，最优先）

上次 8 题配对的私有记录还在本机，直接导出，不需要重跑：

```powershell
.\.venv\Scripts\python.exe scripts/export_flow_v3_diagnostics.py `
  --records .runtime/crossdoc-flow-v3/regression8-20261114/records.jsonl `
  --corpus <当时使用的 591 单元 corpus.json> `
  --output evidence/crossdoc-flow-v3/regression8-20261114-diagnostics.json
```

脚本按记录里的检索结果从语料重建证据，对最后一份模型草稿的每条结论单独重新核验。输出只有题号、结果类型、调用次数、失败码类型，以及每条结论的引用状态、字数和所引单元的类型，**不含任何题目、答案、结论、引文或证据文本**。

- `--corpus` 必须是当时运行用的那份语料，否则证据对不上。
- 输出必须是 `evidence/` 下的新文件，已存在会被拒绝（`NEW_FILE_UNDER_EVIDENCE_REQUIRED`）。
- 默认去掉失败码里的数值。加 `--with-values` 会保留（如 `QUANTITY_NOT_QUOTED:20元`）；这些数值来自模型草稿，上传前先自己看一遍。
- 这批记录由旧版 V3 生成，没有 `final_checks`、`claims_excerpted`，导出里对应为空，属正常。

终端打印的 `totals` 里重点看四个数：

| 字段 | 含义 |
| --- | --- |
| `claim_citation:valid / not_retrieved / quote_not_in_source` | 草稿里各条结论的引用状态 |
| `claim_fails_alone` | 单独核验不通过的结论数 |
| `claim_fixed_by_source_citations` | 其中补上来源标题或日期引用后就能通过的条数 |
| `draft_failure:<类型>` | 各类失败码出现的次数 |

各取一题：曾因年份或引用失败的、曾因证据不足停止的、应当停止的。终端输出里看：

| 字段 | 取值与含义 |
| --- | --- |
| `result_kind` | `answer` 完整答复；`answer_with_gaps` 通过核验但自述仍有缺项；`partial_answer` 部分答复；`stop` 停止 |

## 八、步骤 8：人工判读（不调用模型）

人工判读回答的是程序回答不了的问题：保留下来的结论对不对，漏没漏必答要点，引文是否真的覆盖条件和限定语。**它是这一轮最重要的一步**，决定下一步做证据矩阵还是转去做原生接线。

### 谁做、做什么

| 角色 | 做什么 |
| --- | --- |
| 组织者（不评分） | 生成评审包，保管 A/B 密钥，收表，揭盲统计，上传计数 |
| 两位评审（建议沿用上次的李嘉杰、程千城） | 各自独立评全部 16 份输出，约半小时到一小时 |

两位评审都要有私有参考答案（含各题必答要点）。参考有误时按原文判断，并在备注里写“参考有误”。组织者不要同时当评审，否则看过密钥就失去盲评意义。

### 开始：组织者生成评审包

用 r2 的那批记录（或第 7 步新跑的记录），在**本机**生成，评审包含题目、答案和原文，**只放在 `.runtime` 下，不入 Git，私下发给评审**：

```powershell
.\.venv\Scripts\python.exe scripts/build_flow_v3_review_pack.py `
  --records <r2 目录>/regression8-r2-20261114/records.jsonl `
  --corpus <语料目录>/corpus.json `
  --output .runtime/crossdoc-flow-v3/review-r2-20261114 `
  --reviewers reviewer1 reviewer2
```

生成三类文件：

| 文件 | 给谁 | 内容 |
| --- | --- | --- |
| `review.md` | 两位评审 | 评审说明；每题的问题、输出 A 和 B（逐条结论、引文、停止说明）、输出引用的原文单元全文 |
| `sheet-reviewer1.csv`、`sheet-reviewer2.csv` | 各发一张 | 每份输出一行，四列待填，Excel 或 WPS 可打开，已带 BOM 不会乱码 |
| `key.json` | **只组织者保管** | 每题 A/B 对应哪种方法；两张表都交回之前不给任何评审看，包括不要放进发给评审的文件夹 |

16 份输出 = 8 题 × A/B。A/B 按题随机排列，方法名、结果类型都不显示。输出里偶尔会有露出方法的措辞（“部分答复”“原文摘录”），评审说明已要求不据此猜测，但盲评不是绝对的，报告里如实写明。

### 评审怎么评

打开 `review.md` 和自己那张表，每份输出填四列（取值见 `review.md` 开头的说明）：

| 列 | 取值 |
| --- | --- |
| `conclusions_correct` 保留的结论是否正确 | 是 / 否 / 部分 / 不适用（输出是停止） |
| `missing_points` 是否漏掉必答要点 | 否 / 漏次要 / 漏核心 / 不适用 |
| `citations_support` 引文是否支持结论中的条件和限定语 | 是 / 否 / 不适用 |
| `excerpt_relevant` 带“原文摘录”的条目是否与问题相关 | 是 / 否 / 无摘录 |

做法：

1. 先看问题，对照自己的参考答案列出必答要点。
2. 再看输出里的逐条结论和引文，对照下面附的原文全文核对，不凭记忆判断。
3. 重点看限定语：“有条件”“仅限”“除外”“当天”这类词有没有被引文覆盖。上次执行报告里的 N03 就是这类问题。
4. 备注里记：这道题按参考答案应答复还是应停止；觉得参考有误就写“参考有误”。
5. 停止的输出，前三列填“不适用”，在备注里写停止是否合理。
6. 评完前不讨论、不看对方的表、不看密钥。

### 收表和统计

两张表交回后，组织者检查没有空格，再运行：

```powershell
.\.venv\Scripts\python.exe scripts/score_flow_v3_review.py `
  --pack .runtime/crossdoc-flow-v3/review-r2-20261114 `
  --sheets <评审1的表>.csv <评审2的表>.csv `
  --output evidence/crossdoc-flow-v3/review-r2-20261114-summary.json
```

脚本会检查：行数和题号与密钥一致、取值都在允许范围内（否则报 `INVALID_VALUE`，退回评审改）。输出只有各方法、各列的取值计数、两位评审的一致份数、不一致的题号，**不含任何题目、答案或备注**，可以上传。不一致的份数不要由组织者裁定，由两位评审合议；谈不拢的如实记为“未达成一致”，保留两人原评分。

### 怎么读结果

| 看什么 | 说明什么 |
| --- | --- |
| V3 的 `conclusions_correct` 多数为“是”，`missing_points` 多数为“否” | 答复可用，缺项多是习惯性表述；转去做原生接线和新题评测 |
| `missing_points` 里“漏核心”占多数 | 逐条保留不足以构成可接受答复；先做证据矩阵 |
| `citations_support` 有较多“否” | 引文与限定语不匹配；核验规则需要按条件补检查 |
| 应停止题出现了答复 | 先停下，把题号告诉我，优先于其他一切 |
| 两位评审在某一列分歧很大 | 口径不一致；先对一次口径再重评，不要直接引用单人统计 |

样本只有 8 题，结果用来决定下一步做什么，不能写成准确率。

## 十、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `UnicodeDecodeError: 'gbk' codec…` | 没设 `$env:PYTHONUTF8 = "1"` |
| `No module named 'mcp.server.fastmcp'` | `mcp` 装成了 2.x，按 `requirements.lock` 重装 |
| `Corpus missing: run scripts/build_frozen_corpus.py first` | `--runtime` 指向的目录里没有 `corpus.json`，回到步骤 2 |
| `OUTPUT_EXISTS_KEEP_ORIGINAL` | 输出目录已存在，换一个新运行名 |
| `PRIVATE_RUNTIME_OUTPUT_REQUIRED` | 对比脚本的 `--output` 不在 `.runtime` 下 |
| `--max-calls … is below the ceiling` | 上限小于“题数 × 4” |
| `NEW_FILE_UNDER_EVIDENCE_REQUIRED` | 导出文件不在 `evidence/` 下，或文件已存在 |
| `stop_reason` 为 `MODEL_ERROR` | 看记录的 `model.error`：`WAITING_DEEPSEEK_CREDENTIAL` 是缺密钥，`MODEL_CALL_BUDGET_EXHAUSTED` 是 `--max-calls` 用完；其余多为网络或输出格式问题。它不算答错，如实记入报告，不为此重跑整批 |
| 导出里结论的引用全是 `not_retrieved` | `--corpus` 不是当时运行用的那份语料 |
