## 四、引用、数字与跨文档结论

### F01：同一长引文中，业务对象与金额可被互换

**优先级／证据：P1，已复现。**

位置：`src/gov_mcp/frozen_qa.py`，`verify()`第237—247行及第333—350行。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa.py#L237)

触发：合成证据A写“首次申领20元；损坏换领40元”，证据B写“临时证10元”。候选把A改成“首次40元、损坏20元”，仍引用A的完整段落。

实际：`check.passed=true`；本地脚本化V3最终为`answer`，`final_checks.passed=true`，错误对应关系保留。

原因与影响：检查的是同一引文内的数值和单位集合，不能识别这些数值属于哪个业务分支。跨文档汇总即使改由断言生成，也会保留已经错误配对的断言。

修改建议：分支分别成断言，并绑定对象、条件、数值、单位及对应分句／表格列。无法可靠建立对应关系时保留缺项或转人工复核，不能因数值都出现过就认定语义成立。

验收：正确的20／40对应关系通过；互换、混合对象和跨来源借用被拒绝；存在例外时不能仅截取金额。复现案例：`crossdoc_same_quote_branch_swap`。

### F02：汇总答复能新增与正确断言相反的结论

**优先级／证据：P1，已复现。**

位置：`frozen_qa.py`，`has_cross_document_quantities()`第175—180行、`verify()`第225行起；`frozen_qa_flow_v3.py`，`render()`第123—129行、`check()`第178—189行。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa_flow_v3.py#L123)

触发一：断言正确引用“必须本人办理，不得代办”，但`answer`写“可以委托他人代办”。触发二：两个来源的断言分别写20元，汇总却写“两项均免收”。

实际：两个案例均通过核验，离线最终仍为`answer`，错误汇总保留。

原因与影响：强制由断言生成摘要只在至少两个来源、至少两种数量组合时启用；普通文字、单来源或相同金额比较不满足条件。禁止转许可的额外检查也只检查逐条claim，未检查任意汇总文字。

修改建议：所有业务结论统一由受支持断言生成，或者对汇总与断言做一致性检查；未经核验的自然语言汇总不能独立增加事实。

验收：正确断言配相反汇总时不得返回可用答复；两个来源恰好同价、零费用改写、纯定性答复均要覆盖。复现案例：`summary_invents_permission`、`crossdoc_same_amount_summary`。

### F03：条件和例外缺失，仍可能通过引用核验

**优先级／证据：P1，已复现。**

位置：`frozen_qa.py`，`verify()`；`frozen_qa_flow_v3.py`，`check()`第178—189行。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa_flow_v3.py#L178)

触发：引文是“有条件的测试窗口，可以当天制作发放测试证”，claim与answer均改成“所有测试窗口均可当天领取”。

实际：引用文本确实来自原文，但程序通过核验，最终为`answer`。

原因与影响：当前确定性检查不等于完整语义蕴含检查；几个否定／许可词的启发式规则无法覆盖条件、例外、适用对象及保证性措辞。“引用存在”不能推出“引用支持结论”。

修改建议：对关键限定语进行专门核对，或使用保留上下文的原文展示并标明语义未核定。采用其他语义核验手段前要单独验证其效果，不能只增加提示词就宣称解决。

验收：去掉“有条件”“仅限”“除外”、将可能性变成保证、将部分窗口变成所有窗口，都必须被识别或转人工。复现案例：`conditional_to_unconditional`。

### F04：中文次数、月份等数量未完整进入核验

**优先级／证据：P1，已复现。**

位置：`frozen_qa.py`第29行、第53—54行，`quantity_pairs()`第170—172行。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa.py#L53)

触发：原文“重新拍照三次”改成“九次”；另一合成原文“有效期限三个月”改成“九个月”。

实际：两个错误数量均核验通过并进入最终答复。

修改建议：按实际任务覆盖数量单位与量词，统一中文数字解析；无法解析的业务数量应明确失败或待核定，不能默认为没有数量问题。

验收：三／九、3／9、中阿混写的次数与月份均能检查；不得混同月份和天数。复现案例：`wrong_chinese_count`、`wrong_chinese_months`。

### F05：文号机关只比较末两字，错误前缀仍放行

**优先级／证据：P1，已复现；此前R4-01。**

位置：`frozen_qa_flow_v3.py`，`_document_number_key()`第138—147行。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa_flow_v3.py#L138)

触发：引文为“财综[2007]34号”，候选写成“豫财综〔2007〕34号”。

实际：程序认为文号相同，核验通过，最终保留错误前缀。

原因与影响：`issuer[-2:]`抹掉了机关身份差异。本人知悉并接受此缺陷，不意味着实现已修复或可以把它写成“错误已拦截”。

修改建议：保留完整机关简称，只规范化括号、空白等形式；普通行文前缀应单独解析，不能用截断机关名称解决。

验收：括号变化通过；错机关、错年份、错序号、跨来源文号和相邻错误业务数字均拒绝。复现案例：`wrong_issuer_prefix`。

### F06：网页发布日期年份被用作文件年份

**优先级／证据：P1，已复现。**

位置：`frozen_qa.py`，`verify()`第257—276行，特别是第275—276行。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa.py#L270)

触发：同一合成来源标题是“2018年测试通知”，网页发布日期为2026年；候选据此称“2026年通知”，并引用发布日期、标题和正文。

实际：核验通过，文件被错称为2026年通知。

原因与影响：`page_publication_date`的年份被加入`document_years`。网页重发、迁站或重新上架年份，并不必然等于文件落款年份；即使标题提供相反年份，也没有冲突处理。

修改建议：区分文书年份和网页发布时间。文件身份优先由明确文头／标题支持；冲突时保留未知或暂停，不能直接合并为都可使用的年份集合。

验收：2018年文件于2026年上网时，可以回答网页2026年发布，但不能仅凭此称为2026年文件。复现案例：`page_publish_year_used_as_document_year`。本次未证明实际归档语料中已经出现该冲突。

### F07：身份证号插入空格后绕过个人信息范围门

**优先级／证据：P1，已复现。**

位置：`frozen_qa.py`第28行、`scope_gate()`第116—123行及后续`build_messages()`。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa.py#L116)

触发：将测试用合成证件串分成“前6位 空格 出生日期8位 空格 末4位”放入问题，且上下文明确说是证件号。

实际：`scope_gate()`返回None；连续18位检测没有命中。没有发起真实模型请求。

原因与影响：只识别连续数字。下游会将原问题放入模型消息，若真实用户采用带空格格式，就存在绕过原本“不接收个人事实”边界的路径。

修改建议：在个人信息检测专用副本中处理常见分隔符，结合“证件号”等上下文识别；命中后阻断，不能把原敏感串再送往模型。注意避免把普通政策编号拼接成证件号。

验收：空格、常见分隔符及末位X变体应在调用前阻断；普通文号不应误拦。复现案例：`gate_misses_spaced_synthetic_id`。使用的是仓库既有测试形式的合成串，非用户个人信息。

### F08：范围门遗漏省外城市名称

**优先级／证据：P1，已复现。**

位置：`frozen_qa.py`，`OTHER_REGIONS`第24—26行、`scope_gate()`。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa.py#L24)

实际：范围门返回None，未在检索前识别为省外事项。

原因与影响：省级名称加少数城市的词表不能覆盖省外城市，河南资料有被用于省外事项的路径。后续提示词可能拒答，但不等于后端范围门已经阻断。

修改建议：采用有地区归属的规范化识别，或要求明确河南事项范围后再作答；不能只继续零散增加几个城市就宣称全面覆盖。

### F09：“还有效吗”等现行效力问法绕过范围门

**优先级／证据：P1，已复现。**

位置：`frozen_qa.py`，`CURRENT`第27行、`current_validity_asked()`第104—113行。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa.py#L104)

### F10：中文与阿拉伯数字等值改写导致误停止

**优先级／证据：P2，已复现。**

位置：`frozen_qa.py`第170—172行、第333—351行。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa.py#L170)

触发：原文“三个工作日”改写为“3个工作日”；原文“20元”改写为“二十元”。单位与实际数量没有改变。

实际：分别出现`QUANTITY_NOT_QUOTED:3工作日`、`NUMBER_NOT_QUOTED:3`或`QUANTITY_NOT_QUOTED:二十元`。脚本化修复仍采用同义写法时，全题最终停止。

原因与影响：原始数字字符串直接比较，缺少等值数值表示。没有其他已通过正文断言时，单独摘录也不会形成答复，因此这类误判可变成全题停止。

修改建议：规范化数值表示，保留原引文与显示文本；自然日／工作日等不同单位仍必须严格区分。

验收：同数量同单位的中阿转换通过；3变9不通过；不同单位不自动换算。复现案例：`chinese_arabic_equivalent`、`arabic_chinese_equivalent`。

### F11：已知单元格地址被当成未经引用的业务数字

**优先级／证据：P2，已复现。**

位置：`frozen_qa.py`，`REFERENCE`第31行，`verify()`中的`facts()`第282—287行及数字检查。[查看固定版本](https://github.com/miller7-lan/huaweiICT/blob/d94072185be71a42cc5e7d55f090a8c61f4f7a0d/src/gov_mcp/frozen_qa.py#L282)

触发：已检索行的`cells`明确包含`G36`，原文为20元；候选说“G36记载工本费20元”。

### 第二批：减少误停止，修正分类与证据归属

- F10—F14：数字等值、单元格定位、摘录条件与缺项状态、否定地区表达。
- F17—F19、F21—F23：预检必要输入、记录唯一性、缺规则阻断、失败计数、任务版本与评审口径。
- F24：生成独立的公开回执，实际检查历史产物后再决定是否需要补救。

完成标准：相同数量的规范写法、真实引用定位不误停；缺项不被计作完整；程序无法检查的条件明确阻断或标为未核验；历史结果和原始评分不被覆盖。

|方向|通过的情形|必须拦截或标记的情形|
