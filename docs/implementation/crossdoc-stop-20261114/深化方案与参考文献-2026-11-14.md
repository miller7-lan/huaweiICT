# 跨文档问答深化方案与参考文献

日期：2026-11-14。依据：[30 题盲评结果](../../competition/30题盲评结果-2026-11-07.md)、[Jev 三组对比](../jev-active-comparison-20261114/results.md)、[V3 本地执行报告](V3本地执行报告-2026-11-14.md)，以及下文列出的论文和开源项目。

**状态：设计建议。** 除第三节方案 A 的“原文摘录”一项已写入代码并通过离线测试外，其余都没有实现，也没有任何实测效果。论文中的提升数字来自英文公开基准，不能预期在本项目复现。

## 一、把问题说准：这是“选择性回答”，不是“提高答复数”

已有数据放在一起看：

| | 跨文档题可接受 | 应停止题正确停止 |
| --- | --- | --- |
| 基线（不核验） | 15/16 | 6/10 |
| 本方案（核验即停） | 3/16 | 10/10 |

两种方法是同一条“风险—覆盖”曲线的两端：一个几乎全答，该停的不停；一个该停的全停，能答的也停。目标应当是**保住 10/10 的停止，同时把答复覆盖拉回来**，而不是在两端之间换位置。

文献里这个问题叫选择性生成（selective generation）或拒答：

- Sufficient Context（Joren 等，ICLR 2025）把“检索到的上下文是否足以回答”单独定义出来，发现模型在上下文不足时往往答错而不拒答，并提出把充分性信号与模型置信度结合起来决定是否作答。
- Trust-Score（Song 等，ICLR 2025）用一个综合指标同时衡量三件事：该拒答时是否拒答、作答是否有依据、引用质量。

对本项目的含义：

- 评测不应只报一个可接受率，要同时报“应答题的覆盖”和“应停题的正确停止”，否则任何改动都只是在曲线上移动。
- “能正确停止”本身是政务场景的卖点，材料里应当正面写，而不是只把它当成拖低答复率的原因。

## 二、三个结构性原因

之前的结论是“核验太严、整题取舍”。再往下一层，有三个原因是加流程解决不了的。

### 1. 让模型同时做理解、作答和逐字抄写

现在一次输出要求模型：理解问题、写结论、逐字抄一段原文、照抄 `source_id` 和 `locator`、用年份指称文件时再补一条标题引用。记录里的失败多数属于后三项的抄写和格式问题（引文不在原文、定位带了单元格后缀、年份没有标题支撑），不是事实错。修复一次也改不过来（N04、N08、R06），因为这是模型不擅长的事。

文献的做法是让引用“由构造保证”，不靠模型抄写：

- Attribute First, then Generate（Slobodkin 等，ACL 2024）：先选出要用的原文片段，再只依据这些片段生成，片段本身就是引用。
- Anthropic Citations：引用是指向所给文档的字符区间，引文文本由系统返回而不是模型重打。

### 2. 取舍的粒度是整题

- FActScore（Min 等）把长回答拆成原子事实逐条判断。
- Conformal Factuality（Mohri 与 Hashimoto，ICML 2024）把“删掉把握最低的结论，直到满足目标正确率”做成有统计保证的回退算法，只需要少量人工标注做校准。

V3 的“逐条保留”是这个思路的简化版，但没有校准：现在是“程序检查过就留”，没有回答“留下的结论有多大把握是对的”。

### 3. 系统不知道一道题需要哪些内容

系统里没有“这道题由哪几项组成”的显式表示，于是：

- 判断不了证据是否充分，只能靠模型自己说“不足”；
- 判断不了答复是否完整（N02 标了 answer 却缺核心期限；3 份部分答复丢了要点）；
- 补查没有目标，只能拿模型写的 `unknowns` 当查询；
- 赛题占 25% 的本体，与实际问答链是两套互不相干的东西：南京三跳链用本体但写死句式，自由问答不用本体。

相关做法：

- StructRAG（Li 等，2024）：先把分散在多份文档里的信息整理成表格或图等结构，再在结构上推理；跨文档比较类问题收益最大。
- HippoRAG（Gutiérrez 等，2024）：用开放抽取建图，查询时从问题概念出发做个性化 PageRank，一步完成多跳检索，不需要训练。
- MultiHop-RAG（Tang 与 Yang，2024）：把多跳问题分成推断、比较、时间、无答案四类，正好对应本项目的跨文档比较、先后规定、应停止题。

## 三、方案

### 方案 A：引用改成指针，失败的转述降级为原文摘录（小改动）

**已实现（离线）**：V3 的逐条保留里，一条结论的转述没过核验、但它引的那段确实是原文时，不再丢弃，而是换成该引文所在的整句原文，标“原文摘录”。整句而不是片段，是为了保住主语和“有条件”这类限定语（执行报告发现 5）。两条限制：

- 至少有一条转述通过核验时才附带摘录；全部靠摘录不构成答复，仍然停止。这样不会把应停止题变成答复。
- 引用本身无效（来源没检索到、引文不在原文）的结论照旧丢弃。

**建议下一步（需要改输出契约，由 B 确认）**：

| 现在 | 改为 |
| --- | --- |
| 证据按单元给模型 | 证据按句编号给模型，如 `E3.2` |
| 模型输出 `source_id`、`locator`、`quote` | 模型只输出证据句编号列表，三项由后端填 |
| 模型用“2007 年通知”指称文件，再补标题引用 | 模型写 `[E3]`，后端按元数据渲染成“《标题》（文号，文头日期）” |

预期：引文不在原文、来源未检索、定位格式、年份指称这四类失败在结构上不再出现，剩下的数字和单位不符才是真正需要拦的。旧链和旧契约保留，用新版本号并行。

### 方案 B：本体驱动的证据矩阵（核心改动）

把“问题需要什么”显式化成一张表，行是事项分支，列是属性。例如“首次申领与到期换领的收费和时限分别是什么”：

| | 费用 | 时限 |
| --- | --- | --- |
| 首次申领 | 证据句编号 / 空 | 证据句编号 / 空 |
| 到期换领 | 证据句编号 / 空 | 证据句编号 / 空 |

步骤：

1. **定格子**：用本体词表（事项、分支、属性）从问题里匹配出要填的格子。先走词表规则；匹配不到时才用一次模型调用，且输出只能从词表里选。
2. **给语料打标**（离线，一次性）：591 个单元各标上候选的（事项、分支、属性）。规则加模型提候选，人工确认，沿用现有的候选—确认—激活—回退流程。这一步本身就是“低资源半自动本体构建”，而且量小、可以计时。可参考 EDC（先开放抽取，再定义，再规范化到已有词表）和 SPIRES（按给定模式零样本抽取）。
3. **按格检索与抽取**：每个格子只在标签相符的单元里检索；模型为每格选证据句编号或填“无”。这一步是抽取，不产生新数字。
4. **从表生成答复**：按行渲染；空格子就是精确的缺项，不再依赖模型自述。必答覆盖变成一个确定的数：已填格数 / 总格数。
5. **格子之间的运算登记为算子**：比较、相加、先后。这是南京三跳链里 `household_waiting`、`compare_coverage` 的一般化，每个算子是一跳，带依赖和引用。两条跨文档路径由此合并成一条。
6. **时间关系进本体**：文件节点带日期，文件之间的“取代 / 修改”关系经人工确认后入库。同一格子被不同日期的文件填了两次时，按时间排列并提示“先后规定并存”（新题 V05 的失败点）。未确认的关系不用于下结论。

配套：

- **按复杂度分流**（Adaptive-RAG 的思路）：只有一个格子的题走一次调用的旧路径；两个以上才走矩阵。执行报告里调用从 6 次涨到 14 次，分流后单文档题不再多花。
- **演示**：矩阵本身就是可展示的界面，每格可点开原文。
- **模板**：换行业只需换词表和属性清单，流程不变，对应“可复用 Skill 工作流模板”。

建议先在居民身份证一个事项上做（约 4 个分支 × 6 个属性），不追求通用。

### 方案 C：语义核验放在“结论—原文句”这一层，并且先校准

Jev 那组 0/8 的原因是：对整份回答做动作分类，阈值 0.70 没校准，低于阈值就整题停止。按文献的做法：

- 判断对象是一条结论和它引的那一句（MiniCheck 的设定），不是整题；
- 输出是分数，先只记录；
- 用已有人工评分的题做校准集，按 Conformal Factuality 的办法定阈值；
- 低于阈值的结论降级为原文摘录，不触发停止。

这一项可选，排在 A、B 之后。

### 方案 D：评测口径

- **必答要点**：每题在运行前冻结若干要点，评分时逐点判覆盖。TREC 2024 RAG Track 用的就是要点（nugget）评测。盲评里“关键断言覆盖”的一致性只有 0.25，按要点打勾能明显降低评审之间的口径差异。
- **指标分开报**：应答题报要点覆盖和结论正确率，引用报支撑率（ALCE、RAGChecker 都是这样拆的），应停题报正确停止；再给一个 Trust-Score 式的综合看法和调用成本。
- **题型配比**：按 MultiHop-RAG 的四类出新题（比较、时间先后、推断、应停止），每类都有。

## 四、与评分维度的对应

| 评分维度 | 对应方案 | 能展示什么 |
| --- | --- | --- |
| 编排与 MCP/Skill（25%） | B 的分流与矩阵流程 | 检索—抽取—运算—渲染四步，每步一个工具 |
| 资产激活业务价值（25%） | A、D | 应答覆盖上升且应停题不放行；要点级证据 |
| 算法创新、低资源本体（25%） | B 的第 2、5、6 步 | 本体不只是图，而是决定检索什么、算什么；打标有人工计时 |
| 交互与可复用 Skill（25%） | B 的矩阵界面与词表替换 | 逐格溯源；换词表迁移 |

## 五、建议顺序与不建议做的事

1. 先按[本机测试与上传清单](本机测试与上传清单-2026-11-14.md)导出失败类型，确认主要失败是不是抄写类。这决定方案 A 的指针式引用值不值得做。
2. 方案 A 的指针式引用（契约经 B 确认后）。
3. 方案 B 在单一事项上做原型，同时按方案 D 准备带要点的新题。
4. 方案 C 视时间而定。

不建议：

- 整套 GraphRAG 式的社区摘要：语料只有 591 个单元，建图和摘要的成本与收益不相称。
- 微调或对齐训练（如 Trust-Align）：没有训练数据和算力预算。
- 再加 Agent 或让第二个模型拥有停止权。
- 继续添加针对具体题目的检索和提示词规则。
