# 人工判读结果与下一步规划

日期：2026-11-14。依据：`evidence/crossdoc-flow-v3/review-r2-20261114-summary.json`、`review-r2-20261114-intake.json`、[r2 诊断分析](r2诊断分析与下一步-2026-11-14.md)，以及两篇新近论文。

**本文只依据计数和题号，没有看到题目、答案、原文或评审备注。** 8 题是开发题，下面的数字不是准确率，不能写成效果结论。

## 一、判读结果

两位评审各评 16 份输出。单次流程 8 题全部停止，没有可评的答复；V3 给出 5 份答复、3 份停止。V3 的 5 份答复共 10 次评分：

| 判断 | 结果 |
| --- | --- |
| 保留的结论是否正确 | 是 9，部分 1（N02，一位评审） |
| 是否漏掉必答要点 | 否 9，漏核心 1（N02，同一位评审） |
| 引文是否支持条件和限定语 | 是 10 |
| 评审一致 | 结论 15/16，要点 15/16，引文 16/16 |

按上一轮定的判断标准，这属于“答复正确、缺项多为习惯性表述”：流程本身基本够用，下一步应转向新题正式评测和原生接线，而不是先做证据矩阵。

## 二、这份结果要打的折扣

1. **两份表原样都没通过校验。** 接收记录写明：原表通过 0 份，按规则规范化后通过 2 份，共改动 11 行、19 个字段，另有 1 处“无摘录”由冻结输出补填。规范化是按填表规则做的（停止的输出前三项应为“不适用”），不是改评审的判断，但材料里引用这份结果时必须同时写明这一点，并保留原表。
2. **“原文摘录相关”一列本轮不能用。** r2 的诊断显示 V3 没有产生任何摘录条目，这一列却有 9 次“是”。评审大概率把它理解成了“引文是否相关”。请组织者核对一次输出里是否真有“原文摘录：”字样；没有的话，这一列作废，下次把列名改成“带‘原文摘录’字样的条目是否相关（没有就选无摘录）”。
3. **盲评在这一轮基本失效。** 单次流程 8 题全是停止，而且停止说明里直接带着核验失败码，评审一眼就能分出两种方法。
4. **另外两项判断还没进统计。** 表单里的“停止是否合理”和“参考答案是否有误”被存进了私有备注，公开统计里没有。它们恰好是评价的另一半：单次流程那 8 次停止里有几次不合理，V3 的 3 次停止是否合理，N08 到底该不该答。统计脚本已补上这两项的计数（见第五节），重新统计一次即可，不需要重新评。
5. **只有 8 道开发题、5 份答复。** N02 的分歧说明至少有一份答复可能漏了核心要点。

## 三、从结果里能确定的两件事

- **“后端补来源引用”有了支持证据。** 这是 V3 从 0/5 到 5/5 的主要原因，而引文支撑一项是 10/10。是否接受这项设计，仍由核验负责人决定。
- **`answer_with_gaps` 标得偏多。** 5 份答复里 4 份被标成“有缺项”，评审认为漏核心的最多 1 份。这个标签目前只能当提示，不能当“答复不完整”的计数。

对本项目的结论和上一轮相同：

- **不搬方法**：两篇都是强化学习训练，我们没有训练条件，赛题也不考这个。
- **借一个判断**：决策模型适合事后给单步打分、问“这一步有没有帮上忙”，不适合当场做决定。这和我们的实测一致（Jev 当决策者 0/8）。对应到本项目，就是让 Jev 只给“一条结论 + 它引的那句原文”打分，只记录、不拦截。
- **现在还做不了校准**：这一步需要足够多带人工标签的结论。现在只有 5 份答复、10 次评分，而且几乎全是“正确”，没有反例可供区分。等新题评完、有了正反两类样本再做。

### 第三步：新题正式评测（主线，决定材料里能写什么）

这是唯一能把“停止减少”变成“效果提升”的办法，也直接对应“资产激活的业务价值验证”（初赛 25%）。

- **题目**：20—24 道新题，出题人不看 V3 代码。按四类配比：跨文档比较、时间先后、需要推断、应当停止。每题在运行前冻结必答要点和“应答复或应停止”。
- **被测方法三种**：基线（不核验）、原方案（核验即停）、V3。这样能直接和 30 题盲评的两端对照。
- **预算**：每题最多 5 次调用（1 + 1 + 3），24 题上限 120 次，需要你确认额度。
- **评分**：沿用这次的表单和双人流程，改掉“原文摘录”列名；应停止题单独成组统计。
- **报告口径**：应答题的要点覆盖和结论正确率、应停题的正确停止率、调用成本，分开报。
