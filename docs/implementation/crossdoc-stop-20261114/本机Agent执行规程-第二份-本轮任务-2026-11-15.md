# 本机 Agent 执行规程（第二份）：本轮任务的严格要求

读者：在本机执行本轮任务的 Agent。被测提交：`329f133` 或其后的提交（以 `git log -1` 为准）。

[第一份规程](本机Agent执行规程-2026-11-14.md)定通用规则：预检定名、方案一致、收表即校验、回报格式。本文定**本轮每一项任务的硬性要求**：输入、命令、完成标准、要交回的东西。两份都要遵守；本文更具体，冲突时以本文为准。

本轮共六项任务，编号 T1—T6。**按编号顺序执行**，每项达到完成标准后再开始下一项。

## 硬性要求

以下八条适用于每一项任务，没有例外：

1. **先预检。** 会调用模型的任务（T3、T5、T6）开始前，预检结果必须是 `development` 或 `formal`，并已保存到 `evidence/`。
2. **一项一个新输出目录。** 目录名带任务编号和日期，例如 `.runtime/crossdoc-flow-v3/T3-native-strict-20261115`。已存在的目录换名，旧记录保持原样。
3. **只跑一次。** 每个真实运行执行一次。调用失败照实记入报告，作为结果的一部分。
4. **上限先于运行。** 每项的调用上限写在下面，运行前向用户报上限并得到确认。实际调用数超过上限即为未完成。
5. **冻结的就不改。** 本轮固定 `strict` 方案、本文指定的语料、本文指定的题。运行中发现代码问题，记下来，本轮照旧跑完。
6. **评分值只由评审本人填写和修改。** Agent 负责发包、检查、退回、统计。
7. **未完成就写未完成。** 某条完成标准没达到，报告里写“T? 未完成：<哪一条>，原因：<原因>”。
8. **只交回清单里列出的文件。** 题目、答复原文、参考答案、评审表、`key.json`、语料、日志、密钥都留在本机。

## T4 24 题双人盲评（不调用模型）

这一项决定上一轮 24 题能写出什么结论。

1. 先由一位**未参与出题、也不评分**的人对 24 题做题意复核和参考答案复核：题意是否与旧题重合、参考与必答要点是否与原文一致。结论逐题写成“未发现 / 有误 + 原因”，参考文件不改。
2. 生成评审包（带参考）：

   ```powershell
   .\.venv\Scripts\python.exe scripts/build_flow_v3_review_pack.py --records <24题 records.jsonl> --corpus <591 语料> `
     --reference <24题 reference.json> --output .runtime/crossdoc-flow-v3/T4-review-20261115 --reviewers reviewer1 reviewer2
   ```

3. 发给每位评审：`review.md` 和本人的 `sheet-*.csv`。`key.json` 留在组织者手里。
4. 评审开始前，把 `review.md` 开头的评审说明逐列念给或发给两位评审，特别说明：“原文摘录”一列只看以“原文摘录：”开头的条目，没有就填“无摘录”；“停止是否合理”只对停止的输出判断；同一题各份输出的“参考答案是否有误”填同一个值。
5. 每张表交回后立即 `--check`；有问题就把问题列表原样发还评审本人，改好再交，直到 `problems` 为空。
6. 两张都通过后统计。

**完成标准**：

- 题意与参考复核结论已逐题写好；
- 两张表 `--check` 都通过，且都是评审本人提交的版本；
- 统计 JSON 已生成，`sheets_passed_rule_check_unchanged` 为 true；
- 两位评审在“结论是否正确”上不一致的题号已列出，并已交两人合议；合议谈不拢的记“未达成一致”，保留两人原值。

**交回**：统计 JSON；复核结论只交题号和“未发现 / 有误”的计数；合议结果的计数。
