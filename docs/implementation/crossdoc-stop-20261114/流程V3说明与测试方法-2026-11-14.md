# 跨文档问答流程 V3：设计说明与测试方法

日期：2026-11-14。基线：`efe1708`（含 `f699110` 的检索与核验重构、Jev 三组对比）。本分支把它合并进来，在其上新增 `src/gov_mcp/frozen_qa_flow_v3.py`。

**状态：离线实现。11 项合成数据定向测试通过；没有调用真实模型或 Jev，没有跑原生 Nexent，没有任何准确率结论。** `frozen_qa.py`、`frozen_retrieval.py`、`frozen_qa_flow_v2.py`、旧评测记录和 Agent 配置均未改动。本分支上一版的 `frozen_qa_v2.py` 已删除，由本模块取代（它自带的简易检索和核验不如 `f699110` 的实现）。

## 一、对已有两条思路的判断

| 思路 | 记录的结果 | 判断 |
| --- | --- | --- |
| `f699110`：检索融合 + 上下文补充 + 日期身份核验 | 开发探针定位 22/22；新题两版均 4/6 | 检索和核验值得保留。但流程仍是“一次作答、整题通过或整题停止”，所以答复数没有变化 |
| `efe1708` 修复组：停止或核验失败后修复一次 | 8 道开发题正式答复 1/8 → 2/8；N02 修复后停止，丢掉了初稿的部分答复 | 方向对，收益小。两个原因：修复失败仍然整题停止；修复稿可以比初稿更差，却会覆盖初稿 |
| `efe1708` Jev 组：Jev 决定接受/补查/修复/停止 | 0/8；N03 初稿已通过程序核验，被 Jev 低置信度改成停止 | 不建议让 Jev 做最终门。未校准的整题分类只会增加停止 |

另外两点需要队内留意：

- N04、N08、R06 的失败都是“用年份指称文件，却没有引用标题或文头”，修复一次也没改过来。这是模型不擅长的格式要求，不是事实错误。
- `frozen_retrieval.py` 和提示词里已有针对具体开发题的专门规则（首次申领 2007/2018 收费、邮寄领取）。这类规则对新题没有帮助，继续追加会让开发题成绩虚高，建议不再增加。

## 二、V3 换的方法：按结论取舍，而不是按整题取舍

检索、核验函数、三道范围门、模型输出契约都沿用 `efe1708`，只改第一次模型输出之后的流程：

| 步骤 | 做法 | 针对的问题 |
| --- | --- | --- |
| 补标题 | 后端从语料中取出每个被引来源的标题单元，作为带“【系统补充的来源标题】”标记的引用加入。年份规则不变：标题里没有的年份仍然失败 | N04、N08、R06 这一类 |
| 补查 | 停止，或答复里 `unknowns` 列了缺项时，用缺项再检索一次；有新证据才重新问模型 | 新题 V04（缺邮寄依据） |
| 不退步 | 已通过核验的答复先保留；补查后的新稿不通过或变成停止时，仍用保留的那份 | N02、N03 |
| 修复 | 核验失败把错误码交回模型重写一次 | N01 |
| 逐条保留 | 修复后仍失败时，每条结论连同本来源的标题引用单独核验；通过的保留为“部分答复”，未通过的丢弃并在 `unknowns` 计数 | 整题停止 |

保持不变的约束：

- 展示的每个答复都整体通过 `frozen_qa.verify`；被丢弃的结论文本不展示。
- 隐私、外省、现行效力三道门在检索之前生效，不进入补查。
- “现行、个人、实际”一类的 `unknowns` 是边界，不触发补查。
- 每题最多 3 次模型调用，无自动重试；模型或契约错误记为 `MODEL_OR_TOOL_ERROR`，不记成缺证据。
- 结果仍为 `PAUSED_UNREVIEWED`、现行效力 `unknown`。
- 另加一条单向字面检查：引文含“不得/禁止”而结论写“可以”时判失败。它是启发式，不代替语义核验。

每条记录的新字段：`result_kind`（answer / partial_answer / stop）、`stop_origin`、`follow_ups_used`、`repairs_used`、`claims_dropped`、各轮检索新增条数、每次调用的失败码。

**需要 B 确认的一点：**“补标题”由后端代替模型提供标题引用。标题来自同一来源、同一版本的语料单元，核验规则没有放宽，但它改变了“引用全部由模型给出”的原有约定。

## 三、测试方法

以下命令在仓库根目录执行。第 1、2 步不调用模型；第 3、4 步消耗 DeepSeek 额度，须先取得用户确认。

### 1. 定向测试（不联网）

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_frozen_qa_flow_v3.py -q
.\.venv\Scripts\python.exe -m pytest tests/test_frozen_qa.py tests/test_frozen_retrieval.py tests/test_frozen_qa_flow_v2_comparison.py -q
```

预期：第一条 11 项通过；第二条 74 项通过（确认合并没有破坏 `efe1708` 的行为）。本次在云端环境两条合计 85 项通过；环境需使用 `requirements.lock` 中的 `mcp==1.26.0`，装成 2.x 会在收集阶段报错。

11 项测试对应的行为：

| 测试 | 断言 |
| --- | --- |
| 一次通过 | 只调用 1 次；“[1]”不被当成数字，原始模型输出原样保留 |
| 补标题 | 引用了正文而未引标题的“2019 年通知”可通过；写成“2021 年通知”仍停止 |
| 修复一次 | 60 元（原文 20 元）被退回，改正后通过 |
| 逐条保留 | 一条对一条错时得到部分答复，错误数字不出现在最终结果中 |
| 全部不可核验 | 仍然停止 |
| 否定写成允许 | 判失败 |
| 补查 | 无新证据不再问模型；有新证据才问第二次 |
| 不退步 | 新稿更差或变成停止时，保留已通过的答复 |
| 边界类未知项 | 不触发补查 |
| 范围门与模型错误 | 检索前停止、不调用模型；模型错误单独归类 |
| 调用上限 | 最坏情况恰好 3 次 |

### 2. 只看检索证据（不调用模型）

```powershell
.\.venv\Scripts\python.exe scripts/run_frozen_qa.py ask "只读归档：……你的问题……"
```

需要本机已有 `.runtime/frozen-qa-20261030/corpus.json`（591 单元）。V3 的首轮检索与这里显示的完全相同。

### 3. 单题真实运行

```powershell
.\.venv\Scripts\python.exe scripts/run_frozen_qa.py ask --flow --live --max-calls 3 "只读归档：……"
```

输出里看四项：`outcome`、`result_kind`、`stop_origin`、`checks.failures`。完整记录写入 `.runtime/frozen-qa-20261030/runs/`，其中 `model.calls` 是每次调用的结果与失败码，`retrieval.rounds` 是各轮检索。

建议先各取一题人工看过再做批量：一道曾因年份核验失败的题、一道曾因证据不足停止的题、一道应当停止的题（确认没有被放行）。

### 4. 配对对比（单次作答 对 V3）

```powershell
# 先看计划和调用上限，不调用模型
.\.venv\Scripts\python.exe scripts/compare_frozen_flow_v3.py --questions <题目文件> --output .runtime/crossdoc-flow-v3/<运行名>
# 真实运行：每题最多 4 次调用（单次作答 1 次 + V3 最多 3 次）
.\.venv\Scripts\python.exe scripts/compare_frozen_flow_v3.py --questions <题目文件> --output .runtime/crossdoc-flow-v3/<运行名> --live --max-calls <题数×4>
```

- 题目文件只含 `id`、`question`、可选 `context`，带参考答案的文件会被拒绝。
- 输出目录必须是 `.runtime` 下的新目录，已存在则拒绝，不会覆盖旧记录。
- 每题两种方法的先后顺序由 `--seed` 决定；不重试。
- 终端和 `summary.json` 只有计数：答复、部分答复、停止及其原因、调用次数、tokens。题目和答案留在 `records.jsonl`。

### 5. 怎样算“有效”

计数只能说明停止变少，不能说明答对。按下面的口径判断：

| 观察项 | 期望方向 | 说明 |
| --- | --- | --- |
| 应答复题的停止数 | 下降 | 主要目标 |
| 应停止题的停止数 | 不变 | 任何一道被放行都要逐条排查，优先于其他指标 |
| 部分答复 | 人工逐份看 | 保留的结论是否正确、是否漏掉了问题的关键部分；漏答关键部分应记为不可接受 |
| 事实错误、引用不支撑 | 不上升 | 由不知道方法的人按参考答案评 |
| 调用次数、tokens、耗时 | 如实记录 | 预计高于单次作答，不能写成降本 |

题目的选择：

- N01—N08、R 系列、V01—V06 都已用于开发，只能当回归用，结果不能写成准确率。
- 要主张效果提升，需要另出一批新题：出题人不看 V3 代码，题目和参考答案在运行前冻结，评分沿用 30 题盲评的表格和双人流程。
- 旧 30 题的正式成绩不重跑、不改写。

### 6. 尚未覆盖

- 原生 Nexent：38/39 号草稿的提示词仍是“检索、核验各一次”。V3 目前只有 Python 和命令行入口，接入 MCP 工具与新草稿另行安排，并需单独的原生运行证据。
- 持久化预算与并发：`frozen_qa_flow_v2.py` 的任务目录和预留机制没有搬进 V3，V3 的上限只在单次函数调用内保证。
- 语义完整性：V3 只保证展示的结论有原文引用且数字、日期、单位对应，不判断答复是否完整、是否曲解条件。
- Jev：未接入。若继续试验，建议只让它对单条结论给出提示并记录，不拥有停止权。
