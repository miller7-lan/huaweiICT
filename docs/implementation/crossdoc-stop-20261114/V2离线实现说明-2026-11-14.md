# 跨文档问答 V2：离线实现说明

日期：2026-11-14。对应本目录总指南的 G1/G2 中“检索、补查、修复、核验”部分。

**状态：代码与 11 项合成数据定向测试已完成；没有调用真实模型，没有跑原生 Nexent，没有新的准确率成绩。** 旧链 `frozen_qa.py`、旧评测记录和 Agent 配置均未改动。

## 为什么跨文档题会早停

旧链是“整句检索前 5 条 → 模型答一次 → 核验一次”，三处都对跨文档不利：

1. 整句只检索一次。一份资料的多个段落会占满 5 个名额，第二份资料进不了模型输入，模型只能回答“证据不足”。
2. “证据不足”和核验失败都直接成为最终停止，没有补查，也没有修正机会。
3. 数字核验只比较“回答里的数字是否出现在任一引文中”，20 元/60 个工作日对调仍能通过；而正确答案里写一个“[1]”反而会被判失败。

## V2 流程（`src/gov_mcp/frozen_qa_v2.py`）

| 步骤 | 做法 | 上限 |
| --- | --- | --- |
| 拆分 | 按标点和“与、和、分别、以及”等把问题拆成子问题，不调用模型 | 整句 + 4 个子问题 |
| 证据池 | 每个子问题各自检索，轮流取用；单份资料每轮最多 3 条 | 每轮新增 8 条 |
| 作答 | 模型契约仍是 `AnswerOutput`，提示词增加跨文档三条规则 | — |
| 补查 | 第一次“证据不足”不算结果：用 `unknowns` 和 `stop_reason` 再检索一次；没有新证据才停止 | 1 次 |
| 核验 | 每条 claim 的数字连同单位必须在**它自己的** quote 里；原文“不得/禁止”不得写成“可以”；证据编号不计为数字 | — |
| 修复 | 核验失败把错误码交回模型重写一次，仍失败才停止 | 1 次 |

每题最多 3 次模型调用。证据池只增不减，编号不变，核验始终面向整个池。隐私、外省、现行效力三道门仍在模型调用之前生效；结果仍为 `PAUSED_UNREVIEWED`。每条记录带 `stop_origin`（范围门、补查无新证据、补查后仍不足、修复后仍失败、模型错误等）、各轮检索的查询与新增条数、每次调用的失败码。

## 使用

```powershell
# 只看证据池，不调用模型
.\.venv\Scripts\python.exe scripts/run_frozen_qa.py ask --v2 "首次申领与到期换领的归档收费规定分别是什么？"
# 真实调用（消耗额度，需用户确认后执行）
.\.venv\Scripts\python.exe scripts/run_frozen_qa.py ask --v2 --live --max-calls 3 "..."
# 定向测试
.\.venv\Scripts\python.exe -m pytest tests/test_frozen_qa_v2.py -q
```

## 已知边界与尚未做的事

- 拆分是字面规则，“和/与”可能切开词语；它只影响检索查询，不影响核验。
- 否定检查是单向启发式（原文禁止、结论允许），不能替代语义核验。
- 单位表是固定清单；清单外的单位按裸数字处理。
- 检索仍是字面二元组，同义改写召回不了的问题不在本次范围。
- **未做**：`eval` 配对评测接入 V2、原生 Agent 提示词与工具（补查需放开“检索只许一次”）、用新冻结题验证效果。旧 30 题成绩不能用于证明 V2。
- 南京三跳演示链（`crossdoc_reasoning.py`）是写死句式的单一情境，本次未动；它证明可追溯执行，不承担通用跨文档问答。
