# Jev 实际参与的三组对比

本轮比较原规范化流程、原流程加一次修复、修复加 Jev 实际判断。继续使用 N01—N08 开发题；三组共用同一份模型初稿，不把旧评分并入本轮。

Jev 的 action 选择参与接受、补查、修复和停止。action 的置信值不足 0.70 时进入一次缺口诊断；修复后再次判断，仍未明确接受则停止。0.70 是运行前冻结的实验设置，不是已校准的正确率。分类和 supported 信号另行记录；supported 数值不单独作为放行阈值。程序引用、数值、日期检查始终优先。

仅一次修复机会，允许最多一次定向补查；Jev 明确认可合理停止时可以省略修复。隐私、地区、现行效力等后端硬停止不交给 Jev 改判。

DeepSeek 最多 64 次操作请求，Jev 最多 24 次操作尝试；失败操作最多重试一次，不因评分低或答案不好重跑。输入过长、契约解析或服务失败均属于执行问题，保留脱敏轨迹。

质量计分仅使用三组全部执行完成、且两次交换匿名顺序的评分都成功的题；统一分母。API 失败不算错答，也不删除失败事实：另外报告每组完成率、失败数、重试数和排除题号。所有最终业务输出冻结后才交参考答案给事后模型评审。

这是同模型评分的开发对比，不是真人准确率、独立留出集或生产验收。原生 Agent 和默认配置不改变。实际入口：`scripts/run_jev_active_comparison.py`，Windows 输出目录：`C:\CodexSSH\windows-dev\jev-active-comparison-20261114`。
