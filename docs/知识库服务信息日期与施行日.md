# 服务信息日期与施行日

后续业务复核见[2026省厅服务时限复核](知识库2026省厅服务时限复核.md)。下文记录日期能力提交时的验证边界；主库后来新增1项有范围的服务信息复核，未因此正式发布。

2026-10-17。官方办事解读、公开答复和服务说明可能给出当前服务承诺，却没有明确法规施行日。原复核门槛要求每份资料都有`effective_from`，无法如实表达这种资料。现在为这三类非规范性信息增加单独、显式且绑定原件的日期依据；施行日仍可保持未知，发布日期不会被自动填作施行日。

实现见[日期校验](../src/gov_mcp/knowledge_dates.py)、[资料复核与日期筛选](../src/gov_mcp/knowledge/registry.py)、[引用绑定与展示](../src/gov_mcp/knowledge_answers.py)。本次仅完善工程能力，**没有因此批准主库任何服务资料，也没有解决二七区材料关系**。

## 准入条件

只有`official_service_information`、`official_policy_explanation`、`official_consultation_reply`可以显式采用`reported_service_information`。法律、行政规范、省级规范等不能借用该类型替代施行日；原日期路径继续要求已核定施行日。

新的`date_basis`必须完整提供以下绑定，缺失、多余字段或不一致均拒绝：

| 字段 | 要求 |
| --- | --- |
| `kind` | 仅允许`reported_service_information` |
| `information_as_of` | 已建立的原文发布日期，ISO日期；不能是未来日期 |
| `base_revision` | 同一文档、同一原件、同一选入正文和同一来源观察的基础修订 |
| `original_sha256` / `body_sha256` | 分别与基础及待核修订完全一致 |
| `source_observation_sha256` | 绑定完整来源观察，不能绕过页面标注变化 |
| `source_date_field` / `source_date_value` | 仅允许原观察中的单个`meta:pubdate`或`block:page_date`，值必须完整一致、日期无歧义；不接受修改时间或拼接多个日期 |
| `legal_commencement_established` | 必须为`false`，不得同时填写法律施行或失效日 |

解释字段`published_at`须与截至日期一致，`effective_from/effective_to`保持空值。这些校验只证明字节和日期绑定，不证明服务当前适用。地区、事项分支、用途、材料冲突和真实执行者确认仍分别核对；来源新鲜度、待核停止、至少30题独立评测、90%召回和100%断言支持等发布要求保持。

自动采集不会自己认定这份资料可以使用上述日期依据。资料须先完成具体业务复核；后续正文或重要来源观察变化仍生成待核修订，不能继承旧日期判断。同一正文及来源观察不变时，原有复核保持机制继续有效。

## 查询与引文

服务信息按已建立的截至日期筛选，不能用它回答该日期之前的状态；这不把截至日期改成法律有效期起点，也不重建当时的网站。未来查询继续提示不保证未来规则或服务不变。

此类引文新增`date_basis`与`information_as_of`，两字段一并进入引用标识和完整性核对。群众与工作人员均能看到“服务信息截至日期”和“不能据此推定施行日”，原文仍完整保留。旧引文不增加这些字段，原有内容及引用标识保持兼容；实际与上一提交的绑定函数对照通过。
